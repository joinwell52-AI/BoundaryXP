## 2. 数学关系与适用前提

### 区间与单位

同一指标、同一适用条件下的约束区间为 J₁、J₂，则：

```text
J = J₁ ∩ J₂
J = ∅  →  在上述绑定前提下，没有同时满足的取值。
```

例如 50 毫秒 ≤ 单笔延迟 < 2 秒，换算后为 `[0.05, 2)` 秒；必须保留左闭右开。数值使用 Decimal，避免用二进制浮点近似改写金额或临界值。

总操作 40 分钟与异常回滚 15 分钟分别是 2400 秒与 900 秒。它们约束不同过程，不能直接相交，不能自动得出全任务必须在 900 秒内结束。两者的包含关系需要原文说明。

### 条件重叠与反例

设同一主体、动作与对象范围中，必须执行的生效条件是 p，禁止执行的生效条件是 q：

```text
SAT(p ∧ q) → 存在两项要求同时生效的条件赋值。
在该赋值下，执行变量 x 与 ¬x 不能同时满足。
```

前一个查询为 SAT，后一个相反动作约束查询为 UNSAT；两者不可混写成“SAT 就是冲突”。满足赋值是模型中的反例，不是实际已发生的事件。求解超时或 unknown 不能记为通过，unsat core 也不自动保证是最小冲突集。

“必须获得 CFO 或 Finance_Lead 授权”中的内部表达式为 `CFO ∨ Finance_Lead`，四组布尔赋值中只有双方均未授权时为假。但这不等价于“任一授权后必须执行”，也不说明现实中谁已经批准。

### 显式集合与依赖图

```text
目标交叠 = Targets ∩ Forbidden
其余对象 = Targets \ Forbidden  （不产生授权）

G = (任务节点, 强制前置边)
环路：强连通分量包含多个节点，或单节点存在自环。
无环：可计算拓扑顺序，但不证明业务一定完成。
```

例如 A→B、A→C、C→D、D→B 是无环图，可按 A、C、D、B 排序。不能因为出现多步依赖就报告循环。

## 3. 真正需要验收的是整条计算链

```text
原文与 UTF-16 证据位置
  → 局部约束提取（指标、数值、条件、动作、对象、作用域）
  → 集合 / 逻辑 / 图求值
  → 与原文对应的具体建议
```

若将“必须获得授权”误提取成“必须执行”，求解器即使完全正确，最终提醒仍然错误。因此每条用例必须分别核查提取正确性、运算正确性和建议依据。

当前前端解析采用局部文法、版本化词法规则和局部结构匹配；没有接入通用 UD 依存分析、ICU 或通用语义理解。ADMIN 路径不调用 LLM/API。规则支持的句式有限，复杂嵌套、跨句指标归属、不同措辞的动作等价性及部分中英表达仍可能漏提取或误绑定。

“未识别”不等于“原文未声明”；返回部分计算不等于整段任务已验证。没有适用图输入时可以保持无适用输入，不能为激活引擎而编造节点或依赖。

## 6. 三层独立断言与用例记录规范

本节是后续验收要求，不代表这些断言已全部实现。

| 层次 | 要验证的内容 | 失败时应如何表达 |
|---|---|---|
| 原文证据 | quote 与原始文本的 UTF-16 `[start,end)` 切片完全对应；保留数字、单位、否定词和条件出处 | 标明引用错误或未覆盖片段，不把该映射当成有效约束 |
| 约束提取 | 动作与前置条件分开；主体、对象、指标、量纲与作用域正确；严格大小与等号归属正确 | 保留候选或未知状态；影响动作的未解析条件必须随该动作保留，不能将动作改为无条件 |
| 运算与建议 | 根据已核验的 IR 重算区间、布尔赋值或依赖；每项建议有对应证据和计算前提 | 区分计算失败、输入不足、部分覆盖与具体发现，不输出全局安全结论 |

建议的固定用例文件包含 `raw_text`、`expected_ir`、`expected_findings`、`expected_uncovered` 和 `assumptions`，同时注明预期结果的审查状态。用户提供的“预期结论”先作为候选标注保存；未经独立核对不能直接成为黄金答案。当前 40 条挑战调用记录不等于已经建成逐条审核的黄金用例库。

回归应同时包含原句、中英对应表达、只改变临界数值或主体名称的变体，以及应保持不确定的反例。分别统计提取遗漏、错误绑定和建议错误；不能仅用输出非空计为成功。

### 需要避免的几种语义替换

- “未经 ADMIN 许可，严禁部署”可表示 `¬approved(ADMIN, 部署范围) → FORBID(部署)`；它没有声明已经批准，也不推出批准后自动允许部署。界痕呈现条件提醒，宿主负责实际授权检查和执行控制。
- “必须经 CFO 审批”可能是在规定审批流程义务，也可能为某项操作设置前置条件，需要结合被修饰动作判断。不能一律删去审批义务，也不能凭空补出一个业务动作。
- “生成 report.csv 为完成”不应直接弱化为 `FileExists(report.csv)`：旧文件也可能存在。是否要求本轮生成、内容完整或提交成功，须从原文或已确认契约取得；不能脑补成已验证终态。
- “不超过 30 分钟”直接给出上界 `t ≤ 1800 s`；写成 `[0,1800]` 时，非负下界来自“耗时”的类型域，应作为类型假设说明。一般数值指标不能自动添加零下界。
- 并列对象的展开需要保留连词语义、共同修饰和原句范围；识别出两个对象并不证明它们属于保护清单。
- 当求解器给出 `CFO=False` 的模型赋值时，应称“假设场景/反例”，不能称“当前 CFO 未批准”。条件满足的证人也不证明真实执行已发生。

仅隔离未知文字还不够：如果未知部分影响已识别动作的条件或对象范围，相关约束也必须标记不完整。允许继续计算与该未知片段无关的明确数值，但不能宣称未知片段绝不会影响结论。
