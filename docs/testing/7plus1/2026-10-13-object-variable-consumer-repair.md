# 对象变量消费修复：ui79

本轮只修程序消费者及错误展示。解析/审阅 Skill、共享合同、Schema、模型配置及两次原始候选均不修改，不新增模型请求。

## 问题与修复

MANUAL-TEST-002 的 Skill / Skill1 都用 OBJECT 变量表示从可读输入中选择的同一对象。旧 DATA_USE 校验只接受 ENTITY，导致两次各报四个 DATA_OBJECT_TYPE，尚未开始投影和计算就失败。

修复后的校验接受 ENTITY 或 OBJECT 类型变量；变量必须与消费事件的角色引用同一个变量 ID，不能因两个变量的域相同便认定同一对象。生产者 RESULT 的引用也执行同一身份检查。非对象变量、错误消费对象、错误生产者和外部输入伪造内部生产者仍被拒绝。

计算链另外修复三个实际消费者缺陷：

- 同一个对象同时出现在 OBJECT / INPUT_OBJECT 角色时，按精确引用去重；不同对象仍保留歧义。
- 构造见证按求解赋值把对象变量解析为具体实体；原 IR 不改写，选择自由不被固定答案替代。
- 构造见证纳入模板实例；同一个任务的环境全称约束与整体时间范围同样覆盖这些实例，输入验证使用实例真实选择值，不再遗漏它们。

用户自报观测尚无对象变量绑定接口的部分保持 UNKNOWN 并给出 OBSERVED_OBJECT_VARIABLE_BINDING_NOT_IMPLEMENTED，不把未实现误判为身份不符，也不推定满足。

页面区分“技术校验未通过”与“检查已运行”；后续投影/计算显示“被技术校验阻断”，过程区列出具体错误码和节点。服务保留 DIRECT_IR_TECHNICAL_REJECTED，不再统一掩成 COMPILER_ERROR。旧失败记录也根据已保存 technical_ok=false 正确展示，历史结果不改写。
