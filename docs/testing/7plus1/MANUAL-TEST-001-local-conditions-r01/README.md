# 同一任务的局部条件对照

原始 `MANUAL-TEST-001.txt` 与先前标准封存保持不变。每份新原文只改变一处条件或数量表达；均为测试数据，不执行其业务操作，不是历史 Gold。

| 编号 | 唯一局部变化 | 必须观察到的差异 |
| --- | --- | --- |
| V00 | 原文不变 | 完成条件仍是充分方向，四项状态合取 |
| V01 | “……时完成”变为“只有……才完成” | 必要方向；前提不成立但观测为完成，应违反本条件 |
| V02 | 明示“当且仅当” | 双向条件；不能仍当作单向充分条件 |
| V03 | 完成判据的四项改为“任一” | 析取；只改变完成判据，提交后复核的独立先后不变 |
| V04 | “30分钟内”改为“少于30分钟” | 30分钟不满足，29分钟满足 |
| V05 | 总期限30改为20分钟 | 20分钟满足，21分钟不满足；不改变完成判据 |
| V06 | 高危触发前提改为“未发现” | 保留否定；不能按常识把原文改回“发现” |

`INDEX.json` 与各 `expected.json` 是模型调用前声明的测试要求，不进入模型上下文。V06故意采用不常见但明确的指令，检验程序是否忠于结构；不表示该业务政策合理。

程序层对照使用明确标记的人工合同候选和人工审阅夹具，经过同一技术校验、IR、固定7+1及计算。它验证程序保真，不证明LLM正确解析了全部七份原文。真实模型验证单列V01：解析与新会话审阅各一次，最多两个保守请求；失败保留，不自动重试挑选答案。

实际状态观测是独立的合成测试输入。条件逻辑成立，不证明动作已执行、任务已完成或获得许可。实际时序需要时间观测；不能用逻辑条件成立替代顺序证明。
