需特别核对的来源关联：

1. DEV 检查 app.yaml，OPS 检查 env.json；各自报告不能互换。
2. “两份报告”回指本次 dev.md 与 ops.md；QA 复核与 PM 汇总使用相同身份。
3. “分别将各自报告提交”绑定 DEV→dev.md→QA、OPS→ops.md→QA。
4. “复核通过后”同时约束后句生成 summary.md 与交付 ADMIN；不是只约束其中一个。
5. “立即”是 PM 停止本任务事件的定性及时性要求，没有毫秒/秒数上限。
6. “输入文件”回指两个确切文件；它与停止对象“本任务”不是同一个对象。

## 4. IR 与计算应保留什么

以下符号是人工对照用语义键，不要求 LLM 使用这些 ID。

```text
D = DEV 已将本次 dev.md 提交 QA
O = OPS 已将本次 ops.md 提交 QA
Q = QA 对这两份报告复核通过
S = PM 已将本次 summary.md 交付 ADMIN
H = 发现高危问题

完成组合 K = D ∧ O ∧ Q ∧ S
K → TASK_COMPLETE                      充分完成方向
H → REQUIRED(PM 停止本任务)
H → REQUIRED(PM 向 ADMIN 汇报)
执行停止 → IMMEDIATE(停止事件)         定性属性，未知观测不冒充满足
整体工作耗时 ≤ 30 分钟
FORBIDDEN(修改, {app.yaml, env.json})
FORBIDDEN(访问, 生产环境)
```

明确时序需分别保留：DEV 提交→QA 复核；OPS 提交→QA 复核；复核通过→PM 汇总生成及交付。这些边须引用本地条件表达式、真实事件及来源，并保留触发条件；不能因属于同一个父事件而漏算，也不能凭 owner 创建先后。

产物可用性应覆盖 dev.md/ops.md 的提交、QA 复核、PM 汇总用途，以及 summary.md 的交付用途。可用性不等于生产者整项工作完成，也不能机械新增“生成结束→提交开始”的严格时间边。

事件层级表达整体与局部归属，不意味着子动作等待整体完成，更不意味着组织者自动执行。计算层必须按已表达的本地模态和条件处理；遇到真正缺少激活合同的其他结构须明确未支持，不能删除事实后宣称全部算完。

无观测时：条件原子、完成依据、停止触发、及时性、实际耗时、实际产物可用性为 UNKNOWN。静态公式可有可行组合，但求解器 witness 不是业务事实。`business_decision`、`execution_authorization` 始终 null。
