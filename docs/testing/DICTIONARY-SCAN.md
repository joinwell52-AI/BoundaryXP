# 语义库扫描与标记（ui106）

程序仅扫描用户已选L2、L3的显式名称、别名、术语触发词及对象ID。未选择的包、定义正文中的相关对象和否定说明不进入扫描索引。字典原文件不修改。

原文保持原字节。预览按Unicode字符坐标标记全部命中；重叠词、重复词和同名多义均保留。ASCII大小写不敏感，英文和ID按词边界匹配；中文采用字面子串匹配，因此“客户镜像备份”中命中“客户镜像”只是候选提示，不能直接认定是同一对象。非字面改写可能未命中，LLM仍可主动查词。

## 分工

- 程序：索引、扫描、标记、来源和版本绑定。新增会话保护的只读接口 `POST /api/dictionaries/scan`，不调用模型、不新建运行记录。
- 生成LLM：收到去重的命中词、包ID、词条ID和pointer。影响边界判断时按需查询，不整包加载。
- 审阅LLM：收到同一扫描提示与同版词典，独立核对所依赖的定义。不能从扫描命中直接认定身份或权限。
- 页面：当前输入预览与本次实际扫描回执分别标明；实际查词次数仍单独展示。预览更新不改历史记录。

每次生成前重新扫描实际源文本，不信任浏览器预览结果。保存 `dictionary-scan.json`，最终Trace含 `dictionary_scan`，旧历史无此字段则明确显示未记录。重复词位置完整保存，模型提示只列一次，避免重复上下文。

## 无模型验证

运行 `node --test tests/boundary-dictionaries.test.mjs tests/boundary-report.test.mjs`。

核对中文及emoji来源位置、同名多个候选、重复及重叠词、ASCII词边界、定义正文不进入索引、未选包隔离、会话保护、容量检查、生成及审阅同版提示、扫描证据落盘。实际模型是否正确使用提示，需要后续真实运行核对；工程测试不冒称语义验收。
