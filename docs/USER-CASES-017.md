# 100 号用例的实际测试：哪些算出来，哪些仍然没算清

**编号 1—100 的任务原文已各运行两次；当前不能说这 100 条全部支持。** 本轮修复了部分动作角色、中文数字、工作包分段和禁止条件丢失问题。实际结果、未识别项和漏检都保留在下面的逐例报告中，没有用附件里的参考答案替代引擎输出。

测试通过产品实际 **Node → 隔离 Python** 接口进行。ADMIN 不调用 AI、模型权重或外部 API。产品仍为 `1.2.1-preview.1`，本次是源码更新，不是安装包发版。

## 本轮代码具体改了什么

1. **动作与角色分开。** 读取的文件投影到 I，生成的产物投影到 O；发送还要区分载荷与接收人。执行者、审批者分开，禁止动作不进入正向交付承诺。中文、英文使用同一套局部 Lark 角色文法。
2. **中文数字进入实际数值计算。** “三十分钟”按位值归约为 `30 × 60 = 1800 seconds`，“八千万元”变为 `80000000 CNY`。保留严格小于和不超过的开闭差异。拒绝把“一百二”等省略位值写法强猜成某一个数字。
3. **区分量纲与指标。** 调用次数和每秒调用次数分开；未声明温标的“度”、未明确币种的 `dollars` 不自动改成 ℃ 或 USD。人民币前缀与相矛盾的后缀单位会得到具体提醒。
4. **扩展明确的工作包标题。** `WP-DATA-01`、`【阶段一：标题（WP-DATA-01）】` 能切成独立阶段；不根据编号自动加依赖边。条件产物与无条件产物分开计算来源缺口。
5. **保护独立 B 和原文条件。** 同句逗号前的“当……时”能与禁止句一起保留；不把“且”改成“或”，也不因为没有接口名称而丢弃禁令。
6. **撤掉伪槽位。** “、校验”不再当成输入对象；“推送到存储桶”未给出载荷时不再把目的地当产物；“该阶段任务即为完成”的回指没有绑定时给出具体提醒，不把“该阶段任务”本身当停止断言。

原理、公式和对应源码见 [017 语义契约实现](SEMANTIC-CONTRACT-017.md)。这些是有覆盖范围的规则与文法，仍不能无损理解任意自然语言。

## 如何核对参考答案

附件参考分析单独保存，作为人工核对材料，不自动充当黄金标签。以下区别直接影响计算是否有效：

- 有向图出现一条可达路径，不能证明所有执行都必定终止；不同步骤名称没有明示同一性时，也不能直接合并来制造环路。
- 原文未声明执行组、输出文件或实际生产状态，测试期望不能自行补上。O 有候选产物也不表示已经创建成功。
- “度”、`dollars` 等未指明的单位不能为了得到一致结果强行选定；压力、货币等明确但尚未支持的单位，则应列为实现缺口。
- 禁止边界 B 不能与 I 的对象名不加类型区分地相交。例如“20 辆车”与“禁止远程断电”分别是对象和动作，空字符串交集不构成安全证明。
- Z3 的守卫重叠用 SAT 寻找假设状态；在该状态下检验正反义务才可能 UNSAT。没有事实观测就不把反例当作真实现场；也不自动给禁止边界加豁免。
