# 019：软件工程与 AI 用例 121—140 回归

> 历史／非规范研究或产品规划（legacy / non-normative）。本文中的旧接口、原始结果和未来能力不代表当前产品合同或本轮验证；当前入口以根 README 和产品手册为准。No BXP extraction certification or execution authority is implied.

本轮把 20 条中英混合任务原文作为可重复执行的基准，目标是检验从自然语言证据到 7+1 候选、再到区间、集合、图与布尔约束的完整链路。原文保存在 [`python/cases_121_140.json`](../python/cases_121_140.json)，断言保存在 [`python/test_cases_121_140.py`](../python/test_cases_121_140.py)。

## 工程原则

> 表单收敛输入，数学把关边界，代码保证执行。

在 BoundX 协议中，“代码保证执行”严格解释为：代码强制执行**已确认的边界和授权流程**。ADMIN 不自行授权、不运行任务，也不返回业务放行决定。每个计算与建议仍保留原文 span，`decision` 与 `businessDecision` 均为 `null`。

处理管线是：

1. 将原文投影为 I/O/A/P/R/V/C 与独立 B 候选；
2. 只把证据已绑定的对象送入确定性求解器；
3. 对缺项、代词、步骤身份和效果身份输出 unresolved；
4. 由宿主系统与责任主体确认后重新计算。

`S_required \ S_extracted` 只表示“解析器尚未提取的字段”，不证明原文确实缺失，更不证明已提取字段语义正确。

## 本轮代码增量

- 数值单位新增 Token、源码行、PR 数量、GB；保留毫秒到秒、小时到秒的 Decimal 精确换算。
- 数值类型新增输入选择谓词，防止把“复杂度大于 15”误列为资源预算。
- 中文依赖式支持“完成后/通过后启动或生成”，统一剥离关系后缀，再运行 NetworkX 强连通分量。
- 自然语言显式目标列表支持代码包和 Git 分支；支持 `/` 与 `.` 标识符。
- 行内“阶段一/阶段二”进入隔离工作包，并运行命名文件来源差检查。
- 增加审批 AND/quorum 候选、英文 unless 守卫、局部例外、代词挂起和软件工程状态效果检查。
- 修复动作词落在名词内部的问题，例如“打包箱”“结算核心服务”“预发布版本”“逆向工程智能体”。

## 数学边界

区间与集合的运算本身是确定的；最难的是证明两个自然语言片段应映射到同一个数学变量。BoundX 因此同时输出：

- 运算对象与结果；
- 建立对象同一性的证据和假设；
- 原文 UTF-16 span；
- 尚未绑定的身份、条件或角色；
- 空的业务裁决字段。

这使系统能“算清已知部分”，同时不把解析器覆盖率伪装成完整语义理解。
