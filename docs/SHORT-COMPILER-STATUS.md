# 短文本7+1编译器：版本、能力与验收状态

状态核对日期：2026-10-08。本文是项目文档的当前状态入口，不是新的开发授权、模型调用预算或产品发布声明。运行状态以本机实际检查为准。

## 1. 当前结论

**已有可安装、可运行的短文本编译器候选；完整产品语义验收尚未通过。** 当前优先目标仍是从ADMIN原文正确生成带关系、来源和未决信息的7+1，再接通完整边界计算。恢复页面、封装安装包和工程测试通过都不能代替语义验收。

采用的主方法是：

```text
ADMIN原文 → 解析Skill＋LLM → 候选语义结构
→ 审阅Skill＋独立会话 → 程序技术校验与保真编译
→ 7+1 JSON＋同源中文＋来源与未决
```

两个Skill以同源`INLINE_BUNDLE`进入真实请求；原生Skill发现和加载未验证。NLP不再是这一候选的主解析路径或强制前置依赖。

## 3. 当前使用入口

在已经完成本地安装和58618恢复的工作区，运行：

```bat
cd /d D:\boundx
npm run 7plus1:ui
```

固定地址：`http://127.0.0.1:58618/`。该启动器使用完整已安装版本，不从开发工作区混读Skill或Schema；同版本已经运行时不重复启动。它不是全新克隆后的自动安装器。

维护记录中的监听PID不是永久配置，不应复制用于停止进程。本页也不证明此刻电脑开机、服务存活或登录有效。具体操作见[快速开始](../QUICKSTART.md)。

根仓库`npm run 7plus1`指向工作区编译器，`npm run 7plus1:ui`指向固定安装版本；当前两者可能不是同一版本。比较CLI与网页时，须使用同一完整安装包内的CLI。`npm run ui`是另一条既有BXP应用入口，不是短文本编译器的替代启动命令。

## 6. 产品交付顺序

1. 收口短文本7+1：明确语义完整，真实歧义局部保留，JSON与中文一致，版本与证据可复核。
2. 接通同一7+1结果到已有形式化与确定性边界计算，验证覆盖、冲突、未知和来源，不另让模型猜计算答案。
3. 核查PM计划或Agent下游内容是否满足父边界，同时检查越界与必需交付遗漏；宿主负责实际执行控制。
4. 在前述能力稳定后扩展完整真实任务；Gold-60必须使用原始TASK，不能截成短句后称为原任务通过。

这些是产品阶段，不是本页自动授予的新任务。第一阶段没有完成，不能靠增加后续界面或求解模块掩盖。
