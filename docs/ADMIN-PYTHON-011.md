本文说明 ADMIN 本地 Python 计算入口：七要素与独立 B、分层建议、可编辑建议任务和 JSON 导出。只提供候选解释，不批准、阻断或执行任务；当前安装方式见 [快速开始](../QUICKSTART.md)。

## 安装和使用

在 `boundx` 目录执行（Python 3.10+，Node.js 22.18+）：

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r python/requirements.txt
node ui-server.mjs --open
```

Linux/macOS 将 Python 路径换成 `.venv/bin/python`。自定义解释器可设环境变量 `BOUNDX_PYTHON`。第一次安装需访问包仓库；运行 ADMIN 检查不访问模型服务，不需要 API 密钥。

进入“给 ADMIN 的任务建议”，粘贴原文并点击“本地检查”。修改原文后必须重新计算；旧结果不继续套用。Python 缺失、超时或引擎失败均明确显示，不降级为“通过”。本机请求最多等待 12 秒，后端子进程预算 10 秒。

## 实际计算链

1. 浏览器本地规则产生七要素与 B 的原文候选引用，保留字符位置。这仍是规则映射，不是完整语言理解。
2. 服务端将原文与本地产生的模态候选送入 Python。Lark 的有限文法解析显式集合、数值上下界、必须完成的依赖和模态条款。多解、超出文法的文本保留为 `uncovered`。
3. portion、Z3、NetworkX 分别计算并返回原句、过程、反例和中英文建议。独立收集结果，不投票、不短路掉其他建议。

不是全部语言分析都迁移到了 Python：现有七字段和复杂条件候选抽取仍使用 JavaScript；三类数学运算已经由 Python 实际执行。直接运行 Python CLI 的自然语言覆盖范围小于经过服务端条件抽取的路径。

## 数学原理与可运行案例

### 集合与区间：portion + set

令显式任务对象集合为 S，已知禁止对象集合为 B，计算：

$$X=S\cap B$$

`对象范围：{甲,乙}；禁止对象：{乙}` 返回交叠对象乙，建议核对范围。它不自己生成白名单，也不把未声明范围解释为无限集合。

同一指标、兼容单位的允许区间为：

$$J=\bigcap_i J_i$$

`时长至少120分钟；时长最多60分钟` 归一化成秒后得到空交集。不同指标不强行相交；调用次数按整数域处理。空交集意味着这些候选数值约束无法同时满足。

### 条件与模态：Z3

同一动作的必须条款和禁止条款各有条件 g_r、g_f，先计算：

$$\operatorname{SAT}(g_r\land g_f)$$

如果条件有交叠，给出条件见证，并计算动作约束：

$$\operatorname{UNSAT}(x\land\neg x)$$

`必须修改配置；不得修改配置` 返回两处原句和冲突建议。授权条件仅是符号变量，出现 ADMIN 名字不是已获授权。主体、对象、任务范围相同是需要核对的假设；不同动作文本不推断语义等价。`不必` 不等于 `禁止`。返回的 unsat core 不承诺最小。

### 必须完成的依赖：NetworkX

G=(N,E) 中 u→v 表示 u 必须完成后 v 才能开始。计算强连通分量：

$$\exists K\in\operatorname{SCC}(G): |K|>1\quad\lor\quad\exists v:(v,v)\in E$$

`甲完成后才能开始乙；乙完成后才能开始甲` 返回循环涉及的节点和原句，建议区分强制前置与参考信息。无环时给出拓扑顺序。只有显式列出节点清单后，才检查依赖引用的未声明节点。这不是一般程序停机证明，也不把所有循环都叫作业务死锁。

| B 已知禁止边界 | 未识别明确值，不补造禁项 |

原文没有显式对象集合、数值区间、必须/禁止对或依赖边，因此三类引擎均报告“缺少可计算数据”，不是“三项通过”。七要素映射仍可提供补充建议：明确资料版本、适用资源上限、已知禁止事项。原文保留在完整建议任务中，缺值使用占位符，由 ADMIN 决定填写或注明不适用。

这也暴露当前限制：库能严密计算已表达、已解析的约束，不能保证任意自然语言已经被准确转换。七字段有引用不等于任务完整，30 条文法测试通过也不等于真实语料高准确率。

## 接口与复现

Python CLI 接收一行 JSON `{"text":"必须修改配置；不得修改配置"}`，从标准输入读取，在标准输出返回 `boundx-admin-engines/v1`。本机界面调用受原有来源与会话校验保护的 `POST /api/admin-boundary`，仅需 text；不能由客户端注入条件候选。

输出包含 `ir`、`uncovered`、`versions`、三类 `engines`，每个发现包含 `sources`、`suggestion` 与 `witness`。状态区分 `insufficient_data`、`checked`（仅覆盖部分）、`findings`、`incomplete` 和 `error`；业务决定与确认值始终为 null。下载的原始 JSON 另外包含八维原文映射。

```text
.venv\Scripts\python.exe -m unittest discover -s python -p test_*.py -v
node --test ui/*.test.mjs
node --test src/__tests__/*.test.ts
```
