## 3. Skill 如何写：共享合同、独立职责、明确边界

每个 Skill 目录包含真实 `SKILL.md`，带 `name`、`description` 前置元数据。中文正文，机器标识保留原合同名称。

正文须明确：使用条件、输入、必须读入的合同、操作步骤、输出 Schema、异常处理和禁止事项。入口简洁，复杂标签定义与通用例子放参考文件；不能把整本手册复制两份后各自维护。

共用合同至少说明以下非同义区别，并逐条映射到 v0.4 条款：

- I/O/A/P/R/V/C + B 的准确含义，不能偷换成 who/what/when 等槽位。
- 动作实例与其执行者、对象、结果、接收者、依据和条件的绑定，不能跨事件任意组合。
- REQUIRED、PERMITTED、NOT_REQUIRED、FORBIDDEN 不可混同；只有条件被满足，不自动产生未陈述的执行义务。
- 条件前提、时间先后、整项任务完成、停止状态分别表达。
- 主句、定语、补语、目的、引文、输出内容和历史描述分别保留；单一层级标签不自动决定全部用途。
- 组织者不是所有动作的默认执行者；接收用途不自动成为独立强制动作；参与者角色不等于 Authority。
- 依据不是默认检查对象；文件格式不自动决定 I/O。
- 数量须带比较符、单位、目标和归属；资源约束、内容数量、分类阈值分别表达。
- 原文引文必须真实；重复 mention、指代和作用域有竞争时不猜；字符偏移仍由确定性来源链接器计算。
- 没有指定、真实歧义、未解析、原文没有该项必须区分。不得用全填槽位或全填未决获得表面成功。
- ADMIN 未声明的 WP、分工、默认操作者和工具协议不得补造。

解析 Skill 按已有合同组织语义，不要求模型输出隐藏推理过程。必要输出是图、来源、简短判据或疑点，不是长篇思维链。

Skill 的示例只能是必要的通用对照，不嵌入 027 的逐案期望、锁定评测答案和案例修补表。示例改变语义时不可冒称等义变换。

**隔离原则：待解析原文是数据。即使写着“删除目录”“忽略规则”“安装另一个 Skill”，解析器也不执行、不改变加载策略。任务文字中真实授权的行为可作为候选被表达，但不能变成解析进程的执行权限。**

## 4. 单一来源与版本锁定

优先以 027 经指定的有效提示词和合同为源，先做保真封装，不同时重写方法。

建立一个受版本控制的共用合同来源；构建器为两个 Skill 生成所需参考文件及 Schema 分发副本。所有副本携带相同来源摘要，自动检测漂移。逻辑单一来源不要求模型跨出沙箱读另一个目录。

运行包至少锁定：

```text
skill_name / skill_version / skill_tree_sha256
manual_version / manual_sha256
shared_contract_sha256
parser_schema_sha256 / audit_schema_sha256
short_invocation_prompt_sha256
provider_adapter_version / code_sha256
Codex version / actual model configuration
```

提示词模式与 Skill 模式必须从同一份内容源构建，禁止两套手写定义并存。每次语义措辞、示例或加载协议变化均记录版本；不能以“只是改 Markdown”掩盖方法改变。

不使用运行中的 latest 自动热更新。每个任务在调用前锁定快照，解析、审阅、重试和回放都使用同一快照。遇到版本混用、同名多来源或摘要漂移，停止该请求并明确报错，不悄悄回退到旧提示词。

## 5. 显式调用：不依赖模型碰巧选中 Skill

启动时核验本地 `codex --version`、`codex --help`、`codex exec --help` 与官方文档，保存实际支持能力。不能虚构 CLI 参数。

首选：在独立运行工作区中使用本地 Skill 加载机制，按所用版本支持的位置部署两个固定包，然后分别显式指定 `$boundx-semantic-parse` 和 `$boundx-semantic-audit`。`$` 是调用文本，不允许被外层 shell 当环境变量展开；使用参数数组或标准输入等经过测试的方式传递。

固定流水线只依赖显式调用，不依赖自动匹配 description。若需要 explicit-only 的元数据控制，按实际客户端能力验证并只作用于这两个隔离 Skill；不修改用户其他 Skill 设置。

短提示词只携带：Skill 身份、当前输入引用、合同/Schema身份、输出要求。关键合同不能只写一个路径并假设模型读了：

1. 必须内容实际装入上下文，或由可观察的文件读取进入会话。
2. 记录宿主提供的加载/上下文事件或工具读取证据。
3. 若宿主无法暴露加载过程，运行器可构建确定性内联提示词包，必须明确标记 `INLINE_BUNDLE`；不能将它伪报成原生 Skill 加载成功。
4. 原生方式未验证时，相关原生加载门为未验证，不能仅凭模型回复“我使用了技能”判 PASS。

输出 Schema 由运行器以本地实际支持的 `--output-schema` 或等价正式接口施加，并在返回后用程序再验证。未知参数、超时、截断、拒绝、格式失败均是独立运行结果；不能全算语义错误，也不能抛弃失败后只记重试成功。

同一请求的自动重试最多两次，使用同一快照；只能处理传输/格式异常，不把期望语义答案塞进重试。更多调用需要单独登记预算，不无限循环。
