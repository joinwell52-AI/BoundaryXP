## 2. 测试规程：先固定预期，再运行；不把机器自审当答案

本文件中的测试原文和核对要求由ChatGPT在测试前撰写，属于评测预期，不是ADMIN已经签字的人工Gold。Codex在看到任何本轮模型输出前，依据原文及v0.4/r02展开成逐事实账本，核对冲突并冻结源文、预期、等价比较规则及摘要。

每案预期必须明确：正向动作及模态、角色/对象/结果/依据、条件及其方向/目标/时序、资源与数量、完成/停止、禁止、未指定、真正歧义，以及不应出现的事实。下表核对点是最低要求，不是允许忽略其余内容。

正常语义评测允许等价表示：不同ID、中文同义动作名称、节点拆合、显式等价逻辑式、同一产物有来源关联的版本表示，不按文字相同打分。也不能把所有相近名字都当同一对象。既检查缺项，也审阅输出多出的每一项技术接受主张；不能只断言几个预期字符串存在。

预期/比较器遇到真实语义争议，冻结可确定部分并标REVIEW_REQUIRED，不删除案例或把待审记成通过。测试后才发现评测器错误时，仅更正评测器，在相同原始输出上重评分，保存初始与更正理由；涉及预期意义改变须另列待审，不把它算模型改进。不得让另一LLM即时生成预期并自动当真值。

## 6. 三层分开评分，必须读实际结果

每案形成一张可阅读的对照：原文要求→预期语义→LLM第一次候选→交付时最终候选→最终7+1→差异及具体字段/主张ID。

1. **语义解释**：是否漏掉明确事实、增加事实、绑错对象/角色、误解必要/充分/否定/引文、把未指定当歧义、把歧义强选。以冻结来源账本独立评分，不能用审阅器SUPPORT判正确。
2. **编译保真**：LLM已经正确表达的部分是否被技术处理或投影损坏；LLM错误被下游接受的情况也独立列出。只审被接受事实不能证明没有遗漏。
3. **用户最终结果**：最终7+1的明确要求、禁止、条件、角色和范围是否完整正确；真正歧义是否局部保留；中文是否遗漏JSON中的关键约束。

对每项最终技术接受的主张做来源审阅，保留支持/错误/待审结论；额外结构节点、同义事件拆分等不自动算错误。使用程序检查固定结构断言，并由执行Codex逐事实核对输出多出的内容；评审者如实标Codex，不称ADMIN已验收或独立人工审定。无法可靠判定的保留待审及最小争议，后续可交ChatGPT/ADMIN复核，不能在本任务自动补成PASS。

错误至少分：无依据义务/许可、明确禁止遗漏、必要条件丢失或方向改变、错误对象/角色绑定、数量/作用域错误、遗漏交付/完成、歧义处理错误、来源/渲染错误。报告哪一层最先错，不能拿“可能有问题”当确认错误总数。
