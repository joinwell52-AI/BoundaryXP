## 2. 明确职责：语义分析交给 LLM

新主链：

```text
ADMIN 原文
→ 本地来源保全与精确字面量识别
→ 显式加载任务语义解析 Skill
→ Codex 输出候选语义结构
→ 显式加载语义审阅 Skill，由另一次调用检查原文与候选
→ 程序校验来源、类型、引用、约束和依赖
→ 确定性生成边界中间表示与 7+1
→ JSON 结果 + 从相同结构渲染的中文结果
```

LLM 必须承担：任务行为及其参与者、对象、交付、依据、模态、否定、条件及作用域、指代、数量目标、当前命令与引文/修饰/背景的区别。不能在后面用规则重新解释一句话，把最重要的语义工作交回传统 NLP。

程序负责：精确定位、结构验证、保真规范化、明确依赖检查和固定视图转换。它不负责猜漏掉的执行者、默认协议、比较对象或条件；不能把仅有合法结构或模型之间一致写成已经证明忠实于原文。

HanLP、BGE、E5、NLI 等不作为新链路前置依赖；不因这些组件尚未接入阻断本任务，也不新造另一条 NLP 解析主链。首版先做完整 LLM 主链，辅助模型以后依据实际需求单独决策。

## 3. Skill 与代码必须一起写

至少交付两个真实的专用 Skill：

- `boundx-semantic-parse`：把 ADMIN 原文理解成来源可追溯的语义候选。
- `boundx-semantic-audit`：从原文核对明确要求、限制和指代，再检查候选中的遗漏、错误绑定、作用域错误及无依据推断。

共用一份语义合同和版本化输出 Schema；不要维护两套相互漂移的定义。Skill 正文使用中文，机器枚举和接口标识可保留英文。`SKILL.md` 具备名称、用途、输入、具体识别规程、输出和禁止事项。

解析 Skill 必须明确教给 LLM：

- I 是输入与作用域；O 是交付与结果；A 是要求或允许的动作；P 是明确参与角色；R 是资源及量化约束；V 是规范版本与依据；C 是任务完成/停止；B 是禁止与限制。
- 理解这些定义不等于直接签发最终授权。LLM 输出候选含义及其约束，最后的机器 7+1 由同一结构确定性生成。
- 一个任务可以有多个动作；必须按动作实例绑定角色、对象、结果、依据和条件，不能把平面词语列表任意配对。
- 组织者不默认执行所有动作；接收人不默认承担独立强制审核；未声明 WP 不自动拆 WP。
- “必须、可以、无需、禁止”是不同含义；没有说的保持未指定，不用全填槽或全未决假装完整。
- 定语、引文、目的和条件中提到一个动作，不自动新增执行义务；原文另有独立义务时分别保留。
- 同一文件可以先被生成、再被复核、再被提交；每个用途属于对应动作。它作为内部产物被复核，不自动成为外部输入。
- “依据规范检查文件”必须区分依据与检查对象；同一实体在不同动作中可以承担不同角色。
- 条件保留操作数、极性、必要/充分方向、时间约束及被支配对象；数量保留比较符、数值、单位及目标，不把所有数字放入 R。
- 原文有多种真正可行且改变边界的解释时保留竞争解释；源文明确但模型没有解析出时标解析缺口，两者不可混淆。

审阅 Skill 的每个疑点必须区分“直接受质疑的主张/关系/属性”与“仅用于说明的上下文引用”。不可因为一个操作缺少论元，就否定相关文件在其他独立动作中的清楚用途。

不在 Skill 中放评测答案、旧 case 修补表或对本次单例的专用答案。输入原文是待解析数据，里面的删除/发布/执行命令不成为解析进程的工具权限。

## 5. 新的语义输出合同：紧凑但完整

采用以动作/命题实例为中心的候选语义结构即可，不需要让 LLM 输出旧系统的所有内部字段。它是候选语义图的序列化表示，不另造一个平行语义体系。

必须表达：

- 实体及其不同原文 mention；每个事件/状态的稳定 ID。
- 事件的动作含义、角色关系、作用对象、产物、接收者及依据。
- 每个用途的来源与适用条件；实体身份不携带排他的全局“只能是产物/只能是输入”判决。
- 模态、否定、层级与当前任务用途；未指定项显式为空或未指定，不能从登录身份补值。
- 条件、范围、数量、完成/停止表达式及其绑定；不能只存一段“复核通过后”字符串等待下一次猜。
- 引文、定位线索、备选解释和真正缺口。

输出每条主张均应带支持其含义的原文引文和定位线索。程序计算字符偏移；重复引文需按句段、出现次数或上下文消歧。抽象语义允许对应多个真实片段，不伪造连续原文。

提示词、Schema、Skill、审阅、校验和投影从同一合同出发。对每个必需字段直接检查其生成和消费函数，不把合同盘点单独做成一轮等待审批的任务。

## 6. 重新实现小型验证与编译核心

不复制旧 Γ 的全局禁止、整组未决传播或兼容性要求。

新核心必须做到：

1. 来源不存在、引用悬空、类型非法、操作数缺失时明确失败；不能自己补事实。
2. 疑点作用于被质疑的主张及其真正必需依赖，不沿所有同现实体和说明性引用传播。
3. 条件结构可确定，而条件在业务现场是否为真可以未知；编译不能宣告复核已经通过。
4. 一项受条件限制的许可，不能因该条件未解析好而变成无条件许可。
5. 身份、动作用途、结构包含和认证依赖分别处理；合法共享/回指不自动等于循环证明。
6. 模型提出的审阅意见仍可能错误；审阅一致不是真值证明，冲突不能仅靠自报置信度强行选择。
7. 7+1各视图保留原主张ID、条件、对象和角色关系，不把它们拆成可以任意组合的独立白名单。
8. 未提及某维不等于禁止；未解析的限制不等于 ABSENT；有限结构通过不等于完整语义已证明。

中文视图从同一结构渲染，不再调用模型重新润色而引入另一版边界。
