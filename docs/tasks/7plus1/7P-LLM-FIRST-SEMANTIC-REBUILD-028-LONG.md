## 4. 解析Skill的具体内容

真正写出中文SKILL.md，含name、description及使用边界，而不是只在任务书中说将来要写。名称：boundx-semantic-parse。

规程必须让LLM完成以下工作：

1. 通读完整短任务，确认这是ADMIN边界描述，不执行原文，不自己制定PM计划或拆WP。
2. 识别任务事件、状态和提及事件，给每个实例稳定ID，不因同词就合并不同事件。
3. 按实例绑定谁做、对什么做、产生什么、给谁、依据什么；缺省执行细节不补造。
4. 解释必须/允许/无需/禁止及否定对象，保留层级、任务用途和来源。
5. 解释条件表达式、必要/充分方向、先后、根任务完成/停止与数量目标。
6. 解析同一产物的多次使用和指代；多个合理先行项时保留备选，不能靠最近距离强选。
7. 对照原文逐项检查动作、要求、限制和例外，标出真实歧义、未指定以及未解析部分。
8. 输出紧凑候选结构、来源和必要简短说明，不输出模型自封的CERTIFIED/RESOLVED或最终权威7+1。

必须明确告诉LLM：I输入/作用域、O交付/结果、A正向动作、P参与关系、R执行量化限制、V规范依据、C完成/停止、B禁止/限制。**知道识别目标是必须的；禁止直接签发最终状态，不是禁止理解7+1。**

通用区别必须写清：组织者不等于每个执行者；无需不等于禁止；目的补语不自动产生独立强制义务；条件里出现复核不自动要求执行复核；同一实体可有多种合法用途；单个层级标签不决定全部任务用途。

## 7. 写清楚程序如何消费LLM语义

候选结构可采用事件中心的紧凑格式，不必复刻旧027 Schema。实体、事件、角色主张、条件、数量、来源、疑点都有可引用ID。每个字段只有一份正式定义。

必须直接写出并连通：

- 来源链接：精确引文定位，重复出现消歧，抽象状态多片段来源；无依据偏移不得猜。
- 类型/引用/表达式校验：签名、参数个数、边方向、目标、单位、比较符及引用完整；模型输出不是可执行代码。
- 局部审阅处理：质疑某条角色绑定不等于实体身份错；真正身份歧义才影响依赖该身份的用途。
- 依赖检查：区分身份、结构owner、用途和真正必需前提。合法共享或回指不能直接判循环证明；不能把每个owner/context引用都当ALL依赖。
- 条件编译：保留必要/充分、时间、极性、目标和作用域。条件值未知不等于条件表达式解析失败；缺条件不得降格成无条件许可。
- 逐用途编译：生成/复核/提交同一文件，依据/受检对象，组织/执行等不能使用实体级标签一刀切。
- 固定投影：只根据结构中已表达的用途生成I/O/A/P/R/V/C/B；不重新看动作字符串选槽、不补默认操作人、不把所有数字都放R。
- 中文输出：来自同一Boundary IR，不另调LLM改写另一版意思。

保留技术接受/拒绝/未决状态，但其含义是有限合同检查，不是LLM解释真值证明。已完整表达且来源有效、审阅支持的主张可按公开有限策略接受；不得额外要求一个不存在的完美NLP验证器。可选组件未启用不是冲突。

**不能只写空壳或把全部输入判未决。目标是保留明确语义、局部隔离真歧义、输出可用7+1。**
