# BoundaryXP短文本7+1编译器：产品交付总要求

版本：r01；日期：2026-10-07。
依据：ADMIN明确要求“最后要成为产品，不是实验品”。

**最终交付对象是能日常使用、维护、升级的短文本7+1编译器产品，不是测试报告、样例演示、研究目录或一次可运行原型。** 本文固定产品终点，不新增解析路线，不改变v0.4/r02的7+1语义。

## 1. 当前030与产品交付的关系

030继续按原任务固定029受测版本，完成30条新短文本及规定重复测试；不改模型、Skill、合同、编译器、输入、分母或首次评分，不边测边修。本文的文档变更不是运行资源变更，不要求重启本地UI。

030测试完成只表示得到准确性证据，**不表示整个产品开发结束，也不自动表示产品验收通过**。得到结果后，后续实现必须沿用同一个产品主线，覆盖确认缺陷修复、回归、产品封装、安装升级及使用验收，不能又仅交一份实验报告。

本文件不自动启动下一实现任务，不授权030绕过其停止规则。下一次完整实现授权应引用本合同并绑定030实际结果；在该授权范围内，普通代码缺陷应自行修复复测，不每修一个模块就要求ADMIN另发一个实验任务。

## 2. 产品是什么、服务谁

首版交付Windows本地短文本7+1编译器，复用现有本地UI和统一CLI。正常用户通过粘贴或上传ADMIN短任务、点击编译、查看来源和未决、导出JSON完成工作，不需要编辑源码、手工构造候选图或打开研究报告寻找启动方式。

初版明确支持非空、最多300个Unicode码点的单一ADMIN短任务；超限或不支持结构明确提示，不截断、不伪报完整成功。此范围是首版产品能力，不得将范围外输入当成功；也不能将“所有输入都能被接收”当语义准确。

输入的是ADMIN授权边界，不代替PM规划、不擅自拆WP。产品编译边界，不执行任务提及的读取、删除、发布等业务操作。BUSINESS_EXECUTION_ENABLED=false不妨碍编译器成为产品，不以新增业务执行器作为交付条件。

## 3. 保留唯一的产品主链

短任务原文 → 正式解析Skill指导LLM → 候选语义 → 正式审阅Skill与新会话 → 技术校验 → Boundary IR → 固定7+1及同源中文结果。

LLM负责主要语义理解，程序负责正确消费和保真编译。复用028/029成果，不重搭NLP主解析器，不新建第二个UI，不为每次任务复制另一套完整核心。Skill、共享合同、Schema、校验与编译保持单一版本来源。

当前经过实测的同源INLINE_BUNDLE可以成为正式产品加载方式；不把原生Skill加载改造设为无依据的前置门，也不得虚报其已验证。

产品交付应有清晰、可维护的主模块和固定入口，用户不需要知道028/029等任务编号。如整理目录，须一次迁移并校验引用与行为，不保留两套独立演进的语义实现；仅改目录或删掉“research”字样不等于产品化。

## 4. 准确性是发布门槛，不是报告装饰

必须分别评估LLM原始解释、内部修订后解释、程序编译保真和最终7+1；完整关系、条件、范围、数量、禁止与未指定项都参与核对。

030发现的实际缺陷进入产品缺陷清单。无依据增加许可/义务、明确禁止或必要条件丢失、对象/角色错误绑定、错误状态导致放宽边界等已确认且未修复的关键缺陷阻断正式交付。无法解析的明确内容不能用ABSENT掩盖，也不能靠全部标未决获得安全满分。

真正歧义应局部保留并给出最小澄清；澄清由用户修改或明确补充原文后重新编译，不由模型替ADMIN决定。技术检查、两次模型一致、证明路径完整都不等于源语义必然正确。

修复后应保留对已确认缺陷和原正确行为的回归，比较首次与修复后的结果，不用改分母、改答案或挑最好一次结果凑满分。看过结果后修复的样本属于回归，不再称未见验证。发布说明据实际样本范围、失败/待审和重复运行结果陈述能力，不能宣称所有短文本永远准确。

## 5. 可安装、可运行、可恢复、可升级

正式交付至少同时满足：

- **安装与启动**：可交付版本化运行包或明确可复现的安装方式；在干净目录验证依赖准备、首次启动和新短任务编译，不依赖维护者的未提交文件或临时目录。外部运行环境、模型登录与用量依赖明确说明，不暗中购买服务或申请API key。
- **完整使用**：复用现有UI，真实阶段、取消、超时、错误提示、证据、未决、导出、历史可用；UI与CLI共用一个核心。重复点击、刷新、重启不偷偷重复模型调用或丢历史。
- **数据与安全**：本地保存用户任务与历史，不随源码公开上传。凭据不进入前端或导出；文本仅被解析，不转成工具权限；本地服务维持回环和请求保护。应明确文本发送给所配置模型服务，不将本地UI宣传成离线推理。
- **升级与回滚**：核心、两个Skill、合同/Schema、加载方式组成同一版本；升级前备份，升级后可验证，失败可回退到上一可用版本。历史标注生成版本，不用新版本重算后覆盖旧结果；不静默改变JSON含义。
- **维护与性能**：有使用说明、支持范围、常见故障排查、版本变更记录和回归命令。记录实际模型调用耗时、重复性与错误率，性能目标按实测和声明工作负载验收，不承诺15ms或无限额度。

已有可用功能经核实可直接验收，不为了形式重复重建。无需增加账户体系、云平台、多模型市场、长文本、WP矩阵或完整边界求解项目。

## 6. 什么才算产品交付完成

同一待交付版本须同时具备：稳定的安装/启动入口、明确支持范围、经核定的准确性和回归结果、无未关闭的关键发布阻断缺陷、真实UI/CLI使用验收、机器可消费且版本化的7+1、数据保护、升级回滚及使用维护说明。

最终交付先给用户运行包或安装入口、启动方式、使用流程和实际能力边界，再附测试报告。仅启动成功、测试完成、SEAL通过或一组样例全对都不能独自作为PRODUCT_DELIVERY_READY=true的依据。

当前本文仅规定目标，没有宣告030通过或当前版本已达到全部产品标准。公开merge、release、tag、发布包或对外部署仍须ADMIN明确授权；可先交付可验收的本地产品候选包。不得为“产品化”擅自删用户文件、重置工作区、改全局账号配置或动无关服务。

**终点是可直接使用并持续维护的编译器产品；测试是产品质量工作的组成部分，不是项目终点。**
