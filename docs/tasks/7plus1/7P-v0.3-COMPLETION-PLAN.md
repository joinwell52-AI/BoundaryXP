## 2. Remaining development plan

After 007, do **not** automatically continue with an indefinite sequence of 008/009/010 repair tasks.

The next planned work item is one controlled long task:

`7P-CLOSURE-008 — BoundaryXP 7+1 Parser v0.3 Semantic Closure & Certification`

This long task contains four gated phases.

### Phase A — Remaining Gap Map

Build a complete failure map across all accepted STANDARD cases.

Cluster remaining failures by semantic mechanism rather than by sample id.

At minimum classify:

- scope / ownership
- artifact identity
- action composition
- I/O binding
- condition / modality
- relation closure
- OUTPUT_CONTENT ownership
- typed unresolved
- normalization / comparison
- other method-defined categories

Deliver a frozen `REMAINING-GAP-MAP`.

No parser changes are allowed before the gap map is complete.

### Phase B — Multi-Case Semantic Closure

Repair root-cause clusters, not individual samples.

For every mechanism change:

- prove the first divergence;
- repair the earliest causal stage;
- rerun all STANDARD cases;
- run independent non-Gold tests;
- preserve regressions and first-run anomalies;
- prohibit sample-specific literals, IDs, paths and Gold-specific branches.

The optimization unit is the semantic mechanism, not one sample.

### Phase C — Full 7+1 Case Closure

Move from I/O/A-only progress to complete case-level acceptance:

`I / O / A / P / R / V / C + B + OUTPUT_CONTENT + status + binding + scope`

A correct result may be `RESOLVED`, `ABSENT`, or typed `UNRESOLVED` as defined by v0.3.

Do not force a RESOLVED value when the source does not provide enough evidence.

The objective is method-correct Canonical 7+1, not maximization of superficial MATCH counts.

### Phase D — Generalization, Anti-Overfit & Final Certification

Certify the implementation on material not used to drive repairs.

Coverage must include:

- new Chinese tasks
- new English tasks
- paraphrases
- reordered instructions
- nested lists
- long tasks
- multi-level scope
- tables
- code blocks
- repeated names in different scopes
- ambiguous inputs
- incomplete inputs
- conflicting instructions

Run source audit for:

- SWAI IDs
- Gold literals
- sample-specific text
- sample-specific function names
- sample-specific paths
- case-specific regex
- test-only shortcuts

Then run final:

- STANDARD
- Gold integrity
- generalization
- determinism
- repeatability
- full regression
- performance
- anti-overfit audit
- method compliance
- Manifest / SHA256SUMS / SEAL

## 3. Final outcomes

The v0.3 campaign ends with exactly one of:

### A. `V0.3_PARSER_CERTIFIED`

The implementation faithfully realizes the frozen v0.3 method and passes the final certification gates.

### B. `IMPLEMENTATION_GAP_REMAINS`

A confirmed v0.3-defined semantic mechanism is still not implemented correctly.

Only in this case may another implementation repair task be opened.

### C. `V0.3_METHOD_LIMITATION_CONFIRMED`

The implementation is faithful to v0.3, but a remaining semantic requirement is outside the method's current expressive or deterministic resolution capability.

In this case:

- stop modifying the v0.3 parser;
- preserve evidence;
- do not silently extend v0.3;
- open a separate v0.4 method-design track if ADMIN approves.
