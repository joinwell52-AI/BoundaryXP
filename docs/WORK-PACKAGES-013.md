# 显式工作包检查（迭代 013）

本文说明显式工作包的计算规则。数学求值不等于任意任务均正确解析，也不代表生产执行授权。

## 使用与实际结果

在 ADMIN 入口粘贴带同级 Markdown 标题的原文，例如：

```markdown
全局要求：不得修改配置。
## WP1 准备
必须修改配置。
## WP2 核对
耗时不超过 30 分钟；生成 report.csv。
```

每个 WP 展示“任务原文 → 七要素 + B 候选抽取 → 纯计算验证与待确认项（Diff）”。公式、库输出、反例和原文坐标放在技术详情中。中文与英文由语言选项切换，原句不自动翻译。

上述示例中，WP1 的“必须修改配置”与继承的前言禁令产生相反要求，显示双方原句和核对建议。WP2 的 30 分钟换算为 1800 秒，不与其他 WP 的耗时混算。不会因为编号连续就生成 WP1→WP2 的依赖。

如果删除前言禁令，让 WP1 要求修改、WP2 禁止修改，它们不再被当成同一阶段的一对冲突。这只是局部阶段隔离结果，未证明动作产生的状态变化不会影响后续阶段。

## 实现范围

- 识别显式 `#` 至 `######` 的同级 `WP1`、`WP2` 等标题，编号不必连续，最多 12 包。围栏代码中的标题不作为工作包边界。
- 首个 WP 前的正文保守作为继承前言；相关原句保留 `inherited_preamble` 来源标记。范围不明的前言仍需人工核对，不能把保守继承解释为精确作用域证明。
- 每包单独调用既有局部计算路径，再将证据坐标映射回完整原文的 UTF-16 区间。保留三个顶层引擎槽位，其内部 `scopes` 展示各包计算；没有做跨包全局相容性求解。
- 发现跨 WP 编号引用时，该包返回条件作用域未解决的提醒，暂不做局部相容性结论，避免丢弃跨包守卫。重复编号、嵌套 WP 标题和同级非 WP 标题等范围疑问不会退回扁平求解。
- 继承后待处理文本总量限制为 60000 字符，并保留已有子进程超时和输出长度限制。它们是工程限制，不是生产可靠性或固定延迟保证。
- 不含显式 WP 标题的输入仍使用原来的单文本路径。来自旧前端的无工作包作用域语句映射不混入 WP 局部计算。

## 明确尚未完成

跨包输入输出交接、类型与版本匹配、全局预算/关键路径、父子任务范围一致性、递归子阶段、流程失败/回滚语义以及一般终止性证明均未实现。当前宏观图返回空依赖边及 `dependenciesKnown:false`，不能理解为“原文没有依赖”。

七要素仍是原句候选映射。尤其 A 展示“动作原句（许可待核对）”，不会将扫描到动作词写成已授权动作。未映射字段不直接判为原文缺失；当前还不能保证复杂长句的条件、主体和并列对象都被正确绑定。

最新完整回归：23 个 Python 测试方法、115 项 UI/适配/服务测试、21 项核心测试，以及 UI JavaScript 语法检查通过。新增 WP 测试包含：阶段隔离、前言禁令、中英文显式标签、emoji 证据映射、代码围栏标题、重复/嵌套标题、跨包引用、数量限制和真实 Node→Python 调用兼容性。

## 50 条挑战文本的实际发现

已通过真实 Node→Python 适配器运行 50 条用户场景文本，包含汽车租赁 10 条。50 次均返回结果，零调用错误，零条声明完整解析；这不是 100% 用例正确率。

汽车用例暴露了“大于等于 700”被截为“等于 700”，以及“至少为 200 元”下限漏提取。已保存失败回归，再扩展比较符规则并验证阈值上下及等号。更正后的两项分别为 `ge 700`、`ge 200 CNY`。其余对象清单、理赔依赖、联合审批和跨句指标同一性仍有覆盖缺口，没有为贴合附件预期而强行合并指标、补造依赖或发出授权结论。
