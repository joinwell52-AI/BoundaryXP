> 历史／非规范研究或产品规划（legacy / non-normative）。本文中的旧接口、原始结果和未来能力不代表当前产品合同或本轮验证；当前入口以根 README 和产品手册为准。No BXP extraction certification or execution authority is implied.

- 真实场景：用户提供过“检查并汇报被 PM 扩展为修复后才能汇报”的复盘；本轮将该结构制成最小受控输入。本文不声称重新核验了历史事故全部因果。
- 核心问题：能否把任务边界变化变成可计算、可反驳的观察，同时不让程序取得业务裁决权？
- 骨架：设计决定。由检查→修复的具体反例进入集合差、合取谓词、图依赖，再解释原文映射和回应集合。
- 机制链：原任务→人工/模型语义映射→授权方确认→规划/派单映射→有限差异计算→有原文的建议→负责人逐项回应→未回应集合重建。
- 证据三角：历史背景仅限用户提供复盘；当前独立内核和宿主适配源码解释机制；本轮 native Node、MCP 与文件恢复探针证明受测接口行为。
- 外部对照：本篇不借外部论文证明产品能力；所用集合、命题合取、DFS 在文内直接推导。复杂形式化方法没有实现，不作背书。
- 工程定位：BoundX 是独立任务边界预检产品；本地 ADMIN 计算与宿主执行职责分离。
- 读者收获：能检查输入投影前提、复算反例、区分回应与解决，并按公开在私有仓库的命令复跑当前测试。
- 相邻事实界线：原文引用存在≠语义正确；集合差≠越权；MCP 挂载≠真实模型使用；回复结构完整≠理由成立；构建通过≠部署/发版。
