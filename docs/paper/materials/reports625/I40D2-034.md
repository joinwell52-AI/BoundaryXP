## 三、形式模型

以本轮四个 version 1 节点为分析切片，记根目录为 $W$，角色集合为 $R=\{DEV,OPS,QA\}$。目录绑定为：

$$D(DEV)=W/\mathrm{dev},\quad D(OPS)=W/\mathrm{ops},\quad D(QA)=W/\mathrm{qa}.$$

其中 $W=\texttt{workspace/oct27/i40d2-034}$。[E3] 这是角色与目录的联合映射，不能仅看三个目录标签是否存在。实际使用目录尚未知，不做字符串相等冒充实际路径核验。

记给定离线包为 $P$，实际任务输入为 $U$，网络访问事件为 $N$，当前分解交付为 $O_0$，未来复现输出为 $O_1$。父边界包括 $U\subseteq P$、$\neg N$，以及 $O_0$ 不附已经运行结果。[E1、E4] 未提供 $P$ 的封闭文件 ID 清单，因此不提交虚构的 set_subset 文件列表。

对每一条被作为真实引文提交的条目 $c$，要求存在绑定关系 $L(c,f,p,t)$：$f$ 是本轮允许的文件，$p$ 是该文件页码，$t$ 是该处原文，且三者共同支持 $c$。[E2、E8、E15] 页码相同、文件名相同或 SHA256 已填写，单独均不能证明该联合关系成立。缺失条目可以留在目录或缺口表中而不作为已证实引文提交。

局部命题计算使用：$q$ 表示条目作为引文提交，$l$ 表示该条引用具有可回查的原文、页码及相应文件绑定，$w$ 表示网页摘要替代引文，$f$ 表示填入虚构引文；OPS 计算中的 $u$ 表示执行其计划脚本动作，$o$ 表示该动作只在给定离线资料上做本地索引或摘要，$n$ 表示该计划包含网络访问。它们表示规则或计划约束，不是已观察到的运行值。

联合计算另外使用 $o,n,l,d,s,e,p,g$：依次表示全体角色仅使用给定离线输入、存在联网动作、全部实际引用满足联合定位、遵守角色目录映射、本轮交付保持执行前分解、当前交付附有已运行结果、PM 承担依赖与返工协调、缺失条目按子方案保留且不冒充有效引文。各计算的变量均在自身作用域中定义，不能把局部 $o$ 或 $l$ 的值跨作用域直接代入。

事件采用稳定身份：EV-DEV-HANDOFF 是 DEV 向 OPS 交接实现、样例及登记依据；EV-OPS-RUN 是 OPS 对该交接版本进行计划中的本地运行；EV-QA-READ 是 QA 阅读本轮交付说明；EV-QA-REVIEW 是 QA 依据该说明复核。[E9、E13、E17] 明确前置边仅为：

$$EV\text{-}DEV\text{-}HANDOFF\to EV\text{-}OPS\text{-}RUN,$$
$$EV\text{-}QA\text{-}READ\to EV\text{-}QA\text{-}REVIEW.$$

没有证据把所有 QA 动作都放到 OPS 运行之后，也没有证据要求 DEV 等待 QA 才能交接，因此不增加这些边。

## 四、数学计算一

本例的关键约束是来源与引用定位，不存在需要单位换算的数值限制。

对每条被提交为引文的条目，父规则为：

$$q\Rightarrow l.$$

DEV 的局部方案约束为：

$$C_D=(q\Rightarrow l)\land\neg w.$$

其中 $q\Rightarrow l$ 来自引用表必须列文件、页码和原文，$\neg w$ 来自不把网页摘要补进引文。[E7、E8] 因而：

$$C_D\Rightarrow(q\Rightarrow l).$$

K1 预期为 VERIFIED，证明的是该局部计划保留引用定位规则。它不证明实际文件已存在或引文已经核验。

QA 的局部方案为：

$$C_Q=(q\Rightarrow l)\land\neg f,$$

依据逐条检查原文、页码和文件身份，以及不填虚构引文。[E15、E16] 同样有：

$$C_Q\Rightarrow(q\Rightarrow l).$$

K3 预期为 VERIFIED。抽查截图是留证方式，没有把逐条核查改为只核查部分引文。

对于缺失条目，可作条件见证 $q=0,l=0,w=0,f=0$：该条目留作缺口，不冒充可定位引文，故 $q\Rightarrow l=1$。这是允许处理分支的 HYPOTHESIS，不声称已经存在某个缺失条目，也不要求所有引用都缺失。

对于 OPS，父边界在其运行动作上的投影为：

$$P_O=(u\Rightarrow o)\land\neg n.$$

“只运行本地文件索引和摘要脚本”“网络链接只作为字符串登记”，结合继承的给定离线包范围，保留 $P_O$。[E1、E11、E12] K2 预期为 VERIFIED。URL 字符串的存在不能推出 $n=1$；同样，“本地脚本”的称谓也不能证明实际脚本实现永不联网。后者需要运行前检查，当前未知不推翻文本层面的规则保留。

## 五、数学计算二

联合父边界的命题投影为：

$$P_J=o\land\neg n\land l\land d\land s\land\neg e\land p.$$

其来源依次为 E1 的离线与禁止联网、E2 的引用定位、E3 的目录映射、E4 的本轮阶段和不附结果、E5 的 PM 协调责任。子任务没有明确撤销或改写这些规则，联合有效子规则须保留它们，并叠加缺口处理约束：

$$C_J=P_J\land g.$$

这里的 $P_J$ 是有父正文依据的继承条款，不是假称子节点逐字重述。$g$ 来自 DEV 的保留缺失状态、OPS 的保存原错误、QA 的保留缺口和禁止虚构。[E7、E8、E11、E12、E15、E16]

因此：

$$C_J\Rightarrow P_J.$$

K4 预期为 VERIFIED，范围仅为联合规则的保留。该蕴含本身不证明 $C_J$ 可满足，须另给满足见证：

$$(o,n,l,d,s,e,p,g)=(1,0,1,1,1,0,1,1).$$

这一赋值描述：仅用离线包，引用均有定位，各角色按映射工作，本轮只交分解方案、不附已运行结果，PM 协调，缺口保留。它与三个子方案没有冲突。未来实现与样例的交接、本地运行、QA 复核作为后续事件安排，不要求把它们的结果提前放进 $O_0$。

交接前置图为：

$$G=(V,\{H\to R,\;Q\to V_Q\}),$$

其中 $H,R,Q,V_Q$ 分别对应四个稳定事件。路径 $H\leadsto R$ 和 $Q\leadsto V_Q$ 均直接存在，图无有向环。例如 $H,R,Q,V_Q$ 是一个拓扑序；它只是可行顺序见证，不额外要求 OPS 必须先于 QA。K5 预期为 VERIFIED，仅核对这两个有原文依据的前置关系。

各角色的结论分别为：DEV 的提取与交接计划未越界；OPS 的交接后本地运行计划未越界；QA 的核查、缺口记录及阅读后复核计划未越界。没有角色被证据确定为突破父边界。实际代码、路径、输入来源和运行行为尚未验证。

## 六、关键区别与可满足性

**父规则自身。** E1—E5 可以同时成立。上节满足赋值同时满足 $P_J$；允许缺资料待确认，消除了“必须联网才能补齐全部引文”的无依据前提。因此父规则自身不存在已证明矛盾。此结论来自 RULE 条款及其满足见证，不来自子方案是否违规。当前 Core 接口未提供独立的 SAT 结果对象，本次不把规则保留算子的 VERIFIED 冒充父一致性程序结果。

**父规则加当前事实。** 已知的是任务分解文本、角色及目录规则，没有文件清单、运行日志或真实交付结果。它们没有给出与父规则相反的运行事实。既不能断言现实已经满足全部规则，也不能把缺少日志当作没有运行、没有联网的证明。

**父规则加固定子方案。** 固定方案包含未来运行、交接与复核的条件安排，而父任务当前要求的是执行前分解。这两者可以共同成立：在本轮交付中写明后续步骤、前置和保存方式，但不附已运行结果。E13 的“执行输出按尝试编号保存”没有声明已经取得输出；E17 的“记录原始输出”同理没有声明输出已存在。当前联合方案在所建模型中可满足，不应标成 inconsistent。

**现实是否执行。** 从 PLAN 不能推出执行事实。交接发生、脚本运行、真实输出、引用核验以及目录使用均未被证实。父文“不附已经运行的结果”是交付限制，也不能反向证明任何现实执行均不存在。

两个反例说明判定边界。若未来把网址发给网络客户端获取网页，则 $n=1$，直接违反 E1；仅保存该网址字符串不产生这一见证。若当前分解交付附上真实运行输出，则 $e=1$，违反 E4；仅写出将来输出的保存规则不产生这一见证。反例均为 HYPOTHESIS，不是对任何角色的事实指控。

资料请求也不构成联网授权。QA 可以记录待取得材料；若后续取得材料涉及改变本轮给定输入范围，应重新明确来源与版本，不能因提出请求就视为自动获准使用外部资料。
