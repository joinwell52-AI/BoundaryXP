## 三、形式模型

令 $W$ 为本任务同一站点 `/apps/word-island/` 内的 URL 区域，$S$ 为同一站点根作用域 `/` 覆盖的 URL 区域。父文 E7、E8 给出 worker 的允许控制范围 $C\subseteq W$。路径字符串先解释为 URL 区域，不以字符串长度比较，也不把文件位置作为控制范围。

定义三个动作身份：$a_d$ 是 DEV 拟设置本候选 worker 根 scope；$a_o$ 是 OPS 拟保持已报告的根参数；$a_r$ 是 O5 报告的候选 worker 注册事件。三个身份不合并为一次已执行动作。QA 的动作是检查 $C$，不是修改 $C$。

令 $b_d,b_o,b_r$ 分别表示相应计划或报告中的控制范围完全位于 $W$。D4、D7 给出 $b_d=false$；O5、O6 给出 $b_o=false$；O5 给出 $b_r=false$。前两项是 PLAN，后一项是 FACT。父命题均为相应的 $b=true$。

其他约束用有限文本检查：$o,v,t,x,l,h,r,m$ 分别表示新增安排是否取消交付、弱化实际验证、以桌面冒充真机、调整其他应用或宿主、另选部署位置、破坏报告区分和关联、改派角色职责、移走 PM 自有职责。完整子文中这些变更均未提出，故作为任务书方案变量均为 false；这个结论只描述新增安排，父义务继续继承，不表示实际交付已经完成。

实际采用 L2 `software-ai@0.2.0` 的 `/frames/18`：部署服务属于 CHANGE 动作。该词义不授予部署或全站控制权限。`service worker` 查询未命中；`scope` 查询首批候选为无关完成条件，未采用。控制范围含义直接依据 E8、D4、D7、O5 和 Q3—Q5，不从未命中推导新歧义或身份关系。

## 四、数学计算一

父边界为：

$$C\subseteq W.$$

DEV 的明确选择是 $C_d=S$。OPS 要保持的选择是 $C_o=S$。取站点根 URL $u_0$，则：

$$u_0\in S,\qquad u_0\notin W,$$

因此：

$$S\nsubseteq W,\qquad b_d=b_o=false.$$

这给出了具体违反见证：根 URL 属于所选根作用域，却不属于父允许目录。无需枚举其他应用或网关的所有 URL，也不依赖服务器能否成功注册。DEV 同时将资源放在 $W$ 只证明文件放置选择，没有改变 $S\nsubseteq W$。
