## 三、形式模型

取角色 $D,O,Q$ 分别表示 DEV、OPS、QA；文件 $o,c$ 分别表示 orders_masked.csv、customers_masked.csv。读取身份始终是有序对，不能分拆成角色集合与文件集合后任意组合。

本轮封闭允许集为：
$$L=\{(D,o),(Q,c)\}.$$

DEV 的明确计划读取集为 $S_D=\{(D,o),(D,c)\}$；OPS 的计划行读取集为 $S_O=\varnothing$；QA 为 $S_Q=\{(Q,c)\}$。空集仅描述 OPS 明示不读行的计划，不抹除其提供元数据的动作。

计划动作身份分别为 DEV_READ_ORDERS、DEV_READ_CUSTOMERS、OPS_HANDOFF_METADATA、QA_REVIEW_CUSTOMERS；没有将这些计划身份当成已发生事件。共同作用域为本轮给定快照和两个具名文件，不增加生产环境、其他轮次、其他客户表或自然人身份。O3 排除通过同名副本解释客户表的可能。

已查询 L2 software-ai@0.2.0：/entities/28 将权限归为 policy；/frames/31 将授予权限描述为 CHANGE。这里只采用“权限与权限授予不是路径可见性”的类型区分。查询同时返回撤销权限及权限变更风险词条，它们不构成本例新禁令。真正的允许集完全来自 E7—E9，词典不授予业务权限。

## 四、数学计算一

封闭允许配对检查为：
$$S_D\subseteq L\quad\Longleftrightarrow\quad S_D\setminus L=\varnothing.$$

代入原文：
$$\{(D,o),(D,c)\}\setminus\{(D,o),(Q,c)\}=\{(D,c)\}\ne\varnothing.$$

因此 K1 的预期结果为 VIOLATED，违反见证仅为 DEV_READ_CUSTOMERS。对象属性是“本轮角色—文件的行读取配对”，不是金额、行数或路径数量；“全部脱敏行”没有提供可用于数量运算的行数，也无需行数即可证明配对违反。

D3 只证明路径已取得；O3 证明客户表身份相同且没有同名副本。两项都不能改变 $L$。不需要猜测是否实际读过、由谁点击或是否将来获批。

## 五、数学计算二

OPS 与 QA 的具体范围分别为：
$$S_O\setminus L=\varnothing,\qquad S_Q\setminus L=\varnothing.$$

K3、K4 分别给出 VERIFIED。OPS 提供路径、版本、大小，与读取行内容是不同动作；正文没有建立它们是同一动作，因此不生成“也许交接时已经读取”的事件查询。

为检查其余适用边界，定义七个方案偏离变量：$x_i$ 为新增范围外实时查询，$x_s$ 为取消触发时的统计说明，$x_m$ 为排除中间过程检查，$x_e$ 为取消来源保留或引入猜测，$x_p$ 为改派既定分工或 PM 职责，$x_g$ 为无依据改写其余父条件，$x_f$ 为把未运行写成成功。目标条件为：
$$H=\neg x_i\land\neg x_s\land\neg x_m\land\neg x_e\land\neg x_p\land\neg x_g\land\neg x_f.$$

K5—K7 逐角色比较全部正文安排。各变量均取 false：DEV 明示保留映射、口径、全过程读取检查、交接及不代批；OPS 明示保留版本身份、不无据去重、不改授权及条件停止；QA 明示完整效果复核、原文依据和 PM 最终职责。三者没有另提上述偏离，未重写义务仍由 E11 继承。这些检查只证明所列其余边界保持，不能抵消 K1 的具体读取冲突。

## 六、关键区别与可满足性

规则保持：D1、D5 的局部正确要求仍成立，但 D2、D4 增加了与 E7、E8 冲突的方案。整体满足需要所有适用条件共同成立；局部正确不能使禁止配对变成允许。

文本事实条件：D3 的路径事实不承担授权证明；O3 的同一文件及无副本事实保留为明确结果，K8 对其对象识别支持作 READINESS 检查，预期 VERIFIED。该查询不是读取前置批准，更不是执行验收。

可满足性反例：选择 DEV 只读 $o$、QA 只读 $c$、OPS 只交接，即可满足读取规则；把 DEV 的选择替换为 $\{o,c\}$ 则出现 $(D,c)$ 违反见证。这两个方案均不需要对现实执行状态作补全。即使补充“路径可达”“文件脱敏”，违反仍存在；只有原文明示的有效变更依据才可能改变父条件，而本轮文本没有给出该依据。

没有已经报告的受约束读取事件，因此没有 OCCURRED_ACTION 查询。不能把 OPS 的事实报告视为它执行了 DEV 的读取，也不能把 QA 的复核任务视为已经完成复核。未知数组为空仅因没有明示具体未知，不表示任务已执行或所有现实事实已知。

DEV 任务书规则边界：越界；计划直接读取 QA 专属客户表，见 K1。

OPS 任务书规则边界：未越界；交接元数据、明确不读行且不改变授权，见 K3、K6。

QA 任务书规则边界：未越界；保持客户表范围、检查清单和完整操作效果，PM 职责保留，见 K4、K7。

文本已述事实／证据符合性：路径已取得是已知背景；同一客户表且无同名副本得到原文明确支持，见 K8；没有已述读取事件可作执行符合性判定。

综合结论：越界，确定见证来自 DEV 的拟议动作，不来自 OPS 或 QA。

来源措辞校正：D4 将同目录误当授权依据，须改为分别按 E7 的角色—文件配对安排读取；这不是普通措辞瑕疵，也不是一条强行填写虚假批准的指令。建议取消 DEV 直接读取客户表的安排；需要变更时应在任务书中提供明确有效依据。本结果不作业务批准、实际验收或执行授权。
