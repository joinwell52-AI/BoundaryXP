## 三、形式模型

令当前允许地区集合为 $L=\{DE,FR,IE\}$（E3）；两个准备包的地区投影分别为 $D_1=\{DE,FR\}$（E16）、$D_2=\{IE,ES\}$（E22）。地区符号仅作为原文给出的集合元素，不补充地域、环境或权限含义。

定义动作身份：$a_1$ 为 DEV1 准备，$a_2$ 为 DEV2 候选准备，$a_3$ 为 OPS 拟议导出，$a_4$ 为 QA 计算列举。交付 PM 另属交接动作；它与导出不同。关系保持为“角色—动作—对象集合”，不把 DEV2 接触 ES 推成 DEV2 导出 ES。

设 $X_i$ 为各角色任务书新增的导出请求集合。完整正文支持 $X_1=∅$、$X_2=∅$、$X_3=D_1∪D_2$、$X_4=∅$。这里的空集合只描述新增导出请求，不抹除准备、交付、计算等实际提出的动作。由于没有报告已发生事件，不存在通过空集合回避事件核验的问题。

设 $g$ 表示 OPS 方案新增集合外地区的导出，$n$ 表示该方案取得新 ADMIN 授权。父前置为 $g⇒n$（E4）；E29 给出 $g=true,n=false$。另设 $d$ 表示本文提供新授权；E5 给出 $d=false$，它仅用于文内证据就绪性检查。

共同非干涉检查分别记录是否提出取消 PM 协调、转移 ADMIN 最终批准、凭岗位代批或捏造事实。这些是对完整任务书新增指令集合的比较，不是对现实行为赋值。没有配置词典包，且本次禁止工具调用；未声称完成任何 L2/L3 lookup，也没有虚构命中或未命中回执。

## 四、数学计算一

先计算拟议导出并集和集合外元素：

$$U=D_1∪D_2=\{DE,FR,IE,ES\}$$

$$W=U∖L=\{ES\}$$

所以 $U⊆L$ 为假，ES 是 K4 的具体违反见证。这个结果依赖 E16、E22、E29 对两个包与导出的联合绑定；即使不展开并集，E29 直接写明导出包含 ES，已经支持同一见证。

同时比较各角色实际新增的导出请求：$X_1⊆L$、$X_2⊆L$、$X_4⊆L$ 成立，$X_3⊆L$ 不成立（K2—K5）。准备 ES 的 $a_2$ 不属于父文受限的导出动作 $a_3$，因此不能用 $D_2⊄L$ 直接判 DEV2 越界。

上述集合比较没有数值量纲，不产生金额、时长或预算算法。未给执行记录、自然人姓名或现实结果均不影响这个任务书范围见证。

## 五、数学计算二

对 OPS 的授权前置，先列父命题：

$$g⇒n$$

代入 E29 的明确拟议安排：

$$g=true,\quad n=false,\quad (g⇒n)=false$$

K7 因而给出第二项局部违反见证：OPS 不仅选择集合外的 ES，还明确排除取得所需新授权。它不是普通的“确认某来源内容”，不存在将核对措辞误解成强行肯定的问题。

文内证据就绪性另列 K6：待比较条件为 $d$，实际给定为 $d=false$，故本文没有提供新增地区授权的支持。K6 的 VIOLATED 仅表示该就绪条件未满足，不单独宣布任何角色已经实施违规。这里确定的任务书越界由 K4、K7 支持。

共同检查 K1 比较四个角色的完整新增指令：均没有提出取消 PM 协调、转移 ADMIN 最终批准、凭岗位代批或要求捏造事实；交付对象都仍是 PM，且各自保留对象、版本与未知并禁止伪造完成或批准。因此 P 与相关禁止边界局部保持，OPS 也不因地区冲突而被额外认定改派批准责任。

## 六、关键区别与可满足性

规则保持方面，DEV1 的准备交付、DEV2 的候选准备及不导出、QA 的计算列举，可以与父规则共同成立。一个具体满足安排是：两名 DEV 完成各自候选准备并交 PM，QA 列出 ES，任何后续导出仅取 DE、FR、IE，最终业务批准仍归 ADMIN。此安排用于说明可满足性，不声称已经执行。

OPS 的原文方案不能借继承父规则而自动修复：同时保留“明确包含 ES、不取新授权”与当前地区、授权边界，就得到 K4、K7 的冲突。把 ES 从 OPS 并集中删除会改变原方案，必须作为修订建议明示。

文本证据方面，E5 明确否定“本文提供了新授权”；无需把它改成 null。假设现实另有授权并不能改写本文的给定证据，也不能消除 E29 明确“不取得新授权”的方案。若未来修改授权来源或允许集合，应重新比较修改后的文本。

本例没有明确未知需要真假补全；“没有报告执行”也不等于“已知没有执行”。因此不创建 OCCURRED_ACTION，不将任何准备、交付或报告者推定为实际导出操作者。任务书确定越界与现实执行状态未被报告可以同时成立。

## 七、最终结果

DEV1 任务书：未越界。新增动作是准备 DE、FR 并交 PM；导出、授权与分工边界继续适用。

DEV2 任务书：未越界。准备 IE、ES 的候选包不触发导出范围限制，且正文明确禁止该角色导出候选包。

OPS 任务书：越界。无新授权导出包含 ES 的并集，违反当前允许集合和新增地区授权前置。

QA 任务书：未越界。计算并列出集合外元素属于检查任务，没有导出或批准要求。

文本已述事实／证据：本文未提供新授权；相关就绪条件未满足。没有已述导出事件可作发生动作符合性判定，也没有明确未知被清除。

综合结论：越界，局部责任见证属于 OPS 的拟议导出要求；其他三角色的可靠未越界结论保留。

来源措辞校正：无需校正。标题仅作为主题保存；不把候选准备写成导出，不把计划写成执行，不把岗位写成批准权限。

建议将 OPS 导出集合明确限定为 $U∩L=\{DE,FR,IE\}$；ES 保留为候选并由 QA 列出。若确需纳入 ES，应先形成新的 ADMIN 授权及相应边界文本，再比较修订方案。本结果不作业务批准、实际验收或执行授权。
