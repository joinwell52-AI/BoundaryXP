## 三、形式模型

本轮稳定作用域记为 $\Sigma$：指定工作区内，依据 c41 与 d8 的本轮三次计划尝试及其最终交接。稳定事件 ID 为 run-1、run-2、run-3、submit-arrangement、fill-records、qa-select、qa-delete、pm-handoff。前三者来自 E6、E7、E10 的三个尝试槽；这些 ID 标识拟议事件，不证明事件发生。预检提交与据实填记录的流程关系来自 E4；选取及删除后保存文件列表来自 E15。这里不把报告引用、版本关联或主体分工改写为依赖边。

每次尝试的联合记录表示为 $x_i=(i,c41,d8,\Sigma,\theta_i,o_i,t_i,e_i)$，依次绑定尝试、源码版本、数据对象、作用域、参数、原始输出、耗时和退出码。$\theta_i,t_i,e_i$ 的实际值未知；DEV 拟固定输入参数、线程数及种子，OPS 拟记录实际值。保留 $o_i$ 的含义是保留该次原始证据，而不是仅保留其摘要或另一次版本的替代物。

实际采用 software-ai@0.2.0 的 /references/0：commit 可作为源码版本标识，但提及标识不证明真实性；/entities/22：数据集是数据对象；/references/7：摘要可以标识数据版本但不自证有效；/resources/0：耗时是执行时长，数值边界须有明确指标与界限。/frames/2 将提交代码界定为变更动作，本例“commit=c41”是版本引用，“提交工作安排”“提交复现结论”是交付动作，均不能据词面认作代码提交。数据集查询出现评测集等候选，本例仅按原文“数据集d8”使用通用数据对象义，不将 d8 扩充为评测集。未采用 L3 企业专用定义，也不从角色名称推导权限。

将父规则分别缩写为：$v$ 固定 c41、d8 且不换版本；$n$ 不改代码；$r$ 保留每次原始结果；$f$ 对实际发生的首次失败及恢复过程履行交付；$w$ 新建并使用指定工作区；$l$ 按角色和尝试编号存放；$s$ 先交安排供预检、实际操作后填执行记录；$m$ PM 负责交接收口。则父边界为 $F=v\land n\land r\land f\land w\land l\land s\land m$。其中 $f$ 是条件义务，不编码“首次失败已发生”。

## 四、数学计算一

先明确数量对象：三个是本轮计划尝试槽，单位为“次”；每个槽的输出集合记为 $o_i$，不是假定每次只有一个物理文件。耗时 $t_i$ 是相应尝试的执行时长，只有取得可比单位与口径后才可计算最短者。原文没有具体耗时或单位，不能换算、补造最短值或认定某次成功。

对已形成三个可比较候选的拟议情景，令 $S=\{1,2,3\}$，选中槽 $j\in\operatorname{argmin}_{i\in S}t_i$。只选一个槽时：

$$|S\setminus\{j\}|=3-1=2.$$

这表示另外两个尝试槽被 QA 计划列入删除范围，不是断言实际已经删除两个文件。父要求对三个槽均保留原始输出：

$$r=\bigwedge_{i\in S}Retain(o_i).$$

QA 的固定动作是对其余输出执行删除，因此对任意实际选中槽 $j$，都有非选中槽 $k\ne j$ 的违反见证：

$$Delete(o_k)\land\neg Retain(o_k).$$

故 QA 完整删除方案给出 $\neg r$。这一结论不依赖哪次最短、具体耗时、首次是否失败或环境字段是否已取得。若耗时不可比，最短选择本身未决；但这不使删除要求与父留存要求兼容。对应 K1 的命题操作数只检验原始结果留存，不声称已算出最短耗时。

## 五、数学计算二

父边界要求 $r$，QA 方案在其拟执行的最终状态要求 $\neg r$，所以：

$$r\land\neg r=\bot.$$

K1 以 $r$ 为父要求、$\neg r$ 为明确标注的计划情景，预期结果为 VIOLATED。联合方案中，OPS 先保存所有输出不能抵消 QA 后续删除：留存义务在最终交接仍适用，不能用某一中间时刻曾保存来满足。K4 对联合最终状态采用相同见证，未把互相矛盾的子方案合取作为事实前提，因而没有利用矛盾前提作伪证明。

DEV 和 OPS 的继承检验采用规则保留，而非现实履行检验。以 $d$ 表示 DEV 新增的整理、空表、固定参数、目录和报告条款，以 $o$ 表示 OPS 新增的三次运行、记录、保存和交接条款：

$$F\land d\Rightarrow F,\qquad F\land o\Rightarrow F.$$

K2、K3 中的 $F$ 来自明确列出的父条款继承，$d,o$ 分别来自各自正文；这些蕴含证明新增安排没有取消父边界，不证明任何实际执行。DEV 的“不覆盖首次失败”只是加强局部保护，单凭这句话不能替代完整留存要求；OPS 的全部输出交付也不能替 QA 的后续删除免责。QA 其余六项父规则仍继承，K5 单独验证这一范围，避免把 QA 的一项突破夸大为所有维度都失效。

## 六、关键区别与可满足性

父规则自身可满足：取一次拟议执行情景，使用指定工作区，三次都以 c41、d8 运行，不改代码；各次原始结果分别归档，若第一次失败则完整保留并交付失败与恢复过程；先提交安排，实际操作后填写记录，最终由 PM 交接收口。此时 $v=n=r=f=w=l=s=m=1$，所以 $F=1$。这是具体满足见证，不是假称这些事情已经发生。父规则没有要求删除结果，也没有强制用其他版本恢复，故不存在已证明的父规则内部矛盾。

规则加当前事实：没有提供实际运行与产物状态，因而没有现实违约或现实完成的确定结论。空表计划和事后填写要求均不能补成“确定尚未运行”。

规则加固定子方案：DEV、OPS 的新增安排可与父规则同时成立；但 QA 的删除要求使最终状态同时需要 $r$ 和 $\neg r$，因此完整联合方案无满足赋值。即使首次没有失败，删除其他运行原始输出的冲突仍存在；若首次确实失败，则还需检查失败与恢复过程是否能够完整交付。

反例与修订见证：QA 可以令最终报告只引用最短耗时输出，同时把三个尝试的完整原始结果和失败、恢复证据保存在指定工作区，报告附其路径、摘要与选取依据。令 $r=1$ 并保留选取动作，父规则仍有满足赋值。原文未提供“仅删除临时副本且完整原件继续保存”的限定，不能擅自用这一有利假设解释当前删除条款；若确有此意，应明确重写删除对象与归档位置。

现有接口没有直接的独立 SAT 求解操作，本答复以显式满足赋值和冲突公式提供父一致性、联合不可满足性的论证，不编造父一致性 Core 运算记录。所有列出的操作数均是供宿主复算的输入及预期结果，未声称程序已经执行。
