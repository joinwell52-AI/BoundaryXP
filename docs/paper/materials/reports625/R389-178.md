## 三、形式模型

作用域 $\Sigma$ 固定为 MT009 本轮任务书、其六个节点及明确命名的输入和目录。输入集合为 $S=\{S01,S02,S03\}$，其成员指脱敏副本。该集合有三个不同输入身份，不据数量推断其他对象等价。

令 $D$ 表示 audit-private，$H$ 表示 shared-summary。读取动作身份为 $a_d=(DEV,read,D,\Sigma)$；QA 自行复核为 $a_q=(QA,review,\Sigma)$；接收记录为 $a_r=(QA,receive,DEV\text{的读取记录},\Sigma)$。三者不是同一动作。整理员的编排动作也有独立主体，不能与 $a_d$ 合并。

父规则包含：

$$\neg Read(DEV,D)\land\neg Read(OPS,D).$$

QA 的许可和共享条件分别为允许 $Read(QA,D)$，以及选择共享结论时必须去除个人字段。许可不是必做命题；接收记录也不是 $Read(DEV,D)$ 的授权来源。

L2 的 permission 词条将权限归为 policy（software-ai@0.2.0，/entities/28）；本例具体政策来自父文 E7、E8、E14，而不是词典。L3 开发岗位词条要求依据任职事实判断个人岗位（tenant-a@0.2.0，/positions/2），测试岗位词条区分任职身份与任务负责人、签字人（同包 /positions/3）。因此这里只使用原文明示的 DEV、QA 角色，不把任一候选员工认定为操作者或审批人。OPS 查询也未用于映射个人。两个目录名称的企业词典查询未命中；目录关系仍直接采用 E7、E8 的明文，不从未命中推导同名、授权或未知。

计算 K1—K5 比较各角色的具体方案动作与适用边界；K6 比较完整动作清单是否另外缩减输入、交付、证据职责、冻结和汇总分工等。K6 的否定变量表示“是否提出某项具体越界改写”，不是某项实际执行是否成功。对于未被改写的要求，E13 保持其规范效力；它不会把 E18 自动改写成禁止读取。

## 四、数学计算一

关键问题是主体与目录的联合绑定。定义 $d$ 为“DEV 本轮拟直接读取 audit-private”。父要求与子方案分别是：

$$P_1=\neg d,\qquad C_1=d.$$

E7 固定禁止主体为 DEV，禁止对象为 audit-private；E18 给出的主体、动作和对象完全对应，故代入 $d=true$：

$$C_1=true,\qquad P_1=false.$$

这给出 K1 的局部违反见证。见证不依赖真实读取是否已经发生，也不依赖具体员工姓名、容器是否就绪或 QA 是否完成复核。没有把“拟”转换成“已执行”；被比较的是所选动作能否属于父规则允许的方案。

作为对照，令 $o$ 表示“OPS 的本轮方案安排读取 audit-private”。E29 的具体方案是只准备隔离容器，E27、E28 的相邻任务是整理安排和分开记录，没有读取要求。因此 K2 使用 $o=false$，满足 $\neg o$。这一结论只针对 OPS 任务书，不是对其现实行为的历史证明。

## 五、数学计算二

再检查权限是否可由复核、交接或编排扩张。令 $q$ 为“QA 方案要求 DEV 代读或把 QA 的私有目录读取权转给 DEV”，$h$ 为“QA 拟向 shared-summary 写入保留个人字段的结论”。父条件为：

$$P_3=\neg q\land\neg h.$$

QA 写的是自行复核、接收记录，且明确不转授权限（E32、E34）。没有要求 DEV 代读，也没有拟共享含个人字段的结论，故其方案赋值为 $q=false,h=false$，K3 通过。DEV 独立写出的违规读取仍由 K1 保留；不能反过来把 QA 的“接收”解释成该读取的指令。

DEV 文档整理员的方案为仅编排已交材料、注明缺项、不代造、不改变证据或安排；QA 证据复核员的方案为保留原文绑定、沿用 QA 安排、不转授、不批准、不宣告完成。K4、K5 分别比较这些明确动作及其权限效果，并检查没有改派父角色自身职责。其通过不要求整理员删改 DEV 原文，也不要求整理员承担 DEV 或 QA 的工作。

K6 另外核对各方案没有取消三份脱敏输入范围、复现目标与整体交付，没有新增客户原始库访问、落地修改、个人字段共享、代审批或事实补造，没有改派 PM 冻结、汇总和报告责任，也没有取消各角色保存证据的职责。这是对完整子方案的具体非干涉比较，不能代替 K1 的读取冲突检查。没有数值预算、时长或近似计划参数，所以不生成预算、区间或时长参数查询。

## 六、关键区别与可满足性

父规则自身有可满足解释：使用三份脱敏副本，PM 冻结数据包，各角色保存证据，QA 在自身许可内复核；如需向 DEV 传递结论，去除个人字段后写 shared-summary；DEV 不读取 audit-private，OPS 准备容器，本轮只交报告和建议、不落地修改。这是说明父规则未显现矛盾的模型见证，不是声称这些工作已经完成。

加入 DEV 的固定选择 $d=true$ 后，$d\land\neg d$ 不可满足。无论 QA 自行复核取何种完成状态，或记录是否已交接，都不能使该固定方案满足 DEV 读取禁令。因此完整方案的确定冲突不受这些未报告事项影响。

若只比较其他角色，存在同时满足它们自身安排与父限制的方案：OPS 只准备容器；QA 自行复核、接收记录而不转授权限；两名整理者仅保真编排。这里“接收 DEV 的读取记录”不证明实际存在合法记录，也不证明实际读取已经发生；父文没有禁止接收或要求销毁该类记录，所以不能增设相邻行为禁令。

规则保持与事实条件充分性分别处理。本案没有某个明确报告事件、身份未定或前置证据不足的独立事实陈述需要 EVIDENCE_ASSESSMENT；也没有把“无新增动作”替代对某个已述事件的判断。文内通用的保真指令不产生额外执行成功待证目标。本文不证明前置已经现实满足，也不要求补交运行日志。
