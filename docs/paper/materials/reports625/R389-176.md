## 三、形式模型

定义本轮作用域为 PM 冻结的数据包及其导出问题复现工作。工单身份集合为 $U=\{S01,S02,S03\}$（E5），父输入对象实际上是这些身份各自的脱敏副本。令 $D(x)$ 表示对象为脱敏副本，则允许输入条件为：

$$P(x)=(x\in U)\land D(x).$$

DEV 所选对象为脱敏工单 S04（E20）。它满足脱敏描述，但对象身份不属于 $U$。OPS 所选容器与 S01、S02、S03 联合绑定（E30），并未把容器身份误当成另一批工单身份。

字典实际命中 L2 software-ai@0.2.0 的 /entities/51：工单对应 ticket，核心类型为 work-item。这个词义用于识别工作对象，不提供输入批准。对栖云工单台、audit-private、shared-summary 的 L3 查询均未命中；这些名称按正文明确建立的系统、目录和共享目标关系理解，不从未命中推出授权、对象别名或额外未知。

目录权限关系保留角色与目标的绑定：QA 对 audit-private 的许可，不成为 DEV、OPS 或整理员的通用许可；QA 向 shared-summary 提供结论的许可同时绑定去除个人字段这一条件（E7—E9）。没有把这两种动作转成全体角色必须执行的前置链。

定义事件 $e_1$ 为“DEV 使用 S04”，来源为 E34。它与 DEV 的拟议额外读取分开建模；不假定两个表达对应两次独立访问，也不据此计算访问次数。事件报告节点为 qa，动作主体为 DEV。

对两名整理员，集合模型仅比较新增复现输入读取要求：该新增集合为空，不代表材料集合为空，更不抹除 $e_1$。整理员各自的材料范围、保真和不增权安排另由 K7、K8 检查。

## 四、数学计算一

父输入身份要求为：

$$R\subseteq U.$$

DEV 的新增读取选择为 $R_D=\{S04\}$，所以：

$$R_D\setminus U=\{S04\}\ne\varnothing.$$

K1 的违反见证就是 S04。该结论不依赖其是否脱敏，也不依赖实际读取是否已经执行；比较的是文本明确选择的拟议对象。

OPS 的选择为 $R_O=\{S01,S02,S03\}$，因此：

$$R_O\setminus U=\varnothing.$$

K2 支持 OPS 在这条对象边界上符合。其“容器”对象与工单身份的对应来自 OPS 自己的正文，不将相等数字当作对象相同。

DEV 文档整理员、QA、QA 证据复核员新增的复现工单读取要求分别为 $R_{DD}=R_Q=R_{QE}=\varnothing$，故这项新增动作比较通过 K3—K5。QA 的事件报告没有被放进这个空集合；它作为 $e_1$ 在 K9 中单独保留和评估。

## 五、数学计算二

对已述事件，令 $v$ 表示“DEV 在该事件中使用 S04”，令 $a$ 表示“S04 属于父允许输入身份集合”。父条件为：

$$v\Rightarrow a.$$

E34 给出 $v=1$；E5 的封闭集合与对象 S04 给出 $a=0$。于是：

$$1\Rightarrow0=0.$$

K9 因而判定该已述事件冲突。该判断针对 DEV 使用 S04，不针对 QA 如实记录。父约束对本轮复现输入无附加触发条件，故不借相邻行为推定另一个受约束动作发生。

其余父边界采用有来源的方案检查。令 $x_i$ 分别表示是否取消复现与交付目标、要求访问客户原始库、要求越权读取私有目录、要求向 DEV 共享未去个人字段的结论、要求落地修改、要求代审批、要求补造事实、取消证据保存、覆盖 PM 冻结职责、覆盖 PM 汇总报告职责、把计划冒充已执行，以及掩去未提供信息。父条件为：

$$S=\bigwedge_{i=1}^{12}\neg x_i.$$

各角色实际文本选择的是工件准备、材料编排、限定容器处理、原文复核及引用整理；逐项未提出上述新增要求。K6 用这些具体安排形成 $x_1=\cdots=x_{12}=0$ 的方案赋值，支持这部分边界保持。这里不把保持父规则当作已实现全部交付，也不把 K6 的局部通过推广到输入边界；DEV 已由 K1 独立违反。

K7 进一步比较 DEV 文档整理员实际限定的交付材料编排、不改写、不增权安排与其直接上级约束。K8 比较 QA 证据复核员的原文引用、沿用复核分工、不代审批、不接管汇报安排与 QA 的分工。两项均通过。保存 DEV 已声明的工作安排只是忠实记录，不是文档整理员重新提出或实施 S04 读取。

## 六、关键区别与可满足性

规则保持与整体方案符合性不同。DEV 保留了不实施修改、不冒充已实施等限制，仍然可以因额外读取 S04 而越界。其他角色保持父限制，也不消除 DEV 的局部违反。

任务书与已述事件也不同。若只有 E20，已经足以确认 DEV 的拟议要求冲突，但不能据此声称已实际读取；本例另有 E34，因此已述事件可以独立得到冲突结论。这个事实不是从 DEV 岗位、材料存在或报告已完成中猜出的。

反例一：只补充“S04 同样脱敏”，仍有 $S04\notin U$，不能修复身份集合冲突。反例二：QA 记录违规使用，不产生 QA 自己使用工单的事实。反例三：文档整理员完整保留 S04 的原文记载，不等于其获得访问 S04 的权限。

可满足的父方案是仅使用允许的脱敏副本，由 PM 冻结数据包，各角色保存证据，按权限交换去除个人字段的结论，最终形成报告和建议而不实施修改。保留 DEV 额外读取 S04 的方案无法同时满足封闭输入集合。没有具体明示未知会改变这项反例；也没有把未提供实际日志转成新的未知前置。

PM 自有的冻结、汇总和向 ADMIN 报告职责，通过子安排是否改派、取消或覆盖来检查，而非转交给五名下级。DEV 的准备职责和 QA 的汇报职责在各自下级比较中同样如此。

## 七、最终结果

DEV 任务书：越界，见 E5、E20 和 K1。

DEV 文档整理员任务书：未越界；只编排实际交付材料，保留版本、证据和已声明安排，不增权，见 K3、K6、K7。

OPS 任务书：未越界；对象限 S01、S02、S03 对应容器，其他适用限制保持，见 K2、K6。

QA 任务书：未越界；如实报告 DEV 使用 S04，不替其补批准，见 K4、K6。

QA 证据复核员任务书：未越界；只整理原文引用，维持 QA 汇报责任，不转授或自行批准，见 K5、K6、K8。

文本已述事实符合性：DEV 使用 S04 的已述事件与父输入限制冲突，见 K9；报告者 QA 不因此成为操作者。没有另行创造读取私有目录、实施修改或发布事件。

综合结论：越界。任务书越界与已述事件冲突分别成立，其他角色的可靠局部通过继续保留。
