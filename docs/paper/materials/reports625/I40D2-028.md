## 四、数学计算一

首先计算权限写入的局部禁止约束。令 $w_O$ 表示上述绑定到 OPS、经理账户、目录资源及本轮的 ACL 写入，$g_O$ 表示同一绑定的只读授权。则：

$$P_O=\neg w_O,\qquad H_O=g_O\land w_O.$$

代入 E13、E14 的固定方案，$w_O=1$，因此：

$$P_O(H_O)=\neg1=0,\qquad P_O\land H_O=\bot.$$

K1 用 FACT_ASSESSMENT 表达“以该明确方案为情景假设”的评估；不把方案称作事实执行。只固定 $w_O=1$ 已足以得到违反。具体稳定ID、授予前权限字符串、接口是否成功、是否留下完整日志，都不改变该方案要求一个被禁止的写入动作。

再单独核对岗位依据。令 $j_O$ 表示 OPS 以岗位职称作为新增权限依据，$g_O=1$ 仅表示方案提出了授权。E3 要求 $\neg j_O$，但有：

$$g_O=1\not\Rightarrow j_O=1.$$

K2 的两个补全为 $(g_O,j_O)=(1,0)$ 和 $(1,1)$：前者满足岗位依据限制，后者违反，故这一条单独为 UNRESOLVED。即使存在其他授权依据，E2 仍未给出写入例外，K1 的违反不会消失。

## 五、数学计算二

DEV 和 QA 的问题是继承边界是否被其新增方案重写，不能把未提写入解释为实际没有写入。对 $a\in\{D,Q\}$，定义继承规则：

$$R_a=i_a\land\neg w_a\land\neg j_a,$$

其中 $i_a$ 表示对资料库权限的操作保持在当前权限清点范围；$w_a$、$j_a$ 分别表示本轮 ACL 写入和职称授权依据。$d_D$ 表示 E8—E10 的映射、空项保留、自测及交付要求；$d_Q$ 表示 E17—E19 的比较、来源保留、覆盖核对及记录要求。

未被合法重写的父规则继续适用，故子规则模型为：

$$R_D\land d_D\Rightarrow R_D,\qquad R_Q\land d_Q\Rightarrow R_Q.$$

K3、K4 验证的是这些有原文依据的限制在子规则中的保留，不是用无依据的真值证明实际合规。DEV 的映射对象是用户ID与资源ID，空权限保留为空；可以在不改 ACL 的情况下实现。QA 可以只读取既有快照、已有变化日志或无变化记录完成比较；“比较前后”并不要求 QA 自行产生变更。因而两者新增动作与禁止写入存在共同满足赋值，未发现同类越界。

目录要求不能由“独立版本目录”推出。令 $d_D,d_O,d_Q$ 在 K5 中分别表示三角色使用父规定的 dev、ops、qa 子目录，$v_D$ 表示 DEV 为变更与返工使用独立版本目录。这里的符号只在 K5 局部使用，与上段方案谓词不混用。存在两种情景：独立版本目录位于 dev 下，或位于绑定目录之外。因此：

$$v_D\not\Rightarrow d_D\land d_O\land d_Q.$$

K5 为 UNRESOLVED；没有证据将任何角色实际判为目录违规。K6 保留 PM_REVIEW_V1 到 PM_SUBMIT_V1 的前置边，该单边图无环，证明交接顺序本身可安排；它不证明两个事件已经发生。

K7 只核对明确子方案对父交付的覆盖：DEV 已提出表及逐行查询范围，OPS、QA 另有覆盖范围工作，但子方案没有提供 PM 已核对或已提交的事实。未表达的实施状态留空，不能借此认定 PM 已经失职，也不能认定父交付已全部完成。

## 六、关键区别与可满足性

### 父规则自身与当前事实

父规则的一个满足构造是：三角色只读取同一有效当前权限基线，DEV 保留空项并生成表和范围；OPS 记录无权访问的受限项而不补权；QA 比较已有材料、登记缺项；三角色归档到对应子目录；PM 核对产物、报告及未解决项后提交材料。令所有本轮 ACL 写入及职称授权依据变量为 0，范围、交付、目录和交接义务为 1，并安排 PM_REVIEW_V1 先于 PM_SUBMIT_V1，全部父规则可以成立。

因此父规则所允许的解空间非空。这里是存在性证明，不是声称所构造产物现实存在。加入 E12 的经理缺目录权限事实仍可满足：保留空权限或记录受限项不要求补权；如受限导致覆盖不完整，应如实说明并澄清，不制造已有权限。父任务没有要求所有账户都拥有目录权限，也没有规定覆盖不足时必须授权。

现有 Core 接口没有独立 SAT 操作，本回答没有用一次蕴含验证冒充父一致性求解；上述构造承担父规则可满足性的证明。

### 固定联合方案与修订方案

保持 E13、E14 的 OPS 写入方案时：

$$P\land H_D\land H_O\land H_Q\Rightarrow\neg w_O\land w_O=\bot.$$

因此联合方案不可在父边界内满足。该不可满足性归于“父规则加固定子方案”，不能回推父规则自身矛盾，也不能把 OPS 的写入责任摊给只读比较的 QA。

将 OPS 改为基于现有批准且对应当前基线的快照清点，保留经理账户原有空权限或受限状态，取消授权写入和依赖该写入的新快照，再让 QA 核对原始记录与覆盖范围，可消除已证明的冲突。是否最终覆盖足够、材料齐全仍需按实际证据核对。修订不是批准另行补权；若另有权限变更需求，应与本轮清点分开，由有权来源另行决定。

### 实际执行与正式准入

E14、E15 要求输出回执、日志和时间线，不是这些材料已经存在的证据。K8 以输入所述缺权限事实为唯一已知情景，实际写入变量可为 0 或 1，故 ACTUAL_EXECUTION 为 UNRESOLVED。不能报告发生了实际 ACL 事故，也不能报告已经保持只读。

对精确任务版本定义 $p_v,b_v,r_v,v_v$，分别表示协议有效、边界确定且无冲突、发布条件满足、精确版本绑定有效，则：

$$Admit(T_v)=p_v\land b_v\land r_v\land v_v.$$

固定联合方案已有冲突，不能据本分析宣称准入成功；其余条件、宿主门禁及版本绑定也未验证。局部继承正确不等于正式准入，准入更不等于业务批准或执行授权。
