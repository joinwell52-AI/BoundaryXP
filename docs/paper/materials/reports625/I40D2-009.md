## 三、形式模型

令共同作用域为 $\Sigma$：本轮任务树规定的原流水线、各入口引用的统一模板、同一轮同一制品的阶段串接，以及指定工作区内按角色和尝试编号区分的任务产物。两项计算分别使用稳定标识 S-PIPELINE-ORDER 和 S-DOCUMENT-CONTRACT，含义见对应计算条目。

定义稳定事件 ID：EV-REVIEW 为同轮同制品的审阅完成事件，EV-SCAN 为扫描完成事件，EV-SIGN 为签包完成事件，EV-PUSH 为推送事件。事件 ID 不代表事件已发生。DEV 的 E10 保留节点完成事件定义，E11 要求四阶段制品 ID 串接一致，故这里不是把不同制品或不同尝试中的事件拼成一条路径。

令 $a\prec b$ 表示配置规定的阶段完成前置关系。父任务要求 $\text{EV-REVIEW}\prec\text{EV-SIGN}$、$\text{EV-SIGN}\prec\text{EV-PUSH}$；DEV 提供三条相邻边，OPS 所有入口加载该模板，QA 核对同一配置中各路径的事件生产者及制品摘要（E10、E11、E14、E19）。因此关系保存了入口、模板、事件及制品之间的共同绑定，而不是仅比较 review、sign 等孤立字符串。

## 四、数学计算一

核对顺序约束应使用前置图，而不是把所有记录、交接关系都改成执行前置。

先定义：

$$D=\{(r,x),(x,s),(s,u)\},\qquad R=\{(r,s),(s,u)\}.$$

其中 $r,x,s,u$ 分别对应 EV-REVIEW、EV-SCAN、EV-SIGN、EV-PUSH。符合条件为：

$$R\subseteq D^+,$$

$D^+$ 是前置边的传递闭包。代入 E10 的具体图，存在 $r\to x\to s$，故 $(r,s)\in D^+$；另有直接边 $s\to u$，故 $(s,u)\in D^+$。因此父任务的两个前置关系均被保留，增加 scan 没有把签包移到审阅之前。

此结果不依赖实际日志或运行成功，也不依赖标题中的“扫描”。其必要绑定来自正文：所有入口统一模板、节点完成事件保留、跨阶段制品 ID 一致（E10、E11）。

## 五、数学计算二

其余文字边界用任务规则蕴含核对。父规则投影为：

$$P=c\land i\land\neg p\land w\land a\land m\land t\land f.$$

定义联合子任务规则：

$$S=d\land o\land q\land\neg p\land w\land a\land m\land t\land f\land(d\Rightarrow c)\land(o\Rightarrow i).$$

这里 $d\Rightarrow c$ 来自 DEV 交接配置与统一模板的具体方案（E10—E12）；“源码或配置”不能取消 E10 已明确承担的配置修改。$o\Rightarrow i$ 来自 OPS 明确规划的隔离模板运行及成功、失败测试（E14—E16）。$q$ 对应 QA 的枚举、路径表及独立检查（E18—E20），属于新增检查义务，未要求生产发布或取消父约束。

$\neg p,w,a,m,t,f$ 是未被子任务改写的适用父规则投影，分别由 E3、E4、E5、E8、E7、E1 继承。不能仅由“不配置生产凭据”推出禁止生产发布，也不能仅由“定义失败状态”推出失败必停；这两条禁限的效力来自父规则继续适用。

求证公式为：

$$S\Rightarrow P.$$

假设 $S$ 成立，则由 $d$ 与 $d\Rightarrow c$ 得 $c$，由 $o$ 与 $o\Rightarrow i$ 得 $i$；其余六项是继承条款，因此 $P$ 的八个合取项全部成立。K2 预期 VERIFIED。它验证的是新增交付安排与继承限制共同构成的任务书，不以未来交付成功为操作数。

反例检查：若子任务写成允许失败后仍签包推送，则可令 $f=false$，形成违反见证；若把 push 固定为生产发布，则 $p=true$ 与 $\neg p$ 冲突。本例没有这两类文字，不能自行补入。OPS 记录失败日志和 DEV 另存失败原因只增加诊断产物，不要求继续原流水线。

## 六、关键区别与可满足性

父任务允许增加扫描，但不强制必须扫描；DEV 选择该许可之后，扫描成为本子方案中的具体节点要求。这是缩小可选方案空间，不是突破父边界。父任务的审阅完成前置也不是整个任务的完成条件。

父规则可满足。取一个允许的隔离配置方案，其阶段顺序为 review、sign、push，并规定任一阶段失败即停止后续流水线；交付配置和隔离测试，使用指定工作区，按角色和尝试编号存放，PM 协调依赖与返工，本轮不附已运行结果，不发布生产制品。这一文字方案满足父规则，不需要将任何标题解释为额外义务。

父规则加固定子方案也可满足：将阶段顺序细化为 review、scan、sign、push；所有入口加载同一模板，每条路径使用一致的制品身份；成功分支允许后继阶段，扫描非零退出分支停止后继阶段，同时保存诊断日志和失败原因；OPS 在隔离环境规划两类测试，QA 规划检查配置与未来产生的记录。各阶段失败停止与失败诊断可以同时成立。

就 K2 的命题投影，取 $c=i=w=a=m=t=f=d=o=q=true$、$p=false$，可使 $S$ 与 $P$ 同时成立。这个赋值只是任务要求的可满足见证，不是现实运行状态。图中的线性顺序同时满足 K1，因此联合子方案不存在由这些条款导致的冲突。

“实际执行后填写”保留了未来动作的时态，不要求在本轮凭空提交回执；QA 标记未观测分支也不是自动豁免父约束。不存在需要用执行记录补齐的任务书未知。这里不推出系统零故障、所有运行必成功或未来一定交付。
