# draft.2 配套合同的地位

四个 JSON 文件固定基础载体、阶段索引、状态归约及求值／评估分离的评审内容，均受[规范正文](../BXP-0001.md)约束。协议版本仍为 `0.4.0-draft.2`，本次文件修订为 `2026-10-27-r2`。

它们**不是任务或结果的 wire Schema**，也没有注册到现有 Core。基础载体 Profile 不含发布政策；四种专用阶段政策仍需在本版协议审阅后独立设计、版本化与验证。原 draft.1 配套文件继续保持原版本及原字节。

- `org.boundx.core-7plus1.json`：八类原定义、完整载体的抽象分量和结构／必需信息分离。
- `PROFILE-FAMILY.json`：沿用五个 Profile ID，以精确协议版本及内容身份区分修订；五者不互为别名。
- `STATUS-REDUCTION-RULES.json`：条目到视图的归约、未完成前提和不可混用的后续状态。
- `EVALUATION-ASSESSMENT-CONTRACT.json`：精确查询清单、数学内容 E、固定上下文 Θ、整体结果 B、摘要与重放以及环境／因果声明范围。

下游比较的适用要求统一定义在求值／评估合同的 `comparison` 中，阶段索引引用该处。所有比较声明对象种类、观察范围、身份映射、完整性假设与边界基准，再仅使用对应对象的要求：具体实现检查事实与观察充分性；部分观察检查合法补全和结论范围；候选规格检查沉默解释、承诺环境、逐情境可满足性、关系保持及因果声明范围。父环境绑定只适用于候选规格的委派／精化比较；只有声明运行时因果可实现性或发布政策要求它时，才要求策略合同与证据。各类要求不能合并成所有比较通用的清单。

未完成归约的视图现在必须省略状态字段，另存归约元数据；不再用旧描述中的 `status: null` 示意。此前版本完整保存在历史归档中。

实现下一阶段至少还应固定：关联与来源的 wire 编码、各阶段输入输出 Schema、解释范围依据、形式化和算子 Profile、证据验证合同、比较结果映射，以及宿主发布条件。缺少这些资产时，只能审阅本规范，不能声明新版本运行符合性。
