## 两种见证时间不同，结果不冲突

MD第9.1节给出的人工安排T=16分钟；程序给出T=30分钟。程序任务起止点之差也是30，不再将窗口上限冒充实际见证耗时。两个值均属于[0,30]。原文没有指定逐动作耗时，人工表是一个满足见证，不是唯一执行计划。此差异不应判FAIL，也不能称工期预测。

## 发现的局部公式问题

MD第六节要求：`StartGenerateSummary(t) ⇒ Q_passed(t)`；交付同理。必要前提自身不新增无条件QA成功义务。

LLM候选中`r_summary_generation_gate`的subject是生成事件，body是TRUE_AT_START，applicability=null。消费者`direct-ir-calculate.mjs:122`将此CONSTRAINT编译为：

```text
true ⇒ local_passed_at_generation
local_passed_at_generation ⇒ review_passed
```

没有保留该局部门的动作激活保护。对这一门及其STATE链接做独立小模型检查，固定“生成未发生、QA未通过”，应满足`G⇒Q`的局部限制，程序却返回unsatisfiable。这证明局部门表达较MD必要条件更强。

这是局部公式等价性对照，不宣称“全任务要求都已履行而QA可以不通过”。全任务还有独立生成和交付义务，必须分开评价。初步整模型查询的预期不适合证明局部缺陷，已保存在PRELIMINARY-QUERY-RESULTS.json并由上述隔离查询替代，未修改或重写原始运行。
