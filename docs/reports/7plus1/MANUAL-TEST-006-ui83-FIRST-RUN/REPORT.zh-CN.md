## 3. 确认的根因与修复位置

### A. 合同交付与审阅状态：宿主程序

实际Skill要求同版CONTRACT.md，资源实际交付SEMANTICS.md、注册表和Schema；适配器只替换版本字符串，没有把完整合同和引用要求同步。审阅明确报告未作节点语义裁定。

程序仍把资源错误送到模型局部修订，消耗21.707秒得到空补丁。资源错误应由宿主在调用前检查；无法审阅应标AUDIT_BLOCKED，不能用空reviews/omissions代表无问题，也不能让模型修改候选去修宿主缺文件。

局部修订还报告未交付明确声明的传输Schema；应统一请求资源名称、内容、版本、摘要与实际Schema交付证据，不用重命名文件掩盖合同内容不完整。

### B. 固定对象变量未约束查询角色：程序真正的计算/验证缺陷

源IR明确用TASK_FIXED file贯穿生成、QA复核、交付和收件。在有限查询中设置file=accept，同时让review的OBJECT为reject，应当诊断身份冲突或得到UNSAT。

实际preparePlan仅强制核对角色中静态ENTITY/EVENT引用，跳过VARIABLE引用。后续编译和Core见证复核也没有补回变量实参一致性，于是错误安排被返回SAT / MODEL_CHECKED。

**修复必须是通用的变量实参绑定。** 静态对象、TASK_FIXED变量、实例局部变量及符号对象选择都须按对应绑定环境比较事件角色；不能只检查文件名或为006加特殊条件。编译器与独立模型复核都须覆盖该不变量。

### C. 必要条件没有覆盖相关动作：LLM候选与合同约束绑定

候选只在select上放了双结果形成的门。generate没有同等开始门，条件使用最终状态any_pass/both_fail，而不是相应时点已形成的结果。

通用修复是让条件有明确的受限动作、求值时点和对象域；在解析/审阅中检查同一分支下受该前提约束的动作是否完整。不由程序扫描“结果均已形成”等原文补答案。程序只能对IR已经声明的约束执行计算。

### D. 数量目标不一致：输出合同与LLM生成

“完成一份分支产物”被落成COUNT_STARTED(分支生成事件)=1。这个算子计算启动次数本身没有算错，但目标不是完整产物数。

需要统一开始次数、完成次数、不同产物身份数量和完整可用结果的表达。生成义务的完成/产物就绪与数量目标应相互绑定，审阅必须核对计数对象，不能拿启动成功替代完整产出。

### E. 已知false的时点门：程序三值求值缺陷

同版evaluateCore的TRUE_AT_START先要求建立时间非空，再检查状态值。已知value=false而建立时间未知时，返回UNKNOWN；“状态为真且时间满足”应按三值合取返回false。

同版SAT编译中的AND已经可以false短路，EVALUATE却不同。应统一求值、编译、见证检查的逻辑语义。这是额外无模型反例发现，**不是本次原始OPEN_EVENT_DOMAIN的直接原因**。

### F. 整案查询接线与有限域支持：程序入口

原始UI的默认全约束SAT未传有限完整查询域，TASK_EVENTS开放；环境、禁止、分支唯一性等全称规则不能在当前有限求解profile中枚举，所以进入Z3前停止。

必须区分开放规则、显式有限规划/诊断查询及可独立计算子问题。有限快照只可作为查询假设，不能由节点清单或“最多一次”自动充当完整真实域。部分结果标明覆盖范围，完整结论保留缺口。

### G. 合同表达与7+1投影：同版合同、Skill和消费者

原IR自己承认校验动作类别/实例计数、形成前未知及结果冻结规则不足，需要通用类别/实例与时间化状态合同，不能穷举每个业务动作名。

此外r_outcomes、r_review、r_no_forced_pass、du_review被放进V；V应是规范依据，QA复核和业务状态约束不能仅因“检查”就成为制度依据。程序投影沿用了候选views，同版模型资源却缺完整7+1定义。正常UNSPECIFIED也被normalize统一记为语义缺口。应同步维度定义、结构可确定的归槽一致性检查与诊断分类。

## 4. 无模型反例证据怎样判读

直接使用最终IR和58618实际安装的ui83 Core，不改模型响应。12项局部检查中11项得到预列值，1项发现程序false门错误；其中若干预列值是缺陷复现，不是PASS。

另做5个**显式有限诊断查询**，全部包含原IR全部要求。给定完整构造快照是查询假设，不是从原文推导现实没有其他事件，也不替换原始运行结果：

1. 先修**完整同版合同交付、资源预检及审阅阻断状态**，停止把宿主资源问题发送给语义修订模型。

3. 同步合同/Schema/Skill里的**时点条件作用域、完成产物数量目标、同一对象与7+1维度**；这些模型可见资源改变后须另记版本，再真实验证。
4. 补齐通用**动作类别/实例范围、结果形成与冻结**表达及对应计算，不写校验专用规则。
5. 接通**有限查询与分项结果展示**，不能让一个开放域阻断掩盖已有可算部分，也不能因此宣称完整全域证明。
