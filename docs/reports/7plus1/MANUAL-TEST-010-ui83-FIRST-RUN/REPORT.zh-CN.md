## 3. 直接使用最终IR的数学核查

```text

a≠b                    ——r_distinct
read_a、read_b必须发生  ——r_read_a、r_read_b
任何READ命中y/z不得发生 ——r_read_ban
```

只在源文必须发生的两个读取事件上实例化禁令，就得到必要条件：

```text

⇒ a=x且b=x
⇒ 与a≠b矛盾。
```

同版Core/Z3诊断查询返回UNSAT / BACKEND_RESULT。冲突核包含两个变量域断言、r_distinct、r_read_ban。独立遍历两个三成员域的9个有序赋值，通过同版表达式求值检查different与ban，满足数0。

诊断去掉different要求后SAT，去掉read_ban后SAT。只是数学对照，不修改ADMIN原文或原测试成绩。没有测试移除变量域，不声称自动求得全局最小冲突核。

## 4. 确认的问题与修复位置

### 4.1 同版合同交付和资源错误处理

与006、008相同：Skill要求CONTRACT.md，实际只交付SEMANTICS.md及注册表/Schema，审阅返回0条裁定。宿主又发送局部修订去处理资源缺文件，23.980秒得到空补丁。

资源缺失须在模型启动前处理，不把它送去语义修订。完整合同还须包含算子具名参数、7+1定义、要求种类的跨字段条件与查询支持范围。

审阅另声称“系统响应Schema未声明format”。实际提交的`revision-0/audit-call/output-schema-0.json`包含format字段，并将其列为必填。服务端有效Schema未回显，因此不能把模型的额外指控当成已证实的传输缺陷；此处只确认本地实际提交内容。

### 4.2 TOTAL_DURATION接口错误没有被技术层发现

最终要求：

```text
kind=TOTAL_DURATION
subject=EVENT:task       ——错误
body=MEMBER(duration,[5,10]分钟)
```

应引用VARIABLE:duration，scope_id保留根任务。加载/绑定检查接受了这一结构，technical_errors为空；单独查询r_duration才返回DURATION_VARIABLE_REQUIRED。完整查询先遇到开放域，把后面的结构错误遮住。

这是LLM输出不符合合同、技术层漏检的组合问题。应在统一技术校验阶段检查kind对应的subject类型与根任务/变量关联，再按有界修订反馈；不能由程序扫描“整体耗时”补答案，也不能把接口误用笼统记成求解器能力不足。

### 4.3 整案入口不能因开放域漏掉已可证明的矛盾

当前默认全约束SAT按顺序构建，先在全局FORALL遇到开放域，直接返回NOT_RUN。它没有提取可验证的有限必要约束并计算冲突。

通用改进应保留开放规则与能力诊断，允许独立子问题给出操作数、来源、证明范围和冲突；只有证明必要约束本身无解时，才能说明保持这些约束的完整模型也无解。不能把任意子集SAT升级成全局SAT，也不能把事件节点清单自动关闭成完整现实域。

### 4.4 “未发生”门缺失

no_third使用DEV+READ类型匹配，没有结合EVENT_OCCURRED。构造一个occurred=false、目标为未选z的候选事件，该表达式仍false；未实际读第三份却被判违反。

这个反例只检查该规则，不是解除本案真实读取冲突。应统一操作边界的匹配域与发生门，解析/审阅核对条件作用域；程序按结构计算，不扫描“不得读取”等原文猜门。

### 4.5 7+1归槽及封闭使用接口

read_ban、modify_ban、access_ban被标为V，而V是约束性依据，它们应保留独立B边界；总期限却被标B，未体现R量化目标。缺完整维度定义使模型归槽漂移，程序投影直接沿用views。

“仅依据已经读取的文件”还需通用的消费者输入集合/封闭用途关系，不能因为已列a/b两个角色就证明没有其他依据。它不影响已证明的必要读取矛盾，但仍是全文覆盖缺口。
