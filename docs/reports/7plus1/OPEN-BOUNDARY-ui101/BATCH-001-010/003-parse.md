## I｜输入与作用域

- **任务范围**：在现有测试仓库内开发 Python 3.11 离线配置核验 CLI；只有一个根任务，各章节不是独立工作包。全部开发、测试、报告及交付均限测试环境，向 QA、PM、ADMIN 提交均为受控交付。除终止分支外，开发、复核、交付义务全部保留。〔“只有一个根任务”“仅在测试环境进行”“除第九节规定的终止分支外，必须完成”〕
- **外部仓库资料仅五份**：`src/configcheck.py`、`tests/test_configcheck.py`、`README.md` 为目标文件；`fixtures/valid.json`、`fixtures/invalid.json` 为只读验收输入。任务要求、已安装运行时与标准库不计入五份；新报告和临时测试数据是内部产物。〔“允许读取的外部仓库资料仅有五份”“不是新增外部资料”〕
- **固定输入内容**：合法输入为 `{"service":"demo","port":8080}`；非法输入为 `{"service":"demo","port":"8080"}`。两份均不得修改、删除或覆盖。〔“内容为……”“不得修改、删除或覆盖这两份输入”〕
- **路径须核实身份**：所有路径相对测试仓库根目录；执行前核实归属，符号链接、别名或身份不明不能仅凭字符串不同判定合法。四份报告及设计说明起初均不存在。〔“给出的文件各有独立身份”“执行前须核实路径归属”〕
- **调用与任务范围分离**：工具每次只读 `--input` 指定的一个 UTF-8 JSON 业务文件；该限制不意味着团队只能读取一个文件，也不是整体任务完成条件。读取标准库不计额外业务文件。〔“约束被开发工具的每次调用”“不是整个开发任务的完成条件”〕

## A｜动作与功能合同

入口为 `python src/configcheck.py --input <输入路径> --output <输出路径>`。〔“工具入口为……”〕

### 配置验证

| 对象或条件 | 必须行为 | 原文依据 |
|---|---|---|
| JSON 根 | 必须为对象；非对象时错误列表只能是 `["ROOT_NOT_OBJECT"]` | “错误列表仅包含ROOT_NOT_OBJECT” |
| 字段集合 | 恰为 `service`、`port`；存在额外字段记 `EXTRA_FIELDS` | “字段恰为service和port” |
| `service` | 字符串，去除首尾空白后非空；缺失或不合法记 `SERVICE_INVALID` | “去除首尾空白后非空的字符串” |
| `port` | JSON 解析后为整数，`1 ≤ port ≤ 65535`，拒绝布尔值、浮点数；缺失或不合法记 `PORT_INVALID` | “包含两端，不接受布尔值或浮点数” |
| 错误汇集 | 根为对象时各项独立检查；同类一次、多类同时保留、按字典序排列 | “同类错误只记一次，多类错误同时保留” |
| 输入保持 | 不用默认值补缺，不自动修改输入 | “不以默认值补齐缺失字段” |

### 输出与退出

| 调用条件 | 输出、诊断与退出码 | 原文依据 |
|---|---|---|
| 输出路径不存在，输入可读且 UTF-8、JSON 语法有效 | 必须向指定新文件写 JSON 对象，字段仅 `valid`、`errors`；`errors` 为错误码数组，`valid ⇔ errors为空`；真返回 `0`，假返回 `2` | “必须……写入一个JSON对象”“valid当且仅当errors为空” |
| 输入不可读、UTF-8 解码失败、JSON 语法错误，或输出路径已存在 | 返回 `3`；标准错误非空诊断；不新建、不覆盖指定输出文件 | “退出码为3……不新建或覆盖指定输出文件” |
| 输出写入或其他文件系统操作失败 | 返回 `3` 并报告诊断，不伪报成功 | “也返回3并报告诊断，不伪报成功” |

语义不合法但语法有效的输入仍须生成结果文件并返回 `2`，不能与 JSON 语法错误的 `3` 混同。工具不得写输入、覆盖已有输出、读其他业务文件或联网。所有测试调用的输出和临时输入必须在调用角色自己的临时目录。〔“工具不写输入、不覆盖已有输出”“均必须位于调用角色自己的临时目录”〕

### 开发、检查与测试

- OPS 检查已提供的 Python 版本、测试环境、命令可用性；DEV 完成目标文件及自动测试。〔“OPS检查已提供的Python版本、测试环境和命令可用性”〕
- 自动测试至少六项，必须覆盖给定合法配置、`port` 为字符串、`service` 为空字符串、额外字段、根为数组、JSON 语法错误。除两份给定输入外，其余测试输入由测试在本角色临时目录生成，不得修改冻结输入造反例。〔“至少六项，并必须覆盖”“不能更改冻结输入来制造反例”〕
- 统一测试命令为 `python -B -m unittest discover -s tests -v`；DEV 测试失败时，只能在冻结前、原写入范围及剩余预算内调整，不能删掉必需场景。〔“只可在第六节冻结前、原写入范围和剩余预算内调整”〕

## P｜参与、组织与接收关系

- **PM 组织 DEV、OPS、QA**；OPS 检查与 DEV 开发可并行，无强制先后。〔“由PM组织DEV、OPS和QA”“二者没有强制先后”〕
- **QA 复核前置条件**：完整收到 DEV、OPS 两份报告后才可开始；必须读取两报告和三个冻结文件，执行规定的一次测试，检查全部功能、范围及证据，真实给出结论。〔“均完整收到后才开始复核”“不得为了完成任务伪造通过”〕
- **PM 汇总前置条件**：QA 对本次冻结版本通过，且 PM 已收到本次 QA 报告，才可开始生成汇总；正常分支必须生成。使用内部报告不使其变成外部资料，也不要求 PM 重新生成代码文件。〔“只有……PM才能开始生成”“不要求PM重新生成三个代码交付文件”〕
- **接收链**：OPS、DEV → QA；QA → PM；PM → ADMIN。最终成功以 ADMIN 实际收到规定文件为条件，仅发送不足。〔“提交QA”“提交PM”“ADMIN已收到”〕

### 测试累计预算

令 \(d,q\) 分别为 DEV、QA 启动统一测试命令的次数：

\[
0\le d\le3,\qquad d+q\le3；
\quad 正常分支\ q=1\Rightarrow 0\le d\le2。
\]

次数为非负整数；OPS、PM 启动次数必须为零。每次启动都计数，失败、重启不清零；至少六个测试方法与最多三次命令启动分别计数。DEV 若已启动三次，就不再有预算完成正常分支必需的 QA 一次测试。终止分支可解除尚未执行的 QA 测试义务，但不重置已用预算。〔“整个任务中DEV与QA合计最多三次”“每次启动都计数”“至少六个测试方法与最多三次命令启动是不同计数”〕

### 时间边界

- 正常分支整体经过时间：
  \[
  0<t_{\text{ADMIN收到最后一份最终交付}}-t_{\text{PM开始组织}}\le90\text{分钟}。
  \]
  包含 90 分钟端点，不可按角色或操作分别分配 90 分钟；选做设计说明也须在正常完成前结束。〔“整体经过时间”“不得把90分钟分别分配”〕
- 终止通知：
  \[
  0<t_{\text{PM完成发送终止说明}}-t_{\text{终止}}\le2\text{分钟}。
  \]
  包含 2 分钟端点，独立计算，不套用正常分支的 90 分钟。〔“终止时点之后、大于0且不超过2分钟”“单独计算”〕

## C｜完成、终止与后续条件

**原文成功判定**为以下条件同时成立：

\[
QA通过本次冻结版本
\land ADMIN收到三个目标文件的同一冻结版本
\land ADMIN收到本次汇总
\land 本任务未终止。
\]

测试数量、启动预算、写入范围、时间及其他独立约束仍须满足；完成公式成立不能掩盖违规。〔“当且仅当……任务成功完成”“完成公式成立不掩盖其他约束违反”〕

**终止触发为二选一**：

1. 任一角色确认存在可能导致越权写入、生产访问或数据外泄的高危风险；
2. QA 报告已完成并明确给出不通过结论。

无须等风险实际造成损害；QA 单次测试失败本身也不等同于“QA 报告完成且不通过”。〔“确认存在可能导致……的高危风险”“QA报告完成并明确给出不通过结论”〕

**进入终止后**：

- 状态不可撤销，不得自动恢复或重试整个任务；未完成的正常开发、测试、复核、汇总、最终交付义务解除，且禁止继续这些活动，不能标成已完成。〔“终止状态不能在本任务内撤销”“禁止继续这些正常活动”〕
- 只允许受控停止本任务进程、QA 将已经生成的复核报告提交 PM（如有）、PM 读取已有证据并向 ADMIN 发送终止说明；PM 必须满足上述两分钟时限。〔“终止后只允许……”〕
- 终止不算成功，不得删除历史、扩大写入范围、执行修复性生产操作或取得任务外授权。〔“终止不是成功完成”“任何执行授权”〕
