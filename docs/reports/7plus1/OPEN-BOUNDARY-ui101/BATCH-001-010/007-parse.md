### I｜输入与作用域

- 外部输入仅为 `spec.md` 和 `report.md` 的给定只读初始快照 r0；不得将其他材料扩为外部输入。r0 无需另建备份文件。〔“外部输入仅……给定只读初始快照r0”“r0不是要求另建的备份文件”〕
- r1、r2 是同一逻辑文件 `report.md` 的新版本，各自与 r0 身份不同。〔“均为同一逻辑文件report.md的新版本，与r0身份不同”〕
- 全部操作限测试环境。〔“全部操作限测试环境”〕

### O｜产物与交付

- DEV 必须形成 r1 并提交 QA；是否形成 r2 取决于 r1 的复核结论，不能预先选定。〔“形成r1并提交QA”“若r1……不通过……形成r2”〕
- 最终版本 F：
  - 未产生 r2：F＝r1。
  - 已产生 r2：F＝r2，不得回退选 r1 作为最终版本。〔“最终版本在未产生r2时为r1，产生r2后为r2”〕
- PM 必须向 ADMIN 交付 F；唯一明确的交付义务取消条件是 r2 复核不通过，此时 PM 必须向 ADMIN 报告失败，且不交付 r2。〔“PM必须完成……交付最终版本”“若r2……不通过，则取消本任务交付义务……报告失败，不交付该版本”〕

### P｜参与关系

- **PM**：组织修订，向 ADMIN 交付最终版本；触发失败分支时向 ADMIN 报告失败。〔“PM组织修订”“PM必须完成……交付”“由PM向ADMIN报告失败”〕
- **DEV**：承担版本形成、条件性再次修订及向 QA 提交的义务；**QA**：接收相应版本后复核；**ADMIN**：最终版本或失败报告的接收方。〔见 A、O 对应引文〕
- **OPS**：历史发布许可仅为背景，本任务不继承，不构成本次授权。〔“历史记录‘OPS可发布report.md’仅作背景，本任务不继承该许可”〕

### R｜数量与时间范围

- 新版本数为 **1 或 2**：r1 必须形成；r1 不通过时必须追加且仅追加 r2。禁止 r3 及后续版本。〔“形成r1”“再修订恰一次形成r2”“禁止产生r3及后续版本”〕

### V｜版本与依据

- 本任务依据《版本复核规程》**v1.0**；原文未提供规程正文，不能据标题补充要求。〔“依据《版本复核规程》v1.0”〕
- r1 的形成依据必须同时包括 `spec.md` 与 r0；r2 是 r1 不通过后的再次修订产物。〔见 A 对应引文〕
- QA 通过结论仅对被审的同一版本有效，任何其他版本均不得继承。交付前通过的版本、最终版本及 ADMIN 完整收到的版本必须一致。〔“每次QA通过只对被审的同一版本有效，其他版本不得继承”“ADMIN完整收到同一版本”〕

### C｜完成与失败条件

- **任务完成，当且仅当：F 已通过 QA，且 ADMIN 已完整收到同一版本 F。** 仅通过、仅发出或部分收到均不满足完成条件。〔“当且仅当最终版本通过且ADMIN完整收到同一版本，任务完成”〕
- r2 不通过时，必须转为失败报告分支，取消交付义务并禁止交付 r2；报告失败不等于满足上述“任务完成”条件。不得继续形成 r3 补救。〔“取消本任务交付义务……报告失败，不交付该版本”“禁止产生r3及后续版本”〕
- 原文未规定额外升级流程或超时处置；40 分钟上限仍须遵守。QA 的未来结论尚未知属于条件分支，非边界歧义。
