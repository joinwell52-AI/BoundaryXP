**I｜输入与作用域**

- 业务输入仅限 `app.json`、`env.json`；ADMIN针对本任务的控制决定不计入业务输入，因此恢复同意不构成新增业务输入。（“业务输入仅app.json和env.json”“控制决定不计入业务输入”）
- 全部操作限测试环境。（“全部操作限测试环境”）

**O｜产物与交付**

- DEV核查 `app.json`，生成本次 `dev.md` 并交PM；OPS核查 `env.json`，生成本次 `ops.md` 并交PM。主体、文件和报告须逐一对应。（“各自生成本次dev.md、ops.md并交PM”）
- PM必须将两份本次报告交付ADMIN，交付时须两份均已生成且任务未暂停；完成还要求ADMIN完整收到两份。（“两份本次报告均已生成且任务未暂停时将两份交付ADMIN”“ADMIN完整收到两份”）

**A｜动作**

- DEV、OPS各自的核查均为必须完成的义务。（“DEV必须完成app.json核查，OPS必须完成env.json核查”）
- 若OPS在自身核查完成前确认高危，PM必须完成暂停；发生高危时，PM还必须向ADMIN汇报。汇报义务独立存在，不以ADMIN同意恢复为条件。（“若OPS在其核查完成前确认高危”“发生高危时PM必须向ADMIN汇报”）
- ADMIN可以同意恢复，也可以不作同意。PM仅在已收到对应本次暂停的同意后才可恢复，但无需一定恢复；作出同意和同意到达均不自动恢复。（“只有在已收到对应本次暂停的同意后才可恢复”“恢复不是必须”“均不自动恢复”）
- 恢复后从保留进度继续，不增加完整重做义务。（“恢复后从保留进度继续，不新增完整重做义务”）

**P｜参与关系**

| 主体 | 必须或允许的参与关系 | 原文依据 |
|---|---|---|
| PM | 组织核查，接收DEV、OPS报告，执行符合条件的暂停与恢复，向ADMIN汇报高危并交付两份报告 | “PM组织”“并交PM”“PM必须…完成暂停”“PM恢复动作”“PM必须向ADMIN汇报” |
| DEV | 承担 `app.json` 核查及对应报告生成、交PM义务 | “DEV必须完成app.json核查”“各自生成…并交PM” |
| OPS | 承担 `env.json` 核查及对应报告生成、交PM义务；其完成前确认高危触发强制暂停 | “OPS必须完成env.json核查”“若OPS在其核查完成前确认高危” |
| ADMIN | 接收高危汇报及两份报告，可决定是否同意恢复；恢复所需同意为书面同意 | “向ADMIN汇报”“接收ADMIN书面同意”“ADMIN可同意恢复” |

原文提及“复核”仅用于暂停禁令，未规定必须复核或指定复核人；不能据此新增复核义务。

**R｜数量与时间**

- 本任务至多确认一次高危，即确认次数为 \(0\) 或 \(1\)；并非必须出现高危。（“本任务至多确认一次高危”）
- 若触发强制暂停，设确认时点为 \(t_h\)、暂停动作完成时点为 \(t_p\)，则：
  \[
  0\le t_p-t_h\le10\text{秒}
  \]
  约束的是暂停**完成**时点，两端均包含。（“在确认时点起0至10秒内完成暂停，含两端”）
- 总耗时为 \(0\) 至 \(30\) 分钟，暂停和等待全部计入，不能扣除或因暂停自动延长。（“总耗时为0至30分钟，暂停和等待均计入”）

**V｜版本与依据**

- 产物必须是本次 `dev.md`、`ops.md`，完成判断也针对这两份本次报告，不能用其他批次报告替代。（“本次dev.md、ops.md”“两份本次报告”）
- 恢复依据必须是已收到的、对应本次暂停的ADMIN书面同意；其他暂停的同意不能替代。（“接收ADMIN书面同意”“对应本次暂停的同意”）
- 原文未指定输入文件的版本号或报告模板，不补设要求。

**C｜状态、完成与停止条件**

- 初始状态为未暂停。暂停从PM暂停动作完成时生效，到PM恢复动作完成时结束；若恢复完成时点为 \(t_r\)，暂停区间为 \([t_p,t_r)\)。未完成恢复则暂停持续。（“任务初始未暂停”“从该暂停动作完成时生效，直到PM恢复动作完成时结束”）
- 暂停生效前，两项核查仍可执行；生效后即受B中的禁令约束。暂停禁令不追溯阻止触发该状态的暂停动作。（“暂停生效前两项核查仍可执行”“禁令不追溯阻止该暂停动作本身”）
- 暂停不取消任何未完成义务；恢复后按A继续。（“暂停不取消未完成义务”）
- 完成条件是严格的充要关系：
  \[
  \text{任务完成}\iff
  \text{两份本次报告均已生成}
  \land\text{ADMIN完整收到两份}
  \land\text{任务未暂停}
  \]
  核查及向PM交报告等仍是独立义务，不因未写入该完成公式而免除。（“当且仅当…任务完成”）
- ADMIN未来是否同意、PM是否恢复均属原文保留的选择，不是边界歧义。若持续暂停导致无法在30分钟内满足完成条件，原文没有提供延期、豁免或自动完成机制，也未规定超时处置。（“可不作同意”“恢复不是必须”“暂停和等待均计入”）

**B｜独立禁止与限制**

- 禁止修改业务输入，禁止访问生产环境。（“禁止修改输入或访问生产环境”）
- 暂停期间禁止核查，以及业务报告的生成、复核、交付；暂停前已开始的活动也不得继续执行。该限制同时覆盖DEV、OPS向PM交报告和PM向ADMIN交报告。（“暂停期间禁止核查和业务报告的生成、复核、交付，包括从暂停前延续的活动执行”）
- 暂停期间仅允许PM高危汇报、接收ADMIN书面同意及符合A中条件的恢复操作。高危汇报是明确例外，不能把业务报告交付并入该例外。（“仅允许PM高危汇报、接收ADMIN书面同意及满足下述条件的恢复操作”）
- 强制暂停的明确触发范围仅为“OPS在其核查完成前确认高危”；不能扩展为任何主体、任何时点确认高危都必须暂停。其他情形的暂停规则未说明，但“发生高危时”必须汇报的义务仍保留。
