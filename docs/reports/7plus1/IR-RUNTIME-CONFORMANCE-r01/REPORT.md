## 已实现

- 同一事件模式分类供静态求解和实际观测使用。明确的TASK_SCOPE禁止对所有匹配事件生效；EXPLICIT ACTION仍限定具体身份。条件按匹配实例时点求值，未知作用域不默认空域，不把未违反当成许可。
- 静态模式检查按每个已构造实例建立约束；操作、对象、角色和范围均参与。观测端更换event_id不会绕开全称禁止，同时保留对象、接收者、任务范围的反例。
- 重复角色值作为并列成员保留。构造见证不再用Object.fromEntries覆盖多个接收者；观测消费核对全部接收者。模式字段允许额外成员存在，包含被禁止对象的复合交付仍命中禁止。
- 观测端补齐集合并交差、有限整数/集合量化、事件实例与前次实例求值、布尔等值及零值绑定；GROUP_MEMBERS采用直接成员含义，与静态集合消费一致。
- 静态集合运算保留条件成员的布尔激活；CARDINALITY对实际激活的不同成员计数，并对常量真假条件化简，避免把静态差集误判为动态域。
- 校验器遇到跨类型重复ID输出技术诊断，不再因取错节点类型而崩溃。
- 局部修订权限通过审阅目标身份与来源关联到issue节点，并在请求前提供允许替换清单；不取消无关修改保护，修订后仍需独立审阅。
- 运算实现清单与Schema枚举必须一致；新增运算未登记时资源构建失败。修复资源生成脚本写回ui65旧状态的问题，提供`--check`防漂移。
- 事件查询复用观测表达式解释器，删除独立的小型运算语法；条件、模态、集合及嵌套量词均走同一消费路径。
- 实例状态通过显式`state_instances`按状态和事件身份绑定，独立尝试不再混用；状态成立时点仍独立核查。
- BEFORE的真假两侧都进入时间约束；否定BEFORE不能丢掉反向关系。布尔EQ可组合任意布尔谓词。
- 首次尝试的明确保护条件可以排除不存在的前次实例；OR参数次序不改变结果。无保护的越界仍保留诊断。
- ADD使用Core的精确十进制运算，保留中间值；0.1+0.2、科学记数法及大数抵消有独立预期检查。
- 实数单变量比较可嵌套在条件、否定与析取中。联合求解采用带条件的区间交集，每个见证再独立检查选中的上下界；未把不相交区间合并成更宽的允许域。
- 缺少匹配信息的可选动作允许在构造见证中不发生，作为明确的见证分支选择保存；其发生分支仍列入`conditional_gaps`并在页面明示。若该动作必须发生则保持PARTIAL，不用未决分支证明全域结论。
