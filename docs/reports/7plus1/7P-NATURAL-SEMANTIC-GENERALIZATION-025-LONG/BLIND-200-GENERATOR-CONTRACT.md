# Blind-200 generator contract — frozen before runtime tuning

Abstract frames are the authority for this generated evaluation. The generator has no Parser imports, output access or fixture lookup. It constructs entities, events, modal/role edges, conditions, quantity targets, output-content ownership and ambiguity alternatives first, then independently realizes source text. Expected boundary semantics are those frame relations, not display strings or inferred Parser answers.

There are 200 positions: 80 Chinese, 60 English, 60 mixed. Ten construction families rotate across positions; family 9 contains exactly 20 genuine ambiguities (8/6/6 by language). Families include coordinated checks, passive obligations, approval gates, conditional output and exemption, quantified completion, output content, negative participant roles, closed/excluded scope, negative nominal/passive modality and source ambiguity. Lexical choices, entity names, filenames, numeric values, connectors and ordering are seeded independently. All tasks retain an organization/actor relationship; at least 40 cases cover each additional required mechanism category. Coverage is counted from frame features, not labels attached merely to achieve quotas.

Ambiguity families alternate unresolved artifact reference, competing basis version and explicitly unspecified ANY versus ALL approval. Alternatives and reasons are frame properties. Clear facts surrounding an ambiguity remain required.

The exact 200 frames are not generated now. After all development gates pass, the seed is SHA256("BOUNDX-025-BLIND-200" + implementation tree SHA256 + generator SHA256). Source, frames and expected relations are sealed before the one Parser run. No generator/runtime changes are permitted after holdout observation. This is a generative holdout, not independent human Gold.

Validation of the generator uses small unmaterialized frame/realizer units and static distribution checks. No final seeded 200 is accessible to development.
