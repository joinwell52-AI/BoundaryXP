# 017：从原文中的动作关系得到 7+1

本轮将**读取、生成、发送、执行者、接收人、审批者和条件**接入共享局部语义结构。中文与英文共用结构及投影函数；ADMIN 不调用模型或网络 API。源码保持 `1.2.1-preview.1`，没有生成新安装包。

这是 [开源与论文调研](RESEARCH-7PLUS1-EXTRACTION.md) 后的实际实现：借鉴 CNL2ASP 的语法/语义分层、Rimay 的动作角色、FRET 的条件与响应分离，使用已有 Lark 自研文法；没有复制上游源码。GF 仍是未接入的后续候选。

## 1. 七要素如何得到

```text
原文、明确 WP
  → 带原文偏移的词法片段
  → 局部 Lark 角色组合文法
  → Action(operation, roles, modality, guard_sources, source)
  → 七要素 Fact + 独立 B
  → 既有 portion / Z3 / NetworkX 与文件供给检查
```

例如以下两条原文都归约为相同类型的关系：

```text
由 Analyst 读取 orders.csv 并生成 summary.json。
Analyst reads orders.csv and generates summary.json.

Read(executor=Analyst, input=orders.csv)
Create(executor=Analyst, artifact=summary.json)
```

由此取得 I 的 `orders.csv`、O 的 `summary.json`、A 的读取/生成动作和 P 的执行者 `Analyst`。并列生成动作的执行者有前方显式主体作为依据；R、V、C、B 没有因此被自动填满。

| 要素 | 实际来源 | 不作的推定 |
| --- | --- | --- |
| I 输入与范围 | READ.input、CREATE 的显式 from 来源、由 X 将 Y 的输入；已有范围/清单抽取 | 并非所有动词宾语都是任务总体范围 |
| O 交付结果 | CREATE.artifact、SEND.payload/recipient、EMIT 的打印内容；明确返回状态断言 | 发送/打印不等于创建文件；未写成功记录就不补造 |
| A 动作 | 局部文法动作；已有接口守卫解析器的调用记录 | 禁止或“不必做”不成为执行承诺 |
| P 责任与授权 | 分开的 executor 与 approver | 审批人不等于执行者；提到 CFO 不表示已批准 |
| R 资源 | 已有原文数值、量纲、开闭区间与局部指标绑定 | 不合并同单位不同指标 |
| V 版本与依据 | 根据/依据、according to/based on 等明确引用 | 引用存在不代表已经查验有效性 |
| C 完成与停止 | 明确完成句式、局部动作的完成标记 | 生成文件不自动等于任务完成 |
| B 已知禁止 | 独立禁止抽取器、已有条件禁止关系 | 无须先有接口 ID，不自动新增例外 |

**R、V、C、一般范围与 B 仍使用已有的明确来源适配器。** 本轮没有把所有自由文本升级为形式语义。技术详情中的 `kind` 区分动作角色、数值约束、引用短语等证据类型；`completeInterpretation` 保持 `false`。

## 2. 数学模型与文法

设原文为 T，局部词法识别函数为 L，角色文法为 G，字段投影为 π：

$$T \xrightarrow{L} \tau \xrightarrow{G} \mathcal{A} \xrightarrow{\pi} (I,O,A,P,R,V,C;B)$$

τ 是带源码坐标的词法片段序列。文法接受的局部组合包括：

```text
executor? modality? recipient? subject_input? operation recipient? origin? completion?
READ argument / CREATE argument / SEND argument / EMIT argument
PROCESS argument / CHANGE argument / CALL argument
```

词法阶段仍需版本化词表和局部规则来识别操作符、中文主体标记和英文词形。Lark 负责角色组合，`dataclass(frozen=True)` 保存不可变记录。**语法对词法序列的确定性，不证明词法识别和自然语言本意永远一致。**

若 u 为执行者、v 为接收人，可把部分投影写为：

$$\pi_I(\operatorname{Read}(u,x))=\{x\}$$
$$\pi_O(\operatorname{Create}(u,y))=\{y\}$$
$$\pi_O(\operatorname{Send}(u,y,v))=\{\operatorname{Deliver}(y,v)\}$$

`Send` 产生发送要求，不能据此得到 `Create(y)`。未指明的 u 保持未知。条件、模态、来源附着在记录上，并列动作按局部组合继承关系。

**当前最大的难点是原文到这些关系的准确绑定。** 例如两个金额是否同一指标、审批从句约束哪个动作、文件是读取还是生成、禁令是局部还是全局。相同词语可以处在不同作用域；不同词语也可能指向同一对象。7+1 提供了目标结构，不能自行解决这些指代与同一性问题。无法唯一绑定时，应指出具体原句和待解释关系，不能通过填满字段制造可计算的假基线。

既有接口守卫仍与业务动作分开。例如“未经 CFO 授权禁止退款”和“收到风控警报必须退款”：Z3 先计算两守卫能否同时满足（SAT），再在该假设状态下验证正反动作约束不能同时满足（UNSAT）。反例来自前一个 SAT 查询，不能从 UNSAT 求模型。**新局部文法没有把未解析条件强行转换成 Z3 公理。**

## 3. 条件文件供给的实际计算

输入：

```text
## WP1 准备
若批准，则生成 data.json。
## WP2 执行
读取 data.json。
```

区分三类声明：本地片段中没有识别到附加守卫的产出 U、带守卫的产出 Q、明确外部输入 E。它们都不是文件存在性检查。读取需求为 I：

$$\Delta_U=I\setminus(U\cup E)$$
$$\Delta_{all}=I\setminus(U\cup Q\cup E)$$

| 状态 | 结果 | 给 ADMIN 的建议 |
| --- | --- | --- |
| Δ_all 非空 | `io_handover_deficit` | 明确文件提供方或外部来源 |
| 文件不在 U∪E，但在 Q 中 | `io_conditional_supply` | 明确生成条件，以及条件不成立时的处理 |
| 找到产出，时序未验证 | `io_dependency_unresolved` | 明确 WP 依赖、版本和可用条件 |

上述例子 `I={data.json}, U=∅, Q={data.json}, E=∅`，结果是**文件供给有条件**。不能说没有产出声明，也不能说 WP2 一定能读取。不按 WP 编号推断执行先后。

## 4. 新增的正反例

| 输入变化 | 实际期望 |
| --- | --- |
| 读取初筛生成的结构化文件 violation_clean.json | 文件是输入，不是本句产物 |
| Read the file violation_clean.json generated by screening | 与中文采用同一 input 角色 |
| Analyst creates report.json from orders.csv | report.json 是产物，orders.csv 是来源 |
| 发送 report.csv 给 Reviewer / Send report.csv to Reviewer | 接收人是 Reviewer；不登记为新创建的文件 |
| 打印 orders.csv / Print orders.csv | 打印内容不登记为已生成文件 |
| 经 CFO 授权后生成 refund.csv | CFO 是审批主体，产物保留条件 |
| 无需生成 ledger.json 并发送 notice.txt | 两动作均不成为交付承诺 |
| 生成 a.csv 或 b.csv | 保留备选关系并给建议，不承诺两者都生成 |
| 生成包含 orders.csv 内容的 report.json | 不能精确区分文件角色时，提示区分引用与产物 |
| 生成 report.csv，除非数据为空 | 保留后置条件，不丢弃逗号后的限制 |

这是新构造的工程正反例，不是随机抽样的自然语言准确率测量。

后续补充的中文数字、角色精度、长文本作用域、条件保留和伪槽位回归也纳入测试。最终 Python 测试方法为 87 个；完整测试与 100 号用例主集、20 个中文数字变体的实际观察见 [用户用例测试报告](USER-CASES-017.md)。测试方法通过不等于这些自由文本已完整支持。

## 6. 使用与源码

刷新运行中的本地页面，在 ADMIN 入口粘贴原文并点击“本地检查，给 ADMIN 建议”。无需连接模型。展开**“查看提取关系：动作、角色与条件”**可逐句看执行者、输入、产物、接收人及条件；完整 IR、未覆盖片段和公式在技术详情中。

产品目录执行 `npm run ui` 可启动。沿用 [Python 安装指南](ADMIN-PYTHON-011.md) 的锁定依赖，本轮无需新增库或模型下载。

## 7. 中文数值与量纲怎样计算

原文不重写。数字片段先归约为 Decimal，再按单位表换算。中文采用十、百、千、万、亿的位值组合；整数块有唯一标准写法校验，拒绝把“一百二”擅自解释成 102 或 120。

$$N(三十)=3\times10=30,\qquad R_t=30\times60=1800\ \mathrm{s}$$

$$N(五百万)=500\times10000=5000000$$

“至少”保留 ≥，“严格小于”保留 <，“禁止大于”归约为 ≤。`calls per second` 保留分母，不与总调用次数混为同一个量纲；没有明确币种的 dollars、没有温标的“度/degrees”保留待确认，不能自动换成 USD/℃。人民币前缀与后缀单位冲突时停止该数值的区间求值，输出具体单位诊断。

数值有原始 `originalValue/originalUnit/expressionSource`；归一值另存 `value/unit/relation`。边界探针的三个输入只是检验点，不是新增任务条件。现有同指标归属规则仍有限，找到两条数值不保证已证明它们约束同一个变量。

## 8. 长文本与作用域的实际进展

现在支持 `## WP1`、`【阶段一/WP1：标题】`、`## WP-DATA-01 标题`、`【阶段一：标题（WP-DATA-01）】`。保留标题证据、围栏排除、重复 ID/层级诊断及跨包条件待绑定。支持命名工作包不等于支持所有“第一阶段/Phase 1”自由标题，更没有由编号推导依赖。

在用户 82 号原文中已实际识别两个工作包，读取的 `financial_audit_reconciliation.csv` 得到文件来源缺口建议。第一阶段带修饰的 parquet 产物仍有角色绑定缺口，不能用参考答案偷偷填入供给集合。完整实际 7+1 与差集见 [长文本报告](cases-017/long-81-89.md#long_82)。

引用句中的“机构下发规范”不再产生本任务的发送动作；“执行过程中”不再当成接口调用。“该阶段任务即为完成”仍需把回指绑定到前面的断言，不能把“该阶段任务”本身当成停止条件。目的地也不是发送载荷。未知片段保留在 `contract.uncovered` 中，必要时输出具体澄清建议。
