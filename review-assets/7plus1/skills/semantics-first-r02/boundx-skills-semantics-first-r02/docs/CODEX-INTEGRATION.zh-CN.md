## 4. 与Skill同时核对的程序责任

### A. 外部输入的被约束使用集合

建立数据使用到外部输入投影的明确语义；相对于任务的来源必须有依据，不能把producer为空一律判外部。程序应能拒绝新增域外输入，同时不把内部报告计入根任务外部输入。

本包没有新增一个未经实现的算子。先查现有结构能否忠实表达；不能时提出最小合同扩展及消费者、来源验证和正反测试。批准并实现之前，相关缺口不得从输出或质量门中删除。

### B. 数据可用性

明确“所需内容就绪”“完整产物就绪”“生产任务结束”的区别，消费者与生产者必须绑定同一对象和版本。不能把改变`COMPLETE_RESULT`到`USED_PORTION`本身当作语义修复证明。

反例包括：生产未发生、生产已开始但内容未就绪、部分所需内容已就绪、明确要求完整但仅部分就绪。规则应从合法IR计算，不扫描中文标签、不识别固定文件名。

### C. 接受与疑点隔离

区分对象身份、角色、归属、字段值、语义前提和计算依赖。局部范围缺口应阻止该范围的完整认证，而不是使ROOT身份与所有引用者同时失效。反过来，实际依赖未定对象或条件的表达仍须未决。

审阅输出仍按1.2的整节点裁定及字段记录格式。程序不能只因整体SUPPORT就忽略字段反对，也不能只因members获支持就认为整组身份与范围已审完。

### D. 修订一致性

在新版本事务中同时处理IR、coverage、issues、omissions和审阅适用范围。历史保持不变；当前缺口通过明确的解决记录和独立复核关闭，而不是自动拼接后永久生效，或凭“这次没提”直接删除。

基础摘要、获准替换、受影响节点重审、引用合法性、当前有效状态应作为一个检查单元。首次失败与修订后成绩分开，不沿用未经重新证明的旧PASS。

### E. 投影与计算职责

正向A/O、非正向事实与B按共享模态规则处理；数学摘要使用同一规则。禁止交付不能在正向产物中冒充必交，内部产物输入不能被当成新的外部数据源。

允许结构化而尚不支持的算子可显示其原始结构及能力缺口。不得只因结构合法或找到一个满足见证就宣布完整原文覆盖，也不得把SAT当成父子规划全称符合证明。
