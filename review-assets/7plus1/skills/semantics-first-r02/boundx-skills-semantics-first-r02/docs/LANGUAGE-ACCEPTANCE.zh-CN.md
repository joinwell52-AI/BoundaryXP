# r02语言适用与验收口径

## 1. 不变部分

六步法、同一候选IR、独立新会话审阅、程序接受和计算职责不变。没有新增语言字段或双语节点；已有原文任务与001标准不改。新章节是此次新增的语言处理规范，不是从旧中文Skill中宣称已经存在的能力。

## 2. 需要验证的两个维度

指令语言：中文规程或英文规程，选择一个固定配置。
输入语言：中文、英文或混合，均可以交给同一配置。

先验证选定指令配置下的三种输入，不随输入自动切换规程。要宣称两个指令版本质量相当，应另作两种指令配置的对应测试；不能从文字翻译推断模型行为相同。

## 3. 配对比较的方法

先逐条以原文检查语义正确性，再检查作者预期对应的中英对是否保持同一边界。比较对象身份和版本、角色和接收者、模态、作用域、限制所约束的对象、条件方向及开始时点、数据使用、数量和完成/停止关系。

允许内部ID重命名、集合/合取无关顺序改变、显示描述语言变化。任何规范化都必须遵循明确等价规则；不得抹掉否定、例外、条件、来源用途、身份或数值单位。相同角色代号和路径仍须原样保持；两种文本中的非字面相同概念按评测端明确的成对对应核对，不从字面相似推定等价。

来源引文分别对各自原文验证。中文quote不应出现在只提供英文原文的候选中；源文包含中文文件名则必须保留。JSON转义前后解码一致，不要求序列化字节相同。Unicode正规化和大小写归一化不是通用的对象身份规则。

两版都错误、都漏限制，不能因互相一致判通过。诚实报告同一合同缺口，只能统计为“缺口一致”，不是完整生成成功。真实语言歧义和合同无法表达要分开；缺少业务观测也不妨碍静态规则表达。

## 4. 数据及状态

新组为BI01—BI24，每组中文和英文各一份；MX01—MX06为混合文本，合计54份。全部是公开开发材料，不是盲测。旧20条原样保留，其历史状态不升级。

本次仅创建材料和执行静态检查；模型、Codex、BoundaryXP程序及58618均未运行。实际执行时只提取一个text或单个TXT，不发送pair/expected文件或配对译文，不改变授权预算。

## 5. 必须分开统计

单语逐项来源保真；过强/过弱约束；明确文本被过度澄清；真正歧义；合同表达缺口；消费者缺口；语言对的语义一致性；传输失败；耗时与请求数。

不能只报告“八槽一致、数量一致、JSON合法”。不能把r01或001旧成绩继承为r02英文成绩，也不能把静态包校验次数叫作模型准确率。

## 6. 写作对应检查的边界

四份规程已经按原六步及审阅结构逐节编写和核对；`PARITY-MAP.json`保存章节对应和必须保留的机器标识。脚本只能检查这些对应入口、标识和文件一致性，不能证明翻译语义等价，也不能预测模型输出。英文作为独立全文交付，不要求同时加载中文全文。
