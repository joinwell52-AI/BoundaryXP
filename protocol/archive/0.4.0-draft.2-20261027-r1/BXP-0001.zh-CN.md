# BXP-0001：边界分析协议

## 摘要

边界分析协议（Boundary Xplain Protocol，BXP）规定一套共同约定：表示任务要求，保留要求之间的关联与不确定性，构造形式化边界模型，计算边界结果，并对精确任务版本进入正式下游流程实施准入。界痕（BoundaryXP）是产品实现，BXP 是协议。

本修订汇集界痕编译器设计、规范投影配套资产、语义包和本地生命周期实验所揭示的协议要求。I/O/A/P/R/V/C 与独立禁止边界 B 的含义保持不变；本版明确共享语义结构、状态层次、解释依赖、修订过程及下游比较对象。

八类视图组织要求，共享结构保存身份、条件、作用域、顺序与交接。数学计算作用于完整语义载体的形式模型。载体已有内容、文档结构有效、边界已确定、准入已通过，是不同的结果。

草稿可以保留部分结果和未决信息。正式发布必须针对精确版本和声明的发布范围通过准入。BXP 不授予业务批准或执行权限，也不承诺自动正确理解任意自然语言。

## 1. 状态、规范范围与符合性

必须（MUST）、不得（MUST NOT）、必需（REQUIRED）、应当（SHOULD）、不应（SHOULD NOT）和可以（MAY）表达本草案中的要求。本文件是仓库内的评审草案，不是已采纳的外部标准、认证或公开发布授权。英文为规范文本；本中文文本为非规范译本。

**BXP-VER-001** 实现声明必须列明精确协议版本、能力阶段、Profile 与算子 Profile 修订、Schema、实现快照和验证依据。修改标签不会使现有实现自动升级。本文件包不建立任何实现对 draft.2 的符合性。

规范正文优先于配套文档。Profile 可以限定所支持的语言、对象类别、必需信息和发布政策，但不得重新定义八类视图含义、隐藏不确定性或产生权限。仅有 Profile 标识而没有精确修订与内容身份，不足以固定计算合同。

能力阶段包括语义载体、形式模型、边界计算、准入和下游符合性。通过某阶段的结构检查，不证明后续阶段已经成立。只实现载体的系统可以声明该项能力，但必须明确限定范围。

## 2. 协议对象与边界语义

令 W 为固定来源包，Λ 为声明的解释合同。生产者提出与来源关联的解释，这一候选生产关系可以是非确定的。在选择一种解释或明确保留其余解释之后，表示与形式化在固定合同下进行：

```math
W \xrightarrow{Producer} \operatorname{Candidates}(W,\Lambda),
\qquad
\mathcal C \xrightarrow{Formalize_{\Lambda}} \mathcal M
\xrightarrow{Evaluate_{O_v}} \mathcal B
\longrightarrow Admission.
```

其中，C 为第 3 节定义的完整语义载体，M 为形式化边界模型，B 为边界结果，O_v 为算子 Profile。第一个箭头表示候选生产，不保证唯一翻译。生产者可以是规则、语言模型、其他自然语言处理系统、人工或其组合。

### 2.1. 作为可接受实现集合的边界

固定观察域 X_Σ，包括类型、单位、时间解释、作用域及良构条件。抽象模型及其边界为：

```math
\mathcal M=(E,\Sigma,Q,F,K,\mathcal R,D,\Phi),
\qquad
\chi_{\mathcal M}(x)=Q(x)\land\neg F(x)\land K(x)\land\Phi(x),
\qquad
\Omega_{\mathcal B}=\{x\in\mathcal X_\Sigma\mid\chi_{\mathcal M}(x)\}.
```

E 包含已识别实体；Q 为义务及必需结果；F 为禁止状态或效果；K 为完成停止条件；ℛ 为参与者及其他关系；D 为依赖、交接与版本关系；Φ 为其余约束。这些分量可以采用带共享引用的类型化集合表示。对可接受性起约束作用的关系与依赖必须进入边界谓词，不能只作为展示性元数据保存。

边界无需枚举其全部实现，但结果必须支持在声明合同下重建或核验定义边界的约束。实现集合为空，表示该模型下的要求不相容；候选规格为空时，不得利用空真蕴含通过保持检查。

### 2.2. 解释范围与语义唯一性

**BXP-SEM-001** 每项边界确定结论必须指明解释范围、该范围对来源和上下文的覆盖，以及认定范围充分的依据。依据可以是受支持的无歧义语法、可问责的来源审核、权威澄清或解释选择。候选一致本身不能证明已覆盖全部相关解释。不得为取得唯一结果而丢弃已知且有来源依据的备选解释。

对声明的可接受解释集合，定义：

```math
\mathfrak B_\Lambda(W,O_v)
=\{Evaluate(Formalize_\Lambda(I),O_v)\mid I\in\mathfrak I_\Lambda(W)\}.
```

解释集合必须非空。仅经抽样或尚未建立覆盖的候选集合，只能支持相对唯一性的发现，不能支持不加范围限制的 `determined` 状态。解释范围充分性尚未建立时，必须明确保留这一限制，并阻断正式发布。权威选择改变或确认声明的解释合同，并不构成原始措辞本身无歧义的数学证明。

**BXP-SEM-002** 在相同观察与解释合同下，规范化必须保持边界语义：

```math
Canon_\Lambda(b_1)=Canon_\Lambda(b_2)
\;\Longrightarrow\;
\Omega_{b_1}=\Omega_{b_2}.
```

Profile 必须明确规范化规则及其满足该健全性条件的依据，并单独说明规范化对语义等价是否完备。缺乏完备性时，规范对象不同不能证明边界不同。可以使用受支持的等价判定过程处理此情况，否则唯一性仍未建立。确定性的 JSON 序列化本身不建立逻辑等价。

### 2.3. 职责边界

**BXP-SEM-003** 生产者负责候选主张及其来源；形式化者负责在声明解释下保持语义；求值器负责其执行的数学查询；宿主负责可信上下文、澄清、发布政策与执行准入约束。执行工作的权限仍在协议之外。可追溯引文或符合 Schema 的对象，不得被表述为解释正确或完整的证明。

## 3. 语义载体：八类视图与共享结构

### 3.1. 保持稳定的视图含义

```math
IR_{7+1}=(I,O,A,P,R,V,C,B),
\qquad
\mathcal C=(IR_{7+1},G_s,\Pi,\Lambda).
```

| 标识 | 名称 | 规范含义 |
|---|---|---|
| I | 输入范围 | 对象、数据、系统、群体，或其他任务输入及作用域内的对象。 |
| O | 交付 | 明确声明的交付物或外部可观察结果。 |
| A | 动作 | 必须、允许或其他与任务有关的操作，保留已知的主体、效果、目标及模态。 |
| P | 责任主体与角色分工 | 参与执行、批准、观察、复核、接收或协作的人、Agent、系统及服务。 |
| R | 资源 | 数量限制、预算、容量、截止时间、时长和阈值。 |
| V | 版本依据 | 起控制作用的版本、制度、证据来源及时间基准。 |
| C | 完成停止 | 完成、停止、验收及升级处理条件。 |
| B | 独立禁止边界 | 禁止的效果、目标、动作或其组合，包括守卫与例外。 |

英文版上表的语义定义逐字沿用 draft.1。G_s 为共享身份、关系、表达式、条件和作用域结构；Π 包含来源、覆盖问责、诊断及修订引用；Λ 固定语义解释依赖。它们是完整载体的支撑分量，不是新增语义视图。

**BXP-IR-001** 完整载体必须保存或通过不可变引用保留其全部承载边界要求的共享结构。引用必须能在提交包或明确固定的本地依赖中解析。接收者不得补造缺失关系，也不得依赖获取可变网络内容来完成求值。

必须记录每个规范性根及其引用闭包的去向。跨视图的共享身份不得改变；有向关系的端点、表达式的有序参数必须保留角色和位置。传输格式可以采用数组、带位置的边或等价编码；把有序参数当作无序集合不符合协议。投影与形式化过程中，必须保留条件、例外、时间作用域及跨视图关联。

### 3.2. 条目状态、视图状态与结果状态

**BXP-STA-001** 必须能够区分条目解释状态、视图聚合状态、形式相容性、边界确定性及准入。已经解释的主张仍可能与另一条已解释主张冲突；`resolved` 不表示它们的合取可满足。

公开视图状态仍为 `resolved`、`unresolved`、`absent`。存在更细的条目区分时，Profile 必须保留未决、延后、不支持、归属歧义等信息。必须保留矛盾分组，不得静默选择其中一方。不适用与缺少必需信息的诊断，不得和文本未提及混同。

**BXP-STA-002** 令 Open(S) 和 Resolved(S) 为有明确归属依据的视图 S 的条目。Accounted(S) 表示声明的投影输入对 S 已有完整去向台账，包括可能相关的缺口。规范归约为：

```math
Status(S)=
\begin{cases}
unresolved,&Accounted(S)\land Open(S)\ne\varnothing,\\
resolved,&Accounted(S)\land Open(S)=\varnothing\land Resolved(S)\ne\varnothing,\\
absent,&Accounted(S)\land Open(S)=\varnothing\land Resolved(S)=\varnothing.
\end{cases}
```

问责不完整时，归约前提尚未满足，应返回覆盖诊断，不能伪造第四种公开状态或 `absent` 值。部分记录可以保留已建立的条目及诊断，但不得宣称规范归约完整。归属歧义只传播到有明确证据的候选视图，不允许任意复制到多个视图。

`absent` 表示在声明且已问责的输入内未发现相关条目。它不表示禁止、允许、不适用，也不证明自然语言抽取完整。投影台账本身无法证明上游生产者已识别全部原文要求。即使投影问责已经完成，已知的抽取缺口或不支持内容仍必须在来源到载体的阶段显式保留。

空的 `resolved` 视图无效。有来源依据的明确“无”必须保留为真实解释条目，不得从沉默合成。已解析条目不得掩盖开放条目。

### 3.3. 结构存在与必需信息

**BXP-PRO-001** 规范载体必须在结构上提供全部八类视图。这不要求全部视图都已确定或非空。基础载体 Profile 采用 `structural_elements=[I,O,A,P,R,V,C,B]` 和 `required_elements=[]`，它不是发布政策。

必须由专用 Profile 或明确任务要求建立必需确定的信息，并保留适用条件及来源。Core 不设置“V 总是必需”或“所有视图总是必需”的通用默认值。必需但未提及的内容是确定性或发布条件缺口，不允许据此补造取值。承载要求的未决条目不能仅因其视图未列入 required-elements 而被忽略。

### 3.4. 解释约束

**BXP-IR-002** 视图归属必须保持用途与模态。具体包括：

- 生成产物本身不建立交付义务或接收者；
- 报告中的建议不是执行该建议的指令；
- 参与者或语法主语本身不建立执行权限；
- 一般前置条件不必然是完成停止条件；
- 数量约束保留资源维度、单位及受约束活动，数字本身不是资源限制；
- 编译器来源信息不自动成为任务的控制版本依据；
- 显式禁止必须保留在 B 或明确的未决／诊断记录中，并保留守卫与例外。

当不同用途得到保留时，同一操作可以由 A、B 共享引用。此引用不得把禁止操作变为正向许可或义务。满足正向义务不能抵消无关禁令。B 的独立审核责任，不意味着禁止比否定义务增加了逻辑表达能力。

## 4. 来源、语义依赖与修订证据

### 4.1. 来源问责

**BXP-SRC-001** 每个承载边界要求的条目、关系、条件及派生约束，必须带有身份及来源或推导引用。来源定位必须绑定来源修订与内容身份，并声明位置约定。采用字符偏移的文本 Profile 必须使用从零开始、末端不包含的 Unicode 码点区间 `[start,end)`，保留原文。

必须记录每个已识别边界承载来源项的去向：已表示、未决、不支持或其他有明确理由的处置。以示例、引文或非规范内容排除某项时，需要可问责的来源层理由。字符范围正确只能证明位置，不能证明解释。

**BXP-SRC-002** 在固定解释下，形式化既不得遗漏要求，也不得增加无依据要求。派生约束需要从提交的主张及已经声明的背景中推导。实现不得事后增加背景假设来证明偏好的输出合理。免除义务不产生禁止；冻结一组参数不证明不存在任何训练。

### 4.2. 解释合同与语义包

**BXP-DEP-001** Λ 必须标识实际使用的每项语义依赖：观察类型、实体和谓词签名、论元角色、模态含义、单位与时间换算、作用域规则、允许的推导及形式化规则、沉默解释政策和适用权限事实。依赖必须有版本及内容绑定。语义包描述符必须区分语义定义、抽取启发式及部署元数据。

选择语义包、校验其 Schema 或匹配词项，不授予任何操作权限，也不证明包内事实为真。适用性与权限必须有明确来源。岗位职级、相似度分数、模型偏好及默认常识，不得产生权限事实或实体绑定。

**BXP-DEP-002** 无法映射的谓词、不支持的结构或未决身份，必须保留来源及具体缺口诊断。不得静默丢弃、按最相近词项强行映射或赋予方便计算的默认值。新增条目或规则需要新的依赖身份、适用政策下可问责的接受决定，以及对受影响结果重新求值。本合同不规定 L1/L2/L3 文件格式、解析器架构或通用本体库。

### 4.3. 澄清与版本化修订

**BXP-REP-001** 修订请求必须标识受影响的来源、主张或关系，阻断问题，已知的解释备选项，以及请求所依据的版本。响应必须标识其来源及变更权限。求值器可以诊断并请求澄清，但不得补充缺失授权、仅为获得可满足结果而丢弃约束，或静默选择方便的解释。

修订必须产生新的任务版本或解释版本。旧来源、载体、诊断和结果必须可以恢复。受影响的投影、模型和比较必须重新求值；复用未受影响的结果，需要明确检查依赖。本修订不引入自动约束放宽规则。

## 5. 形式化与语义保持

### 5.1. 完整载体的映射

**BXP-FOR-001** 形式化消费完整载体 C，而非八个相互分离的列表。必须把共享实体和参与者身份映射到 E、R，把交接、依赖和版本关联映射到 D，把适用的守卫、顺序和作用域约束映射到 Q、F、K 或 Φ。每个边界承载输入必须有翻译、有依据的等价归约，或明确的不支持／未决处置。存在尚未翻译的边界承载内容时，不得给出不加限制的确定结论。

对于 Λ 下固定的解释 S，保持义务为：

```math
\forall x\in\mathcal X_\Sigma,\qquad
\chi_S(x)=\llbracket\mathcal C\rrbracket_\Lambda(x)
=\chi_{Formalize_\Lambda(\mathcal C)}(x).
```

来源对应建立第一个等号，表示与形式化保持建立第二个等号。来源记录和 Schema 校验本身不能履行其中任一义务。实现必须标明由哪些检查、声明、审核或证明支持该义务，以及它们的局限。

### 5.2. 条件、分支与观察

**BXP-FOR-002** 规格 Profile 必须固定分支激活、条件义务及未激活分支的行为。未激活分支的私有贡献可以置为中性值，但不得仅因某个分支未激活就删除共享实体或事实。只有当改变私有非活动变量不能改变父任务可观察行为或比较结论时，才允许这些变量保持自由。否则必须约束它们，或将该形式化保持为未决。

映射到父观察域时，必须保存父任务可观察的全部动作、效果、身份、时间和资源贡献。将新增禁止动作隐藏为内部细节不符合协议。Profile 必须声明支持的身份映射和聚合方式，并确保拉回后的查询仍处于支持语言内。

### 5.3. 覆盖与组合

**BXP-FOR-003** 局部检查与联合检查必须共同覆盖被比较的父谓词。只依赖一个子任务的顶层合取项可以在局部检查。跨任务析取、交接、共享预算、分支约束及其他耦合项，除非已建立保持语义的分解，否则必须保留为联合检查。本条不承诺任意公式都能独立分布式验证。

提交了语法上完整的任务树，不等于证明了来源完整性、全局可实现性或环境覆盖。三者必须分别有依据或查询。

## 6. 确定性计算与算子合同

### 6.1. 数学结果与运行结果

**BXP-EVA-001** 对相同形式输入及固定计算合同，完成的求值必须产生相同的规范数学结果。未声明的网络状态、模型响应、随机抽样和当前时间不得改变结果。Core 在数学求值期间不得调用模型、获取制度或重新解释自然语言原文。

```math
\mathcal M_1=\mathcal M_2\land O_{v1}=O_{v2}
\Longrightarrow Evaluate(\mathcal M_1,O_{v1})=Evaluate(\mathcal M_2,O_{v2}).
```

此等式比较规范数学内容；来源绑定的结果信封及单独附带的重放证据可以不同，见第 9 节。实际合同包含任何影响求值的已声明模型背景和解释依赖。运行完成、超时、取消、不支持输入、内部错误与数学结论必须分别报告。不得把超时或 `unknown` 重标为不可满足、相容、保持或确定。耗时及暂态进程诊断不属于语义边界身份。

若见证具有多种有效形式，Profile 必须对进入规范结果摘要的见证规定确定性选择或规范化；也可以把见证字节作为单独绑定的重放证据，此时规范语义结果仍必须稳定。

### 6.2. 算子 Profile 的要求

**BXP-OPR-001** 算子 Profile 必须声明：精确身份，支持的类型、语法和查询种类，背景语义，界限和精度，规范化与编译规则，输入输出合同，失败及不支持行为，以及证据检查与重放要求。Profile 标识不是获取或执行远程代码的指令。

**BXP-OPR-002** 数学证据必须区分已核验见证、已核验证明／证书、仅能在声明的可信计算基础内复跑的求解器结果，以及未核验证据。求解器名称和版本本身不是证明证书；UNSAT core 本身也不是不可满足性证明。重放声明必须提供精确查询、依赖、求解器版本与选项及可本地运行的过程；独立可检查证明的声明还需要受支持的证书和检查器。发布政策必须明确接受哪类证据，不能默认接受未核验标签。

### 6.3. 查询编码

**BXP-OPR-003** 实现域编码必须精确表示声明的合法观察。辅助变量必须针对完整查询引入，定义约束放在被否定或异或的操作数之外。至少满足：

```math
D_\Sigma(x)\Rightarrow\exists z\,\Delta_Q(x,z),
\qquad
D_\Sigma(x)\land\Delta_Q(x,z)
\Rightarrow(\widehat\psi_Q(x,z)\leftrightarrow\psi_Q(x)).
```

这些条件要求每个合法扩展都保持查询真值；全定义的函数性扩展是一种充分实现方式。分别编码的操作数仅仅等可满足，不允许把它们直接用于否定之下。所有见证投影都必须对原查询语义进行核验。

### 6.4. 支持的判定范围

**BXP-OPR-004** Profile 必须区分可判定查询语言与实际资源限制。有限命题、类型化集合、有界图及受支持线性算术 Profile 可以分别提供。本草案不注册完整 SMT 实现，也不声明支持任意带量词、时序、概率或非线性约束。

明确有限的环境可以按第 11.4 节枚举。对无限环境作有限划分，仅在存在可检查论证、能够保持每个单元内的可实现性及反例存在性时才足够。只抽样代表元不足以满足要求。精确的带量词过程只能在另行声明且支持该过程的 Profile 下使用。否则相关覆盖查询为不支持或未决，不能记为通过。

## 7. 边界结果与分层确定性

### 7.1. 结果内容

抽象边界结果保留以下分量：

```math
\mathcal B=(State,Required,Forbidden,Limits,Completion,
Relations,Dependencies,Provenance,Findings).
```

**BXP-RES-001** 结果必须绑定来源、完整载体、形式模型、解释范围、Profile 及实际执行的查询。必须区分结构验证、来源／覆盖评估、形式相容性、边界确定性与运行完成。初步或部分制品不得冒充已完成边界结果。

### 7.2. 边界状态

公开边界状态仍为：

| 状态 | 含义 |
|---|---|
| `invalid` | 协议数据违反声明的结构或语义输入合同。 |
| `inconsistent` | 声明解释下，模型的要求之间存在有依据的矛盾。 |
| `underdetermined` | 相关解释、身份、作用域、适用性、覆盖、支持能力或求值仍不足以确定边界。 |
| `determined` | 必要条件已经建立，模型相容，且在充分确立的解释合同下边界语义唯一。 |

**BXP-RES-002** 输入无效优先于语义判定。已充分建立的子集中存在的矛盾，不能被无关不确定性掩盖；但整体 `inconsistent` 状态要求其证明在全部可接受解释范围内成立。否则应保留有条件的发现及 `underdetermined`。没有建立此类矛盾时，相关义务未决排除 `determined`。

确定条件为：

```math
Determined(\mathcal B)=Valid\land InterpretationScopeEstablished
\land RequiredResolved\land RelevantCoverageEstablished
\land UniqueSemanticBoundary\land Consistent\land EvaluationComplete.
```

这是证据与语义要求，不是证明任意自然语言理解正确的算法。覆盖声明必须保留依据，不能抹去已知缺口。

### 7.3. 部分结果与相关性

**BXP-RES-003** 部分事实可靠时，即使其他事实未决，也必须保留这些可靠事实。只有在声明合同下建立某未决诊断与所问边界或发布条件无关，才可将其视为非阻断项。此发现必须记录范围与理由。置信度分数、空的 required-elements 列表或用户已读确认，都不是无关性证明。相关性未知时，对不加限制的边界确定和正式发布构成阻断。

通过缩小范围忽略某项要求，会改变所发布的任务；必须明确修订任务并重新准入，不能把原任务静默标为部分通过。

## 8. 强制准入与修订生命周期

### 8.1. 准入谓词

**BXP-ADM-001** 宿主可以保留未完成或不相容的草稿用于分析和修订，但正式发布必须满足：

```math
Admit(T_v)=ProtocolValid(T_v)\land BoundaryDetermined(T_v)
\land ReleaseConditions(T_v)\land VersionBound(T_v).
```

准入条件为假、缺失、陈旧或尚未计算时，必须阻断正式发布。载体有效及 `required_elements=[]` 都不是默认发布许可。适用的发布 Profile 及其条件必须明确且固定。

### 8.2. 委派与精化义务

**BXP-ADM-002** 以父边界的委派或精化形式正式发布任务时，ReleaseConditions 必须包含声明的父边界保持义务。比较必须绑定父任务和候选版本、映射、环境合同与比较政策。`not_guaranteed`、`necessarily_violating`、可实现性或环境覆盖失败，以及比较未完成，均不能满足该义务。

没有声明父精化关系的任务，不必补造此关系。宿主不得通过遗漏实际委派关系绕过必需检查。任务关系如何得到权威确认，由声明的宿主政策负责，不能从角色名称推断。

### 8.3. 修订与准入执行

**BXP-ADM-003** 任务来源、解释选择、语义依赖、Profile、模型、比较基准或发布证据发生变化时，受影响的旧准入绑定不得继续复用。即使任务修订后的边界语义等价，也必须有新的准入记录。宿主必须在发布前重核当前绑定，防止陈旧或并发写入绕过检查。

允许“草稿 → 分析 → 澄清 → 修订 → 重新求值 → 准入”的生命周期。这不产生自动批准、到期放宽或删除阻断要求的规则。修订期间应保留部分结果。

### 8.4. 权限分离

准入表示满足 BXP 条件，可以进入正式任务生命周期；它不授予执行操作的权限。外部业务批准、凭据、主体权限与运行时控制仍由宿主负责。

## 9. 身份、交换与重放

**BXP-ID-001** 身份绑定必须包含语义依赖、形式化输入与共享结构，不能只绑定展示的八类视图。至少需要以下身份，或等价且无歧义的依赖结构：

```math
D_S=Hash(SourceBundle),\quad
D_C=Hash(Canonical(\mathcal C)),\quad
D_M=Hash(Canonical(\mathcal M)),\quad
D_B=Hash(Canonical(\mathcal B)),
```

```math
D_A=Hash(ProtocolVersion,ProfileIdentities,D_S,D_C,D_M,O_v,D_B,
ComparisonBindings,ReleaseEvidence).
```

规范化必须规定编码、排序、数值精度及元数据包含／排除规则。内容寻址引用必须在求值前验证。来源或规范化规则不同，即使边界语义等价，结果摘要也不必相同。在声明方案下，摘要相等标识固定内容，不证明真实性、权限或语义正确性。

**BXP-ID-002** 交换必须携带足够的依赖信息，使接收者无需原生产者即可验证和重放所声明能力。依赖缺失必须返回明确缺口。运行软件版本与选项必须绑定在重放证据中；如果影响语义或规范化，也必须进入计算／准入合同。重放旧版本不构成新版本准入。

## 10. 生产者独立性

**BXP-PRD-001** 生产者选择不得改变视图含义、状态归约、数学语义或权限边界。对同一原文重复识别可以产生不同候选，这些差异必须可追溯；这不放宽固定形式输入的确定性计算要求。

```math
Formalize_\Lambda(\mathcal C_a)=Formalize_\Lambda(\mathcal C_b)
\Longrightarrow Evaluate(Formalize_\Lambda(\mathcal C_a),O_v)
=Evaluate(Formalize_\Lambda(\mathcal C_b),O_v).
```

该等式针对相同完整计算合同下的规范数学内容。不同来源或生产者溯源信息仍可能产生不同的来源绑定结果身份。BXP-EXTRACT 继续保留为 RESERVED；本修订不建立抽取认证，也不新增协议编号。

## 11. 下游符合与规格保持

### 11.1. 比较对象与证据

**BXP-CMP-001** 比较必须声明对象是具体实现、部分观察，还是候选规格／任务分解。必须声明观察范围、身份映射、完整性假设及边界基准。不完整日志中没有记录某事件，不得被当作该事件未发生的证据。

对具体且观察充分的实现，定义：

```math
Conform(x,\mathcal B)\iff x\in\Omega_{\mathcal B}
\iff\chi_{\mathcal M}(x).
```

只有当相关集合、身份、守卫和观察覆盖已经建立时，集合差或禁止动作交集才是有效诊断。记录了依赖边，不证明运行事件实际按要求的顺序发生。

对于部分观察 O，令 X(O) 为其非空合法补全集合。全称符合结论要求全部补全都符合；确定违反需要充分的已观察事实，或全部补全都违反的证明。否则返回证据不足。观察相互矛盾时，不能利用补全集合为空来建立符合。不支持的补全推理必须保持为明确不支持。

### 11.2. 沉默、组合与环境

**BXP-CMP-002** 候选沉默必须有声明的解释。没有来源明确的穷尽声明或继承规则时，未提及的观察变量保持未约束。封闭域或继承约束需要明确作用域、来源和版本绑定。求值器不得为获得偏好的结论而选择沉默政策。

对于候选分解 Π，记：

```math
H_\Pi(e,u)=D_{ctx}(e,u)\land\Gamma_\Pi(e,u)
\land\bigwedge_i\left[(a_i(e,u)\Rightarrow\chi_i(e,u_i))
\land(\neg a_i(e,u)\Rightarrow Z_i(e,u_i))\right].
```

Γ 包含共享约束；a_i 表示分支激活；Z_i 满足第 5.2 节的非活动观察规则。变量必须有带作用域的身份，公式组合必须避免变量捕获。父观察映射 ρ 必须明确并保留相关行为。令 E_adm 为候选承诺处理的非空外部情境集合。候选不得通过把外部事件变成无依据的假设来缩小该集合。

### 11.3. 将可实现性与保持结论分开

**BXP-CMP-003** 完整保持结论要求：候选在每个承诺情境下可实现，且全部实现满足父边界：

```math
Coverage(\Pi)\iff\forall e\in E_{adm}\;\exists u:H_\Pi(e,u),
```

```math
Preserved(\Pi,p)\iff Coverage(\Pi)
\land\forall e\in E_{adm}\;\forall u:
H_\Pi(e,u)\Rightarrow\chi_p(e,\rho_e(u)).
```

完整查询保留环境范围限制：

```math
J(e,u)=(e\in E_{adm})\land H_\Pi(e,u),\quad
Bad=J\land\neg\chi_p(e,\rho_e(u)),\quad
Good=J\land\chi_p(e,\rho_e(u)).
```

在有效性与环境覆盖已经建立后，该关系具有三类语义结果：

| 结果 | 数学条件 | 含义 |
|---|---|---|
| `preserved`（保持） | Bad 不可满足 | 承诺情境下候选的全部实现都满足父要求。 |
| `not_guaranteed`（未保证） | Bad、Good 均可满足 | 候选同时允许符合与违反的实现。 |
| `necessarily_violating`（必然违反） | Good 不可满足 | 这些情境下不存在满足父要求的候选实现。 |

上述条件要求 J 非空，该前提由非空 E_adm 上的覆盖保证。J 为空时，报告候选不相容，不能报告违反实现。若某承诺情境没有实现，报告覆盖失败，不给出完整保持结论；有效反例仍可作为限定范围的发现保留。如果解释、映射或必需查询未决，应报告比较未完成；这与已经计算得到的 `not_guaranteed` 不同。

传输词汇可以不同，但必须有明确版本化映射。旧结果 `VIOLATED` 加 `CHILD_CONDITION_INCONSISTENT` 必须映射为候选不可实现，不能映射成已观察到或已有见证的禁止行为。局部 `VERIFIED` 不得提升为整个任务保持。

### 11.4. 有限情境求值

当承诺情境被明确枚举为：

```math
E_{adm}=\{e_1,\ldots,e_m\},\quad m\ge1,
```

覆盖与全称保持可归约为每个情境上的两个查询：

```math
\operatorname{SAT}(H_\Pi(e_j,u)),\qquad
\operatorname{UNSAT}(H_\Pi(e_j,u)\land\neg\chi_p(e_j,\rho_{e_j}(u))).
```

只有在代入与编译后仍处于受支持的无量词语言中时，它们才是无量词求解查询。这不会自动把实数区间变成有限情境。抽象划分及无限情境必须满足第 6.4 节。零情境枚举不是有效的空真保持证书。

## 12. 算子族及其限制

基础协议不固定求解器，也不规定封闭算法清单。现有算子族可以继续作为符合第 6 节的机制：

| 算子族 | 必需解释与限制 |
|---|---|
| 必需信息检查 | 用明确且适用的政策对照已建立条目；不得推导“八类普遍必需”。 |
| 区间与数量检查 | 固定单位、维度、域及受约束活动；区分总量、单任务限制与截止时间。 |
| 类型化集合 | 固定身份、成员关系与封闭范围；未提及不自动表示非成员。 |
| 交接检查 | 在适用守卫下匹配同一产物身份／版本、生产者与接收者。 |
| 依赖检查 | 环对严格必需先后关系构成矛盾；其他关系类型的环需要各自的语义。 |
| 布尔与线性约束 | 固定原子含义、合法域和完整查询编译；SAT、UNSAT 是数学结果，不是权限。 |
| 规格比较 | 要求明确映射、沉默政策、分支行为、环境覆盖与共享约束。 |

扩展此清单的算子 Profile 必须给出自己的支持语言、证据合同及未决行为。出现在清单中，不表示已经实现、具备数学完备性或获得实测性能结果。

## 13. 权限边界

**BXP-AUT-001** 结果、诊断、修订建议和准入记录不得产生业务裁决或执行权限。暴露下列字段的所有符合协议的传输对象，必须保持：

```json
{
  "business_decision": null,
  "execution_authorization": null
}
```

来源可以声明外部批准事实，模型可以把它用作条件。但 BXP 不会仅因完成解析就认证该事实。证据信任、凭据检查和外部批准由宿主负责。任何符合性阶段都不得把 `determined`、`preserved` 或 `admitted` 重新定义为执行许可。

## 14. 版本、配套资产与迁移

**BXP-VER-002** draft.1、其冻结配套修订、历史 0.3 资产、来源任务及证据，必须保留原始字节与身份。draft.2 是新的评审基线。不得只替换 `protocol_version` 或用默认值填补缺失语义字段来迁移旧对象。

本修订包含规范正文、中文译本、发展依据与迁移说明、阶段／Profile 索引及规范状态规则。它不冻结完整的 draft.2 任务／结果传输 Schema 或专用发布政策。随附机器描述文件记录规范合同，不是运行时注册或实现发布。draft.1 Schema 继续绑定 draft.1。

实现声明某能力阶段符合 draft.2 之前，必须版本化受影响的 Schema 和 Profile，实现并测试该阶段的不变量，保留精确代码及依赖快照，并标明支持和不支持的操作。准入声明还要求宿主执行约束和精确发布绑定。自然语言覆盖与准确率需要独立限定范围的评价；历史开发记录及结构化向量不建立这些结论。

迁移必须检查关联保留、条目／视图状态归约、来源问责缺口、语义依赖、运行与结果分离、比较对象类别及发布绑定。无法映射的内容必须保留为明确迁移缺口。重新验证不得改写历史结果，也不追溯认证旧结果。

[迁移记录](MIGRATION.zh-CN.md)列明新增与澄清内容；[发展依据](DEVELOPMENT-TRACE.zh-CN.md)列明仓库证据，并区分规范决定与已实现能力。

## 15. 稳定的协议核心

```math
\boxed{\mathcal C\longrightarrow\mathcal M\longrightarrow\mathcal B
\longrightarrow Admission}
```

BXP 的稳定核心是在表示、形式化、确定性计算和精确版本准入之间，保持并共同解释任务边界信息。七类任务视图和独立禁止视图组织这些信息，共享结构保留其关联。Profile 限定支持的操作，不替代这一合同。宿主执行发布准入约束，权限仍在求值器之外。

识别方法、编译器和求解器可以独立改进；没有明确版本化修订，这些改进不得改变协议含义。
