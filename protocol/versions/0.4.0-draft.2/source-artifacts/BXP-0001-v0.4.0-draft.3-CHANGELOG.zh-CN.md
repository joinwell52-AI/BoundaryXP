## 3. 三处主要合同如何收口

### 3.1. 数学结果与边界状态

修订稿明确区分：

- 规范数学求值内容：固定形式输入与计算合同下的查询及其数学结论。
- 固定评估上下文：解释范围、覆盖依据、必需信息政策、证据核验／接受情况和查询完成情况等。
- 整体边界结果：结合以上输入得到的边界状态、约束内容和来源绑定。

因此，相同形式模型可以得到相同数学结论，但一份材料已建立来源覆盖、另一份尚未建立时，整体边界状态仍可能不同。该差异有明确的上下文输入，不构成数学求值不确定。

求值函数还显式接收本次精确查询清单。仅固定模型和算子 Profile，不足以固定本次问的数学问题；例如在模型 x=1 下，询问“模型且 x=1 是否可满足”与“模型且 x=2 是否可满足”，虽然都是 SAT 查询，结论不同。清单固定精确查询，评估上下文同时绑定协议、状态归约规则修订与必需查询覆盖要求。

这是一项协议对象与责任分界，不要求将求值和评估部署成新的独立服务。

### 3.2. 部分载体状态

原三态 `resolved`、`unresolved`、`absent` 保持不变。

当 `Accounted(S)` 尚未成立时，不能给该视图提供最终聚合状态。采用 `status` 字段的表示省略该字段，并在独立归约元数据中保存“归约未完成”及具体覆盖诊断。它不使用 `status:null` 或第四种状态替代。

八类视图的结构位置、已经建立的条目与关系仍然保留。某些视图已经完成归约，不要求其他视图同时完成。完整的字段布局仍由版本化 Schema 固定，本次没有发布完整 Schema。

### 3.3. 逐情境可满足与因果可实现

原有覆盖公式保留：

```math
Coverage(\Pi)\iff\forall e\in E_{adm}\;\exists u:H_\Pi(e,u).
```

它说明每个固定情境分别存在相容实现。若较早动作需要依赖未来才可获得的信息，不能仅据此声称已经证明运行策略存在。

一个说明性反例是：先选择比特 a，随后才获知不可提前知道的外部比特 b，要求 a=b。此时：

```math
\forall b\exists a:(a=b)
```

成立，但事前固定选择所需的：

```math
\exists a\forall b:(a=b)
```

不成立。这里的第二个公式仅用于这个先选择、后获知的单步反例，不能作为一般交互策略的定义；普通任务可能允许观察环境后选择不同动作。

修订稿保留关系层 `preserved` 等结果，同时要求声明是否包含因果可实现性。发布条件若要求该能力，尚未建立的因果依据必须阻断相应发布。基础协议不强制引入通用策略求解器。

## 4. 正文新增的两个说明例

### 4.1. 局部资源约束不能代替总量约束

父任务要求两个子任务合计资源消耗不超过 10 个单位，候选只规定每个子任务最多 6 个单位。

两个局部约束都可满足，但资源取值为 6 和 6 时违反父要求，取值为 4 和 4 时符合父要求。在其他有效性与覆盖前提成立时，该候选属于 `not_guaranteed`，而非候选不相容或整个分解已经保持。

该例位于第 5.3 节，说明局部和联合检查各自承担的责任。

### 4.2. 环境范围不能由候选自行缩小

父任务在本次委派范围内要求处理正常与故障两种情境，候选只处理正常情境。比较必须保留父任务的适用环境要求，不能仅检查候选自报的正常情境便宣布完整保持。

如果父任务通过明确守卫仅委派正常分支，该局部范围可以成立，但完整分解仍须覆盖故障分支。该例位于第 11.2 节。

## 5. 批准单版本案例的建模约定

以下为实施时可采用的说明性案例，未在本次交付中注册为规范向量或执行产品测试。

场景：R-old 仅批准 rc331，本轮拟部署 rc332，当前比较情境明确没有适用于 rc332 的批准。

定义：

- d：执行本次 rc332 部署。
- a：在固定比较时点与情境下，存在经宿主认可且适用于本次候选版本、目标、动作和条件的批准事实。
- 父约束：d 蕴含 a。
- 当前事实：a 不成立。

| 比较对象 | 候选约束 | 正确诊断 |
|---|---|---|
| 原始拟执行方案，对照父约束检查 | 要求部署，并固定当前没有适用批准 | 候选存在实现，但全部违反父约束，属于 `necessarily_violating` |
| 已继承父约束的有效子合同 | 同时要求“部署需批准”“执行部署”“当前没有批准” | 候选不相容／不可实现，不能用空真蕴含报告保持 |
| 实际执行观察 | 需要充分的执行事实及适用批准证据 | 根据观察充分性判断具体执行；不能仅凭拟方案宣称部署已经发生 |

参考 Profile 必须事先固定比较对象类别、继承政策及批准事实的时点和作用域。求值器不能为了偏好的状态临时选择建模方式，也不能自行创造未来批准。前两种对象均不能满足相应正式发布要求，但应保留各自准确的数学诊断。

## 6. 保持不变的约束

- 7+1 的视图定义与独立禁止边界 B。
- 八类结构位置必须存在，内容不要求普遍非空。
- 已知不确定性、不支持内容和来源缺口必须保留。
- 角色、岗位、模型偏好和相似度不能产生操作权限。
- 形式化不得增加无依据要求或遗漏承载边界的要求。
- 辅助变量编码必须保持完整查询语义，不能把分别等可满足的编码任意放入否定。
- 候选为空时不能空真通过；局部通过不能替代整体保持。
- `determined`、`preserved` 和准入成功均不授予业务批准或执行权限。
- 来源、解释、依赖、比较基准或发布证据变化时，受影响旧准入不能直接复用。
- 历史结果继续保留原身份，新修订不追溯认证旧实现。

## 7. 文档校验与实施边界

本次核对范围包括：版本及历史引用、规范条款编号、视图定义保留、数学对象与公式联动、部分状态规则、内容身份与重放要求、正文与说明的文件链接，以及新增示例的数学分类。

说明性资源例、批准单模型和单步因果反例进行了有限枚举核对。这些核对用于发现文本及示例的逻辑错误，不构成现有 BoundaryXP 产品实现通过 draft.3 一致性测试的声明。

本次没有提供或修改：对应英文规范稿、完整任务／结果 Schema、运行注册配置、专用发布政策、生产代码或现有产品测试结果。

后续实施应先固定一个范围明确的参考 Profile，将支持的输入、查询、继承与沉默政策、状态对象、规范化、证据接受条件和准入绑定写入可重放合同。自然语言理解与覆盖准确率仍需要独立、限定范围的评测。

以下是建议纳入参考 Profile 的验收主题，属于待实施验证项：

| 主题 | 预期行为 |
|---|---|
| 条目均已解释，但约束矛盾 | 区分视图状态与整体不相容 |
| 来源覆盖不足、视图暂时为空 | 保留部分对象，不伪造 absent |
| 两个模型均 SAT，但边界不同 | 不得据标签相同判为语义唯一 |
| 相同数学内容、不同覆盖依据 | 允许整体状态不同，并固定其上下文绑定 |
| 候选自身不可满足 | 报告候选不相容，禁止空真保持 |
| 候选允许符合与违反行为 | 返回 not_guaranteed |
| 父任务要求的情境未覆盖 | 阻断完整保持声明与相应发布 |
| 局部成立、联合资源或交接不成立 | 保留全局失败，不提升局部结果 |
| 旧候选批准用于新候选 | 检查适用身份并阻断，保留对象类别对应的诊断 |
| 超时、unknown 或不支持 | 不伪造数学结论或完整结果 |
| 精确版本或发布证据变化 | 受影响准入重新建立 |
| 动作依赖未来未知信息 | 保留关系层结论范围，单独处理因果可实现性要求 |
