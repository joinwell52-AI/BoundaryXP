# BoundaryXP 数字来源与取证边界

> 当前协议文档身份以[固定基线](baselines/0.4.0-draft.2-20261027-r2/README.md)中的 SHA-256 为准。相同数学结果要求相同完整求值合同与查询；整体结果还依赖相同评估上下文 Θ。摘要证明内容身份，不证明解释正确、证据真实或执行权限。

本文件规定 BXP 规范资产的可验证来源机制。目标是证明“某个字节序列在某个版本已经存在”，不是通过破坏数学语义制造隐藏行为。

## 允许的来源证据

1. 规范、Schema、向量套件与来源索引的 SHA-256 内容摘要；
2. 稳定、不可复用的测试编号；
3. Git 提交、签名标签或受信时间戳服务形成的公开时间链；
4. `boundx-provenance-manifest/v1` 清单中的字节数、摘要和套件 ID 集摘要；
5. 私有挑战集的独立加密存证，前提是测试行为完全符合公开 BXP 规范。

## 禁止污染规范语义

BXP 核心实现不得为了“留指纹”而：

- 在精确区间计算中加入未公开的 epsilon、质数偏移或舍入偏置；
- 增加会改变解析结果的秘密文法或秘密默认值；
- 伪造业务实体、输入、授权、异常或审计事件；
- 让私有反例期待一个与公开规范不一致的结果；
- 把相同规范输出本身当作复制代码的充分证据。

这些做法会削弱一致性套件的公信力，并可能伤害使用者。独立实现只要遵守同一规范，本来就应产生相同结果。

## 私有挑战集

私有挑战集可以包含公开规范允许但组合罕见的合法输入，例如深层布尔组合、Unicode 码点边界、开闭端点相等、不同依赖边类型混合和同名制品身份未决。它必须满足：

- 不进入公开向量或开源构建产物；
- 不含客户数据、凭证、未授权第三方材料；
- 预期结果由公开规范唯一导出；
- 每次变更有独立复核、内容摘要和可信时间记录；
- 只在自有系统、获授权系统或明确开放的测试接口上运行。

未经授权不得探测、绕过限制或向第三方生产系统批量提交挑战输入。相似错误码、遍历顺序或输出结构只能作为调查线索，不能单独证明侵权；正式主张应交由有资质的知识产权律师结合源码、访问记录、时间链和独立专家意见判断。
