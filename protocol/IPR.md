# Boundary Xplain Protocol IPR Policy Draft

状态：`DRAFT_FOR_REVIEW`。本文件用于在公开前暴露权属和披露问题，不构成法律意见，也不表示已经完成专利、商标或标准组织程序。

面向首版小工具的许可、公开范围、数字来源和行业资产安排见 [《BoundaryXP 轻量产品与发布方案》](../docs/BOUNDARYXP-LIGHTWEIGHT-PRODUCT-PLAN.md)。该文件当前同样不改变许可证或授权公开。

## 1. 当前资产分类

| 资产 | 当前建议 |
|---|---|
| 协议文字、Schema、图表 | 保留作者、年份、版本和提交记录；适用仓库现有许可证，除非后续文件另有明确许可 |
| 最小校验器与一致性运行器 | 作为可复现参考实现；适用仓库代码许可证 |
| 公开规范向量 | 允许互操作验证，但必须保留来源和版本 |
| 自然语言编译器 | 可作为非公开商业实现 |
| L2/L3 语义资产 | 按来源、授权、租户和许可证分别治理 |
| 私有对抗测试集与调优数据 | 作为商业秘密候选，限制访问并记录使用 |

## 2. 公开前门禁

公开 BXP 技术细节前必须完成：

1. 作者、雇佣关系、委托关系和第三方贡献权属确认；
2. 现有论文、专利、开源协议和标准的先前技术检索；
3. 是否申请专利及申请地域的书面决定；
4. “界痕”“BoundaryXP”“bx”名称、商标、域名和软件包冲突检索；
5. 协议文字、Schema、测试数据和参考代码的许可证确认；
6. 对外发布内容与继续保密内容的清单。

在上述记录完成前，仓库中的 `publication_authorized: false` 不得改为 true。

## 3. 专利披露

任何参与者如果知道其专利或申请可能覆盖 BXP 的必要实现，应尽早向维护者披露专利号或申请号、权利人和可能覆盖的章节。披露不等于承认专利有效或必要，也不自动形成许可。

是否采用免版税承诺、合理非歧视许可或其他模式，必须在 1.0 Candidate 前由权利人和法律顾问明确，不得由代码贡献或 Git 合并推定。

## 4. 贡献记录

每项规范性改动必须可追溯到提交者、评审者、提交时间和变更依据。引入外部术语库、标准文本或测试语料时必须记录许可证、版本、下载来源和允许用途，不能仅写“来自公开网络”。

## 5. 不授予的权利

除适用许可证明确授予的权利外，本草案不授予商标、认证标识、专利或商业服务权利。实现协议不等于获得“官方”“认证”或“BoundaryXP Approved”身份。
