# 独立核对比较

特别核对已选支出预算与父额度上限：父任务限定同一活动全部支出上限，该上限约束子任务为同一活动确定的预算、费用安排和额度分配。确定的子预算超过父上限属于规划额度越界，不需要实际付款证据。不得接受“预算不等于实际支出，所以超额确定预算仍相容”或“父限制继承后自动缩小子预算”的解释。先核对资源、币种、对象、窗口和费用关系；仅背景报价、未选参考估算、收入或其他活动金额不能混同为本次确定支出。对有来源的数额映射，要求候选提供budget等程序操作数并核对端点；不由审阅者改写候选或伪造操作数。

内部coverage登记错误与边界差异分开：若某coverage标记不当，但原文限制已由accepted_checks中的对应比较或继承关系保留，且不影响越界结论，不将它放入issues。另用diagnostics:[{"category":"COVERAGE_RECORDING_ONLY","coverage_id":"v1","reason":"登记错误及为何不影响已有边界比较"}]保留。必须引用候选中实际存在的coverage ID；不能以此掩盖子任务遗漏比较、父限制被取消、操作数来源错误或实质语义分歧。这些仍列issues并关联实际check；没有关联check的真实边界问题仍须说明具体差异。诊断不能撤销已成立的越界。

唯一裁定目标：子任务及其组合有没有突破主任务边界。拒绝把“尚未执行、无法证明已完成、未来执行者或权限尚待确定”混入文本越界判断。文本保留父方前提与禁令时，实际执行证据缺失不妨碍判断其相容。外部PLAN正文未附只在具体边界差异确实依赖该正文时才未决；不能仅因引用外部文件而把已提供的文本整体置为未知。对每个UNRESOLVED检查是否明确给出了无法判定的父子边界差异。

任务级“全程记录”等义务持续有效，不因没有另建PM任务或逐角色登记消失。coverage.retained_work可用task_wide:true与逐字引文表达任务级义务，不要求虚构actor。若候选missing仅基于未登记、未执行，审阅否定该missing时，用issues项 {"category":"REJECTED_MISSING","missing_id":"m1","reason":"原文义务仍保留的具体依据"} 记录分析纠正，不再把已否定的缺失制造为新的未决；accepted_missing_ids不得包含该项。若确有无法判定的边界差异，仍用普通issue明确说明，不能靠REJECTED_MISSING抹掉冲突。

完整读输入节点原文、条款、任务树和比较候选。检查每项语义对应及 operation 操作数是否真实来自引用条款；特别核对范围、单位、累计窗口、实例去重、排他关系、条件方向、时间起止、通过与结束的区别。子任务不承担全部父责任是正常分工，不能为凑覆盖把父要求补入组合。

同时检查操作数接口完整性。interval_subset必须有dimension、unit，parent与child都须显式包含lower和upper；未限制的一端必须是null，有界端须含value数值字符串与inclusive布尔值。仅给upper而省略lower不能接受；不得替候选补0或改写操作数。固定值用两端同值且inclusive:true表示。格式错误关联对应check写明具体中文原因，不能只凭语义正确就接受不可复算的操作数。

时间口径按完整原文核对。共同启动点、连续执行和全部完成即结束已限定整体经过时间时，不接受脱离上下文臆造“也许指累计工时”而产生的未决；明确同起点并行应核对最长完成时间。相反，原文明确累计工时、人时或设备占用量时，即使并行也不能取最大值替代累计。核对起点、结束、先后/重叠的来源引用；真正没有这些关系或存在相互冲突口径时保留具体缺口，不为消除未决强行选一种计算。

必须分别核对“子原文自己的条件”与“适用上级条件”。当前检查是规划文本是否保持父边界，不是把二者先合取后检查有效授权。子文本未重复禁令可继承；子文本明确将父方“两份均提交后”改写成“任一份提交后”，则应保留原文条件放宽差异，不能添加父条件把差异消掉。此差异不表示已经授权或实际发生了提前执行。

例：父启动前提 d∧o，子明确写出的启动前提 d∨o。检查原文条件保持关系 (d∨o)⇒(d∧o)，存在 (1,0)、(0,1) 两类反例。即使子文本同时说“适用父任务约束”，也不能用 ((d∨o)∧(d∧o)) 替换子原文操作数并抹掉差异。可以另述实际适用边界仍受父约束，但不能据此否认原文变更。检查“通过”改成“结束”、明确许可父禁令时同理。这个检查既不把必要条件改成充分许可，也不要求为所有可能执行构造见证。

父原文明示由父方承担的具体责任继续有效，无需人工登记或另建PM子任务。核对coverage.retained_work的主体、动作、逐字引文及父条款来源；不得将组织责任扩大为PM亲自验证，也不得把父任务全部复制进组合。客户没有填retained不是缺失证据；QA不承担终报不等于PM终报被取消。明确取消或放宽父条件的子原文仍须指出。

对missing逐项核对parent_work_reason：排除父方和全任务仍保留的义务后是否真的缺失，而非未执行、未来可能失败或未人工登记。相同缺失只列一次。对coverage检查所引部分是否覆盖整项责任；对affected_axes只接受实际受影响维度，不能复制所有引用标签。混合建议和禁令不得整体当成非义务。只保留真正影响边界比较的信息缺口。

核对混合条款的部分保留与部分取消：具体取消可直接由checks判定，不应再复制missing。coverage只对应父条款的一部分时须显式coverage_scope:"PARTIAL"，不能按整条覆盖接受；PARTIAL登记不消除其余义务被取消的越界。若候选同时声称整条覆盖与整条缺失，则拒绝矛盾映射；不能用部分已交付掩盖另一项明确取消，也不能把仅仅部分登记当成真实越界。

输出 JSON：{"contract_version":2,"accepted_check_ids":[],"accepted_coverage_ids":[],"accepted_missing_ids":[],"issues":[]}。仅对确实核对一致的 ID 列入 accepted；接受包含本项责任归属与affected_axes的核对。问题用 {"reason":"具体问题","check_id":"可选关联ID"}；没有关联check时省略check_id，不借用无关ID。漏掉子条款、祖先限制或联合责任也须指出。不得把未知关系当作空集或已符合，不重复长篇理由，不重写候选。旧候选没有contract_version:2时，不仅靠审阅声明将其升级；需重新按新版依据比较。

## 父边界比较的范围及去重

只判断有没有突破主任务边界。节点内部矛盾、抽取诊断或保留工作登记问题不等于边界差异。对单独INCONSISTENCY项的纠错保留为诊断，不要求把它变成父子越界或未决。对同一数额的相互冲突固定值，各值分别与父上限比较；不得相加、假设互斥或要求证明子方案可执行。有正确逐值操作数且各值未越父限时，可以接受边界相容；子方案内部矛盾仍保留，不能宣称整体通过。

审批等发布/访问/调用许可前提的放宽主要影响A，有明确未获批禁令同时影响B；不是任务完成或停止判据时不能仅因有条件词就标C。只接受按实际变化选择的affected_axes。

交付产物的接收者、公开范围、去向或必需交付集合改变时，主要维度须包含O。接收者出现角色名称不等于只属P；不能接受用P/A替代O的映射。有明确外发禁令时同时核对B；额外P/A须有实际责任/动作变化依据，不机械扩散标签。

源条款有旧审阅争议时，允许核对候选source_rechecks。逐条验证node_id、clause_id、issue_index对应真实审阅问题，quote逐字来自该节点原文且等于该条款一段完整证据；reason能否从该原文解决此争议。只有真实消除抽取偏差、未绕过未知事实和计算问题时，列入accepted_source_recheck_ids；同时单独核对引用该复核的checks。拒绝或遗漏的复核不能生效，不修改旧条款或旧审阅。

如果祖先检查已报告一个子任务的同一违规，组合重复该违规不应再次计数。对候选duplicate_of，只有相同父限制、同一越界原因、无新增数学操作或冲突时，将重复check.id列入accepted_duplicate_ids；累计超额与各节点单独比较、不同父限制不得合并。费用关系缺失优先一项组合未决，不重复展开相同缺口。

输出可附accepted_source_recheck_ids:[]、accepted_duplicate_ids:[]。真实无法确认的父子差异仍列issues并写具体中文原因；不要只因为内部诊断或缺少保留工作登记而阻断已明确的父边界比较。
