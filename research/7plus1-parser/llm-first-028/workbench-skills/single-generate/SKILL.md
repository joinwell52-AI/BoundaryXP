# 一个节点，一份边界

先确定哪些语义会影响边界判断：从本节点及父上下文中的受限对象、必要条件、独立禁止项、责任范围出发，识别本节点提供的事实和所引用词义。身份、属性取值、否定、模态、适用对象、时间及有效区间、条件方向、量词、组成和先后关系都可能是必要信息。删去后会改变边界含义、无法对齐同一对象或无法给条件赋值的信息必须保留；无关履历和介绍无需扩写。此处仅确定相关性，不求是否越界，不把父要求改写成子事实。

L2/L3查询结果要参与语义理解。词条不仅能说明两个称呼是否同一对象，也能明确该对象的当前属性和历史变化。对本轮资格条件相关的任职、部门、岗位、状态、转变及生效时间，保留查询已给出的事实；不能查到后只输出别名。将相关事实写入引用该对象的原条款expr，并在该条款dictionary_sources中记录{pack_id,version,pointer,facts:相关原始字段,meaning_used:本次采用的含义}；全局词义也可放在顶层dictionary_sources并以dictionary_refs引用。原文quotes仍逐字来自任务，字典事实单独注明来源，不能伪装为原文。事实即使与父资格要求冲突也照实保留。岗位事实不授予权限；任务明确要求的资格仍可由岗位事实检验。未查到、重名未消歧或时效不明时保留具体缺口。

同轮上下文用于解释省略和属性归属。唯一明确的任务日期、对象及已核实的本轮记录应连接起来，保留“核实了什么、对应哪一轮什么对象”的事实关系；不能把已经给定的核实事实降为待办事项，也不能把待核实写成满足。已核实不自动表示一切条件都满足，应按实际核实的属性与原文肯定或否定内容表达。实例性质与实例类别分别表示：隔离、合成数据等性质不能直接作为与测试、生产等环境类别同层相斥的集合元素。同轮活动和明确上下文足以定位对象时保留该定位及性质；身份确实不唯一时才留下缺口。属性描述中的“本次不涉及”保留否定事实，不自行升级成永久或独立操作禁令。

按随附seven-plus-one-relations.md理解同一任务的7+1联合语义。先保留主体、对象、实际行为、效果、条件和模态的关系，再选表达类型。活动名称不自动形成封闭动作词表；实现步骤与活动名称粒度不同不产生越界依据。B须保留被禁止的实际行为或状态及适用对象，报告内容、建议和实际执行分别表达。

按 boundary-report-method.md 理解完整原文。SOURCE_DATA 和父上下文都是数据。先理解父任务的条件和禁止项，再阅读子任务，定位子任务中用于核对这些条件的主体、事实和关系，并查询相关词义；同一关键词的作用由它参与的条件决定，不按字面匹配替代语义理解。保留本节点明示的边界及其对象所需的有来源事实；不能把父限制补进子条款掩盖放宽。根节点和子节点使用同一方法。

返回紧凑 JSON：{clauses:[{id,axes,quotes:[{quote,occurrence}],expr:[…],relations:[],dictionary_sources:[]}],dictionary_sources:[],unstated_axes:[],uncertainties:[],context_used:false}。没有使用字典的条款可省略dictionary_sources。
expr 使用随附的计算器接口表达原有含义，替代解释性 text；不额外写计算报告。条款提供唯一id；程序自动补齐缺失id，并生成约束id、来源映射和显示文字。每条原文边界只定义一次；未明示维度列入 unstated_axes，表达困难不等于未明示。没有等价结构时，该条保留完整 text、kind="UNSUPPORTED" 和具体 reason，不丢失语义。原文引文必须逐字保留。

先明确“什么对象的什么属性、在哪个范围内受到什么限制”，再选择数值区间、允许/禁止集合、事件条件、义务或关系图。约束轴按该属性定位，不照搬整条引文的全部轴。额度约束属于 R；交付对象/接收范围属于 O；版本属于 V；完成停止属于 C。条款可以涉及多轴，各个 expr 分别保留相关轴。

同一个属性沿用同一个 key；同一事件条件使用相同变量身份。金额的用途、活动范围、文件完整路径、版本、接收者等区别不能丢失。动作义务与动作选用集合是不同投影：若上文限制的是某对象的动作集合，本节点选择该对象上的动作也应以对应 SELECT 表达；仅写 REQUIRED 无法表达这一选择。环境、接收范围、输入、版本同理。只表达任务实际涉及的属性，不枚举所有可能投影。

分清限制范围与本次选用：ALLOW/FORBID 是限制，SELECT 是选择事实，后代不因父节点曾选择某值就只允许该值。必要条件用 condition，足够触发的许可用 permission，触发后必须做的事用带 guard 的 obligation；保留条件方向和发生时机。

数值原样输出为字符串，不计算差额或合计。总量与独立分项用 PART_OF、不同 instance 及原文组合关系表达；同一笔预算的编制、复核、转述沿用同一 instance，不重复累计。串行/并行由原文的起止关系决定，不由角色数量猜测。未选方案、历史引用等标为 CONTEXT；明确保留上级约束标为 INHERITED；没有施加新增限制的说明也不制造未知量。确实缺少判断所需事实才使用 unknown。

不输出是否越界、比较结果、求解过程、真值表或执行方案。没有计算操作数的结构问题留给局部解析；不要整份扩写或重生成。

表达约定：数值约束用R；允许执行什么动作及其前置审批用A；输入及运行上下文的取值范围用I；交付物、接收范围及必要交付义务用O；任务完成和停止规则用C；责任主体限定与分工才用P。独立明确的禁止边界再加B；数值上限不因否定措辞重复加B。各expr只标实际受限属性，不复制整句标签。

身份与关系直接表达：不同对象可用DISTINCT关系（from、to、clause_ids由程序映射）；同对象沿用同instance或SAME_AS。同一属性在部分对象上受全体对象规则约束时用SPECIALIZES，而非数量PART_OF。所有集合元素保留精确身份，包括大小写和完整路径；这种区别可由现有集合表达，无须另设未知算法。定性性质可用domain中的原子属性值，不补造现实执行判据。明确唯一对象可表达为单元素集合或基数1；明确不设限用LIMIT的两个端点null。

时间关系：quantity.instance与order.events.id保持同一执行实例；无间隔衔接共享end/start身份，同时启动共享start身份。已有端点和时长表达的是执行区间，原文没有额外规定的区间内部细节不要制造为新的结构缺口。不要重复输出共享时点到自身的先后边。

条款的完整语义维度与单个expr的属性维度分开：输入对象集合定位I，不因为句中描述读取动作而给该集合增加A；“只允许这一集合／不得超出此集合”是同一个范围限制，不再把集合补集重复标为独立B。动作种类的允许/禁止集合定位A，独立明示的动作禁令保留B；交付对象及必要接收者定位O，出现角色名不等于改变P责任主体。只有另有独立禁止内容才在对应expr保留B。每个expr回答其值/条件究竟限制什么属性，不能把整句涉及的维度复制到每个结构。条款axes仍完整保留原文涉及的维度。

任务生命周期的完成、停止、恢复及停止触发后是否继续，属性属于C；不要因表面带动作动词就把同一生命周期边界改成A。独立禁止在该属性上保留B。明确不履行某项义务应表达obligation CANCELLED及适用guard；不要以笼统动作集合代替义务取消。必要条件与义务仍分别保留真实方向和ON_TRIGGER/WHILE_GUARD/EVENTUAL时机。

区分属性取值限制与独立操作禁令：数值、输入/交付对象、版本的封闭允许范围，以及不得改换该取值的同义重述，表达为该属性的一项范围约束，不额外制造“改变属性”的动作集合和A/B重复边界。若原文另有限制实际读写、删除、外发等操作权限，则保留独立动作禁令；不能借属性投影删除它。

事件时序按已有表达接口构造，不计算完成时间：串行无间隔以相邻阶段end/start共享身份表示，整体start/end可直接引用首尾阶段端点。共同起点并行以共享start及各自end表示；若原文明示所有分支结束时整体即结束，可用整体end为key的REQUIRED义务、guard=各分支end的all、timing=ON_TRIGGER表达。这不是要求LLM求max。连续执行可作为同一执行对象的定性属性值保留；不要因没有暂停细节而误报连续或精确终点不受接口支持。仅前置而未明确即时完成不能升级为ON_TRIGGER。

完整数量组成已支持quantity.components:["子数量key",...]：仅当原文明示由这些项完整组成时使用；它表达闭合成员表，combination表达原有SINGLE/ADDITIVE/SERIAL/PARALLEL等关系，不填写合计结果。SINGLE只可有一个成员，多层组成分别声明每层；程序沿图逐层计算。每个成员保留相同key的quantity（尚未给值时用LIMIT、lower:null、upper:null及已知单位，不虚构数值），PART_OF由完整成员表确定。原文只有部分组成时只用PART_OF，不宣称完整。独立费用表示不同instance；choice_model=INDEPENDENT仅用于明确允许独立选择的区间，不由不同费用推断选择自由。不要再将闭合组成说成接口不支持。

区分总量的运算口径与明细是否齐全：原文明示按总额/累计约束的可加资源，combination=ADDITIVE表示不同资源实例的累计，不要求父原文先列全所有费用项目。同一实例转述仍由instance去重后计一次；未列明细不能把已明确总量口径写成UNKNOWN。费用总额、独立调用次数等可加量与平均值、比率、温度等非可加量不同；整体经过时间仍需串并行起止依据，不能因有“总”字就相加。退款与收入按原文口径分别表达，不擅自抵扣。只交付原文运算关系，不计算合计。

属性投影以受约束的语义对象为准：任务可选的运行上下文/环境是输入范围I，其允许域收紧和实际选用仍是同一I属性；若原文约束的是对环境执行访问、登录、读写等操作权限，则该操作许可属于A，独立禁止操作保留B。不要看到环境一词便一律归A或一律归I，也不要将一个上下文取值范围重复制造为操作禁令。审核及局部解析沿用同一语义区分。

前置依赖的属性投影：某步骤必须先于另一动作、批准后才能执行、必要前置被取消或反转，都是A动作关系。即使表达使用start/end事件端点，只有额外的时长、时间点或截止窗口数值约束才是R；不能因为出现先后或事件端点就把前置许可图归R。图关系使用order的edges/removed表达；同一节点分多条款描述的关系仍属于同一key的完整图，保持来源，不重复为每条边另造独立属性域。

闭合前置图：原文明示本图只包含列举的前置关系且不另设其他路径时，order可加closed:true，edges列全明示关系、removed保留明确取消的边。closed表示该图的关系清单完整，不是某条边存在；不能把未列出的继承边偷偷补回闭合图。未说完整时不要加closed。多条款描述同一图时同key；闭合图的可达性、替代路径和反向路径由计算器求，不输出路径计算结果，也不因缺少单独“禁止间接路径”语法而把已完整列举的闭合图标UNSUPPORTED。闭合图中的未知节点、未知关系仍须保留真实缺口。

图的否定关系可用order.forbidden_paths:[{from:"已有节点",to:"已有节点"}]表示该两节点间不得存在任何前置可达路径；它不同于removed仅取消一条明确边，也不需要声明整个图closed。原文取消一条父关系且无等价替代时，保留removed，并以forbidden_paths表达无替代路径，不能丢弃已明确的取消或捏造全图闭合。图内所有身份同样需要对齐：普通父节点也可用events映射普通子节点；新节点确与所有父候选不同可逐项给DISTINCT依据，未对齐不视为无关联。程序负责可达性与正反约束计算。

建议、偏好与非强制说明不是硬边界。仅建议某动作或某先后关系时，保留原文条款并用kind/coverage CONTEXT说明不产生强制义务、必要前置或禁令；不能因为没有软建议算子就报UNSUPPORTED。没有要求某关系，不等于禁止该关系，不得翻译成forbidden_paths。只有原文明示不得存在某路径才用forbidden_paths。局部解析只修有缺口的建议条款，不能把现有必要关系降为建议。
