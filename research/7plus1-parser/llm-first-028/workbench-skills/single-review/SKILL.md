# 核对表达，不替计算器判断

先核对影响边界判断的语义是否完整：对象身份、事实与要求的区别、当前属性与历史变化、有效时间、否定、条件方向、责任范围和数量关系。用本节点及父上下文确定哪些事实与资格或禁止条件有关，再双向核对这些事实的原文和所用L2/L3词条。确认别名对应不等于完成词义审阅；如果查询已给出相关部门、岗位、状态及生效时间，而候选只保留姓名或ID，应指出遗漏并要求在原对象条款及dictionary_sources中补回事实。岗位事实用于核对任务明示资格，不因此新增权限、禁令或责任。保留不满足父条件的事实，不替任务修正人员或安排。

核对已确认记录是否保留其具体对象、轮次、日期与属性关系，不把已给定的事实重新变成待办。核实状态应按本轮具体语境解释，不一律扩成满足全部条件，也不脱离上下文要求重复陈述已明确内容。检查实例性质和环境类别是否被错放为同层互斥成员；检查“本次不涉及”的事实是否被改成操作禁令。原文和词条都已明确的关键语义不能只留引用编号而没有含义或事实字段。审阅指出具体缺失语义，不要求预先计算答案。

按随附seven-plus-one-relations.md核对跨维度语义。检查是否凭活动名称造出封闭原子动作白名单，是否混淆活动及实现步骤，是否将建议、引用或内容当作实际执行，是否保留B对具体对象和行为或状态的约束。集合类型合法不证明该集合有来源；不得把不同粒度的动词强行视为同层可比较身份。

按 boundary-report-method.md 双向核对完整 SOURCE_DATA、候选条款及 formal 结构。候选显示文字可由原文引文机械生成，约束含义以结构与原文的对应关系核对。先理解父条件，据此核对本节点相关事实、身份与省略是否完整；不得静默向子节点添加父约束，也不得为满足父条件改写实际事实。

检查遗漏、多加、对象与属性身份、数值端点、单位、独立分项和同一实例、集合限制与选择、条件方向和触发义务、先后关系、责任及接收范围、来源引文。背景和未选方案不当成当前选择；未知事实和未能结构化是两种不同情况。只校验当前原文实际表达的属性，不要求为每条生成全套类型。

输出 {"status":"NO_ISSUES_FOUND","issues":[],"scope":"简短核对范围"}。问题用 ISSUES_FOUND，issues:[{clause_ids,reason,suggestion}]，建议仅修改有问题部分。漏项没有条款 ID 时用空数组。无法结构化但已完整保留原文和具体缺口，不因缺少计算结论判错；不得要求生成总和、是否越界或执行方案。审阅无问题不是正确性的数学证明。

条款的完整语义维度与单个expr的属性维度分开：输入对象集合定位I，不因为句中描述读取动作而给该集合增加A；“只允许这一集合／不得超出此集合”是同一个范围限制，不再把集合补集重复标为独立B。动作种类的允许/禁止集合定位A，独立明示的动作禁令保留B；交付对象及必要接收者定位O，出现角色名不等于改变P责任主体。只有另有独立禁止内容才在对应expr保留B。每个expr回答其值/条件究竟限制什么属性，不能把整句涉及的维度复制到每个结构。条款axes仍完整保留原文涉及的维度。
发现属性投影多加或漏加时，仅指出对应条款和约束；不改变原数值、集合成员、条件方向或关系。

任务生命周期的完成、停止、恢复及停止触发后是否继续，属性属于C；不要因表面带动作动词就把同一生命周期边界改成A。独立禁止在该属性上保留B。明确不履行某项义务应表达obligation CANCELLED及适用guard；不要以笼统动作集合代替义务取消。必要条件与义务仍分别保留真实方向和ON_TRIGGER/WHILE_GUARD/EVENTUAL时机。

区分属性取值限制与独立操作禁令：数值、输入/交付对象、版本的封闭允许范围，以及不得改换该取值的同义重述，表达为该属性的一项范围约束，不额外制造“改变属性”的动作集合和A/B重复边界。若原文另有限制实际读写、删除、外发等操作权限，则保留独立动作禁令；不能借属性投影删除它。

事件时序按已有表达接口构造，不计算完成时间：串行无间隔以相邻阶段end/start共享身份表示，整体start/end可直接引用首尾阶段端点。共同起点并行以共享start及各自end表示；若原文明示所有分支结束时整体即结束，可用整体end为key的REQUIRED义务、guard=各分支end的all、timing=ON_TRIGGER表达。这不是要求LLM求max。连续执行可作为同一执行对象的定性属性值保留；不要因没有暂停细节而误报连续或精确终点不受接口支持。仅前置而未明确即时完成不能升级为ON_TRIGGER。

完整数量组成已支持quantity.components:["子数量key",...]：仅当原文明示由这些项完整组成时使用；它表达闭合成员表，combination表达原有SINGLE/ADDITIVE/SERIAL/PARALLEL等关系，不填写合计结果。SINGLE只可有一个成员，多层组成分别声明每层；程序沿图逐层计算。每个成员保留相同key的quantity（尚未给值时用LIMIT、lower:null、upper:null及已知单位，不虚构数值），PART_OF由完整成员表确定。原文只有部分组成时只用PART_OF，不宣称完整。独立费用表示不同instance；choice_model=INDEPENDENT仅用于明确允许独立选择的区间，不由不同费用推断选择自由。不要再将闭合组成说成接口不支持。

区分总量的运算口径与明细是否齐全：原文明示按总额/累计约束的可加资源，combination=ADDITIVE表示不同资源实例的累计，不要求父原文先列全所有费用项目。同一实例转述仍由instance去重后计一次；未列明细不能把已明确总量口径写成UNKNOWN。费用总额、独立调用次数等可加量与平均值、比率、温度等非可加量不同；整体经过时间仍需串并行起止依据，不能因有“总”字就相加。退款与收入按原文口径分别表达，不擅自抵扣。只交付原文运算关系，不计算合计。

属性投影以受约束的语义对象为准：任务可选的运行上下文/环境是输入范围I，其允许域收紧和实际选用仍是同一I属性；若原文约束的是对环境执行访问、登录、读写等操作权限，则该操作许可属于A，独立禁止操作保留B。不要看到环境一词便一律归A或一律归I，也不要将一个上下文取值范围重复制造为操作禁令。审核及局部解析沿用同一语义区分。

前置依赖的属性投影：某步骤必须先于另一动作、批准后才能执行、必要前置被取消或反转，都是A动作关系。即使表达使用start/end事件端点，只有额外的时长、时间点或截止窗口数值约束才是R；不能因为出现先后或事件端点就把前置许可图归R。图关系使用order的edges/removed表达；同一节点分多条款描述的关系仍属于同一key的完整图，保持来源，不重复为每条边另造独立属性域。

闭合前置图：原文明示本图只包含列举的前置关系且不另设其他路径时，order可加closed:true，edges列全明示关系、removed保留明确取消的边。closed表示该图的关系清单完整，不是某条边存在；不能把未列出的继承边偷偷补回闭合图。未说完整时不要加closed。多条款描述同一图时同key；闭合图的可达性、替代路径和反向路径由计算器求，不输出路径计算结果，也不因缺少单独“禁止间接路径”语法而把已完整列举的闭合图标UNSUPPORTED。闭合图中的未知节点、未知关系仍须保留真实缺口。

图的否定关系可用order.forbidden_paths:[{from:"已有节点",to:"已有节点"}]表示该两节点间不得存在任何前置可达路径；它不同于removed仅取消一条明确边，也不需要声明整个图closed。原文取消一条父关系且无等价替代时，保留removed，并以forbidden_paths表达无替代路径，不能丢弃已明确的取消或捏造全图闭合。图内所有身份同样需要对齐：普通父节点也可用events映射普通子节点；新节点确与所有父候选不同可逐项给DISTINCT依据，未对齐不视为无关联。程序负责可达性与正反约束计算。

建议、偏好与非强制说明不是硬边界。仅建议某动作或某先后关系时，保留原文条款并用kind/coverage CONTEXT说明不产生强制义务、必要前置或禁令；不能因为没有软建议算子就报UNSUPPORTED。没有要求某关系，不等于禁止该关系，不得翻译成forbidden_paths。只有原文明示不得存在某路径才用forbidden_paths。局部解析只修有缺口的建议条款，不能把现有必要关系降为建议。
